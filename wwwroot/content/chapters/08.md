## 8.1 泛型，一次写好，适应所有类型

[第 4 章](/chapter/04)用过的 `List<T>` 就是泛型。`T` 是类型参数，使用时由具体的类型来替换它。泛型让同一份代码既安全又能复用。

### 没有泛型会怎样

假设要做一个栈。没有泛型的时候，只能存 `object`。

```csharp
public sealed class UntypedStack
{
    private readonly List<object> _items = new();

    public void Push(object item) => _items.Add(item);

    public object Pop()
    {
        var last = _items[^1];
        _items.RemoveAt(_items.Count - 1);
        return last;
    }
}
```

```csharp
var untyped = new UntypedStack();
untyped.Push(1);
untyped.Push("两行");
try
{
    int first = (int)untyped.Pop();
    Console.WriteLine(first);
}
catch (InvalidCastException ex)
{
    Console.WriteLine($"运行时才发现：{ex.Message}");
}
```

输出如下。

```text
运行时才发现：Unable to cast object of type 'System.String' to type 'System.Int32'.
```

编译器对这段代码没有任何意见。错误藏在运行时，只有执行到那一行才会爆出来。如果这个栈在一个很长的程序里被很多地方使用，找出哪次 `Push` 放进了错误的类型，会很花时间。

### 泛型栈

把 `object` 换成类型参数 `T`，编译器就能在编译时检查每一次调用。

```csharp
public sealed class TypedStack<T>
{
    private readonly List<T> _items = new();

    public int Count => _items.Count;

    public void Push(T item) => _items.Add(item);

    public T Pop()
    {
        if (_items.Count == 0)
        {
            throw new InvalidOperationException("栈是空的");
        }

        var last = _items[^1];
        _items.RemoveAt(_items.Count - 1);
        return last;
    }

    public bool TryPop(out T? item)
    {
        if (_items.Count == 0)
        {
            item = default;
            return false;
        }

        item = _items[^1];
        _items.RemoveAt(_items.Count - 1);
        return true;
    }
}
```

```csharp
var typed = new TypedStack<int>();
typed.Push(1);
typed.Push(2);
Console.WriteLine($"Pop = {typed.Pop()}");
string? empty = default;
Console.WriteLine($"default(int) = {default(int)}，default(string) 是 null 吗？{empty is null}");
if (!new TypedStack<string>().TryPop(out var missing))
{
    Console.WriteLine($"空栈 TryPop 返回 false，missing = {missing ?? "null"}");
}
```

输出如下。

```text
Pop = 2
default(int) = 0，default(string) 是 null 吗？True
空栈 TryPop 返回 false，missing = null
```

`typed.Push("两行")` 这样的写法现在会在编译时报错，不会等到运行时。`default(T)` 给出类型的默认值，对于数值是 0，对于引用类型是 `null`。`TryPop` 用 `out T? item` 返回结果，调用方通过返回值判断有没有取到数据，比抛异常更适合"空"是正常情况的场合。

`List<object>` 装 `int` 时，每次放进去都要装箱，取出来又要拆箱。`List<int>` 则没有这些开销。这也是 .NET 的集合大多是泛型的原因之一。

### 类型参数的约束，限定 T 能做什么

没有约束时，方法体里的 `T` 只能当作 `object` 来用。`a.CompareTo(b)` 这样的调用写不出来，因为编译器不知道 `T` 有没有这个方法。约束就是告诉编译器，`T` 至少具备哪些能力。

下面几个泛型方法分别演示了常用的约束。

```csharp
using System.Runtime.CompilerServices;

static T ParseEnum<T>(string text) where T : struct, Enum =>
    Enum.Parse<T>(text, ignoreCase: true);

static string Describe<T>(T item) where T : notnull =>
    $"{item.GetType().Name}: {item}";

static T NewOne<T>() where T : new() => new T();

static T Max<T>(T a, T b) where T : IComparable<T> =>
    a.CompareTo(b) >= 0 ? a : b;

static int Size<T>() where T : unmanaged => Unsafe.SizeOf<T>();

static double TotalArea<T>(IEnumerable<T> items) where T : Shape =>
    items.Sum(s => s.Area);
```

`ParseEnum` 要求 `T` 是枚举。`struct, Enum` 两个约束写在一起，前一个说明它是值类型，后一个说明它是 `Enum`。`Describe` 要求 `T` 不能为 `null`，这样就能放心地调用 `item.GetType()`。`NewOne` 要求 `T` 有无参构造函数，所以能写 `new T()`。`Max` 要求 `T` 实现 `IComparable<T>`，所以能调用 `CompareTo`。`Size` 要求 `T` 是非托管类型，也就是值类型，而且内部不包含引用。`TotalArea` 要求 `T` 继承自 `Shape`，所以能访问 `Area`。

这些方法需要一组辅助类型，下面一并列出。

```csharp
public enum Severity
{
    Info,
    Warn,
    Error,
}

public abstract class Shape
{
    public abstract double Area { get; }
}

public sealed class Circle : Shape
{
    public Circle(double radius) => Radius = radius;

    public double Radius { get; }

    public override double Area => Math.PI * Radius * Radius;
}

public sealed class SquareShape : Shape
{
    public SquareShape(double side) => Side = side;

    public double Side { get; }

    public override double Area => Side * Side;
}
```

```csharp
Console.WriteLine(ParseEnum<Severity>("warn"));
Console.WriteLine(Describe(42));
Console.WriteLine(NewOne<List<string>>().Count);
Console.WriteLine(Max("apple", "banana"));
Console.WriteLine($"int {Size<int>()} 字节，double {Size<double>()} 字节");
var shapes = new List<Shape> { new Circle(1), new SquareShape(2) };
Console.WriteLine($"总面积 {TotalArea(shapes):0.00}");
```

输出如下。

```text
Warn
Int32: 42
0
banana
int 4 字节，double 8 字节
总面积 7.14
```

下表列出常用的约束。

| 约束 | 含义 | 典型用途 |
| --- | --- | --- |
| `where T : class` | 必须是引用类型 | 只接受对象，不接受 `int` 这类值 |
| `where T : struct` | 必须是值类型，不能是 `null` | 数值计算 |
| `where T : notnull` | 不能是 `null` | 字典的键 |
| `where T : unmanaged` | 非托管值类型 | 直接按内存布局处理 |
| `where T : new()` | 必须有公开的无参构造函数 | 工厂方法里创建对象 |
| `where T : Enum` | 必须是枚举，通常和 `struct` 一起写 | 按名字解析枚举 |
| `where T : 接口` | 必须实现某个接口 | 比较、遍历、格式化 |
| `where T : 基类` | 必须是某个类或它的子类 | 访问基类的成员 |

把 `class` 约束和某个基类约束写在一起，编译器会报 `CS0450`。约束也不能随便写，比如 `where T : int` 会得到 `CS0701`，提示 int 不是有效的约束，约束只能是接口、非 `sealed` 的类或另一个类型参数。

### 协变与逆变

到这里，泛型的基本用法已经够用了。协变和逆变属于进阶内容，它们解决的是泛型接口和委托之间的赋值问题。

先看一个会让人困惑的现象。`string` 是 `object` 的子类，那 `List<string>` 能赋给 `List<object>` 吗？

```csharp
List<string> strings = new();
List<object> objects = strings;    // CS0029：无法隐式转换
```

不能。`List<T>` 是**不变**的，`List<string>` 和 `List<object>` 是两个互不兼容的类型。原因很直接。如果允许赋值，程序就能通过 `List<object>` 往里放一个 `int`，而原来的 `List<string>` 里却出现了 `int`。

可是对于只读的场景，这种赋值其实是安全的。协变就是为这种场景准备的。泛型接口的类型参数前加 `out`，表示 `T` 只出现在输出的位置，也就是只能被读取、不能被写入。

```csharp
public interface IReader<out T>
{
    T Read();
}

public interface IWriter<in T>
{
    void Write(T item);
}

public sealed class LineReader : IReader<string>
{
    private readonly Queue<string> _queue;

    public LineReader(IEnumerable<string> lines) => _queue = new Queue<string>(lines);

    public string Read() => _queue.Dequeue();
}

public sealed class ConsoleWriter : IWriter<object>
{
    public void Write(object item) => Console.WriteLine($"写出：{item}");
}
```

```csharp
IEnumerable<string> lines = new List<string> { "a", "b" };
IEnumerable<object> objects = lines;
Console.WriteLine($"协变后的数量：{objects.Count()}");

IReader<string> reader = new LineReader(new[] { "x", "y" });
IReader<object> objectReader = reader;
Console.WriteLine($"协变读取：{objectReader.Read()}");
```

输出如下。

```text
协变后的数量：2
协变读取：x
```

`IEnumerable<T>` 本来就是 `out T` 的接口，它只提供读取。所以 `IEnumerable<string>` 可以当作 `IEnumerable<object>` 来用。`IReader<out T>` 也是同样的道理，`Read` 只把值交出来。

逆变则是反方向。`in` 表示 `T` 只出现在输入的位置，只能被写入。`Action<T>` 就是逆变的，因为它只接收参数，不返回值。

```csharp
Action<object> printObject = o => Console.WriteLine($"收到：{o}");
Action<string> printString = printObject;
printString("hello");

IWriter<object> writer = new ConsoleWriter();
IWriter<string> stringWriter = writer;
stringWriter.Write("逆变写入");
```

输出如下。

```text
收到：hello
写出：逆变写入
```

`Action<object>` 能接受任何 `object`，当然也能接受 `string`。所以它可以赋给 `Action<string>`。`IWriter<in T>` 也是如此，一个能写出任何对象的写出器，自然能写出字符串。

记住一个简单的判断方法。协变的 `out` 对应"产出"，逆变的 `in` 对应"接收"。协变与逆变只适用于接口和委托，类不能声明协变或逆变。`List<T>` 之所以不变，是因为它既能读也能写。

## 8.2 类型推断与泛型方法

前一节的泛型类型，使用时必须写明类型参数，比如 `TypedStack<int>`。泛型方法则多数时候不需要你写。编译器会从实参推出类型参数，这叫**类型推断**。

下面是一个统计任意序列中每个键出现次数的泛型方法。它的完整代码在 `code/ch08-generics/Program.cs` 中。

```csharp
static Dictionary<string, int> CountBy<T>(IEnumerable<T> items, Func<T, string> keySelector)
{
    var counts = new Dictionary<string, int>();

    foreach (var item in items)
    {
        var key = keySelector(item);
        counts[key] = counts.GetValueOrDefault(key) + 1;
    }

    return counts;
}
```

调用它的时候，可以省略类型参数。

```csharp
var sample = new[]
{
    "INFO api 启动完成",
    "WARN db 查询较慢",
    "ERROR order 处理失败",
    "INFO api 请求完成",
};

// 编译器从 sample 推出 T 是 string，lambda 的参数 line 也随之确定
var byModule = CountBy(sample, line => line.Split(' ')[1]);
// 显式写出类型参数，效果相同
var byLevel = CountBy<string>(sample, line => line.Split(' ')[0]);
Console.WriteLine("按模块：" + string.Join(" · ", byModule.Select(pair => $"{pair.Key} {pair.Value}")));
Console.WriteLine("按级别：" + string.Join(" · ", byLevel.Select(pair => $"{pair.Key} {pair.Value}")));
```

输出如下。

```text
按模块：api 2 · db 1 · order 1
按级别：INFO 2 · WARN 1 · ERROR 1
```

`CountBy(sample, ...)` 能成立，是因为 `sample` 是 `string[]`，它能对应 `IEnumerable<T>` 中的 `T`，于是 `T` 被推断为 `string`。随后 lambda 的参数 `line` 的类型也就确定为 `string`，`line.Split` 才能写。

推断依赖于参数里能提供类型的信息。如果什么都推不出来，编译器就会停下。下面这行在探针中会报 `CS8917`，提示委托类型无法推断。

```csharp
var f = x => x;   // CS8917：无法推断委托类型
```

此时要么给 lambda 的参数写上类型，要么像 `CountBy<string>` 那样显式写出类型参数。

## 8.3 参数类型怎么选

写一个接收集合的方法时，参数类型有三种常见写法，分别是 `IEnumerable<T>`、`IReadOnlyList<T>` 和 `List<T>`。它们对调用方的限制不同。

```csharp
static int SumEnumerable(IEnumerable<int> numbers)
{
    var total = 0;
    foreach (var n in numbers)
    {
        total += n;
    }

    return total;
}

static int SumReadOnly(IReadOnlyList<int> numbers)
{
    var total = 0;
    for (var i = 0; i < numbers.Count; i++)
    {
        total += numbers[i];
    }

    return total;
}
```

```csharp
int[] array = { 1, 2, 3 };
var list = new List<int> { 4, 5 };
Console.WriteLine($"IEnumerable 接受数组：{SumEnumerable(array)}");
Console.WriteLine($"IEnumerable 接受 List：{SumEnumerable(list)}");
Console.WriteLine($"IReadOnlyList 接受数组：{SumReadOnly(array)}");
Console.WriteLine($"IReadOnlyList 接受 List：{SumReadOnly(list)}");
```

输出如下。

```text
IEnumerable 接受数组：6
IEnumerable 接受 List：9
IReadOnlyList 接受数组：6
IReadOnlyList 接受 List：9
```

选择的原则是，只需要遍历时用 `IEnumerable<T>`，它能接受数组、列表以及后面要讲的查询结果；需要按下标访问、又不修改时用 `IReadOnlyList<T>`；只有方法内部真的要增删元素时，才要求调用方传入 `List<T>`。参数越宽，调用方越自由，方法本身也越不会误改别人的数据。

如果把 `SumList(List<int> numbers)` 这样的方法传入数组，编译器会报 `CS1503`，提示参数 1 无法从 `int[]` 转换为 `List<int>`。这是类型不匹配，不是泛型的问题，但它说明了参数类型选得太窄会带来什么。

## 8.4 常见错误

下表中的错误码与报错文字都是编译器在检查点探针中实际报告的内容。

| 报错或现象 | 原因 | 怎么改 |
| --- | --- | --- |
| `CS0029` 无法隐式转换 `List<string>` 到 `List<object>` | `List<T>` 是不变的，两者是互不兼容的类型 | 只读场景改用 `IEnumerable<object>` 这类协变接口；需要转换时逐个转换元素 |
| `CS0450` 不能同时指定基类约束和 `class` 约束 | 把 `class` 与一个类的约束写在一起，如 `where T : class, Shape` | 只保留 `where T : Shape`，它已经限定了引用类型 |
| `CS0701` 不是有效的约束 | 把 `int` 当作约束，如 `where T : int` | 约束只能是接口、非 `sealed` 的类或另一个类型参数；值类型的限制用 `struct` 或 `unmanaged` |
| `CS1503` 参数无法转换 | 把 `int[]` 传给了形参为 `List<int>` 的方法 | 形参改用 `IEnumerable<int>` 或 `IReadOnlyList<int>` |
| `CS8917` 无法推断委托类型 | `var f = x => x;`，没有任何信息能确定 `x` 的类型 | 给 lambda 的参数写上类型，或给泛型方法显式指定类型参数 |
| `InvalidCastException`（运行时） | 没有泛型的 `object` 栈，取出时强制转换成了错误的类型 | 改用 `TypedStack<T>`，让错误在编译时暴露 |

`CS0450` 的说法需要说明清楚。探针中只报了 `CS0450`，没有出现 `CS0449`。因此如果你看到的是 `CS0450`，就按上表处理。

## 8.5 小练习

**练习 1（泛型约束）**，写一个泛型方法 `static T? FindFirst<T>(IEnumerable<T> items, Func<T, bool> predicate) where T : class`，返回第一个满足条件的元素，没有则返回 `null`。用它在 `sample` 中找出第一条以 `ERROR` 开头的行。

<details>
<summary>参考答案</summary>

```csharp
static T? FindFirst<T>(IEnumerable<T> items, Func<T, bool> predicate) where T : class
    => items.FirstOrDefault(predicate);

var found = FindFirst(sample, line => line.StartsWith("ERROR", StringComparison.Ordinal));
Console.WriteLine($"第一条 ERROR：{found ?? "没有"}");
var fatal = FindFirst(sample, line => line.Contains("FATAL"));
Console.WriteLine($"FATAL：{fatal ?? "没有"}");
```

输出如下。

```text
第一条 ERROR：ERROR order 处理失败
FATAL：没有
```

`FirstOrDefault` 本身也是一个泛型方法，它的参数是 `Func<T, bool>`。[第 10 章](/chapter/10)会详细讲它。这里只需要知道，它找不到时返回 `default`，对于引用类型就是 `null`。

</details>

**练习 2（思考）**，为什么 `IReader<out T>` 可以把 `IReader<string>` 当作 `IReader<object>` 使用，而 `List<T>` 不行？请用"只读"与"能写入"两个角度解释。

<details>
<summary>参考答案</summary>

`IReader<out T>` 只有 `T Read()`，`T` 只出现在输出的位置，调用方拿到的只是 `object` 的父类型，不会向里面写入一个错误类型的值。`List<T>` 既能读也能写，如果允许把 `List<string>` 当作 `List<object>`，外面就能往原来的 `List<string>` 里放一个 `int`。协变只适用于只读的接口。

</details>
