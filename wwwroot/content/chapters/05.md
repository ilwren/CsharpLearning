## 5.1 为什么需要方法

[第 4 章](/chapter/04)的统计代码能跑，但有两个毛病。

第一个毛病是重复。下面两段代码的结构一样，都是先数一数，再打印，只是字段和条件不同。

```csharp
// 毛病 1：重复
Console.WriteLine("级别分布");
foreach (var level in new[] { "info", "warn", "error" })
{
    var count = 0;
    foreach (var log in logs)
    {
        if (log.Level == level) { count++; }
    }
    Console.WriteLine($"  {level,-6}{count} 条");
}

Console.WriteLine("各模块问题数");
foreach (var module in new[] { "api", "order" })
{
    var count = 0;
    foreach (var log in logs)
    {
        if (log.Module == module && (log.Level == "warn" || log.Level == "error")) { count++; }
    }
    Console.WriteLine($"  {module,-6}{count} 个");
}
```

重复的代码有一个麻烦。想改输出格式，就得改两处，改漏一处，两段输出就会不一致。

第二个毛病是主流程读不懂。统计代码全部平铺在顶层语句里，写到几十行以后，你很难一眼看出这个程序分几步做事。

方法的作用就是给一段代码起一个名字。起了名字之后，好处主要有三点。


- 重复的地方可以直接调用名字，不用再复制粘贴；
- 主流程变成一串名字，读起来像一份说明；
- 出了问题，可以先看是哪个方法出错，再进去找具体的行。

## 5.2 定义与调用

先看一个最小的方法。

```csharp
// 定义（写在文件里）
static void SayHello()
{
    Console.WriteLine("你好！");
}

// 调用（在使用的地方）
SayHello();
SayHello();          // 调用几次，就执行几次
```

拆开来看，一个方法由几部分组成。

| 部分 | 名称 | 含义 |
| --- | --- | --- |
| `static` | 修饰符 | 顶层语句里的方法先照着写，[第 6 章](/chapter/06) 6.5 节再解释它的含义 |
| `void` | 返回类型 | 表示"不返回任何值" |
| `SayHello` | 方法名 | 用大驼峰（PascalCase）命名 |
| `()` | 参数列表 | 空括号表示调用时不需要传入东西 |
| `{ }` | 方法体 | 调用时真正执行的代码 |

方法可以写在顶层语句的末尾。编译器不关心定义和调用的先后顺序，所以 `SayHello()` 放在定义之前调用也没有问题。

## 5.3 参数与返回值

### 参数，把数据送进去

```csharp
static void PrintLevel(string level, int count)
{
    Console.WriteLine($"{level,-6}{count} 条");
}

PrintLevel("info", 4);       // info  4 条
```

参数相当于方法内部的局部变量。调用的时候，传进来的值会被复制一份，赋给这些参数。

### 返回值，把结果交回去

```csharp
static int Double(int value)
{
    return value * 2;         // 交出结果，同时立刻结束方法
}

var result = Double(21);      // 42
```

`return` 有两个作用，交出结果，并且立刻结束方法。

```csharp
static string Describe(int ms)
{
    if (ms > 1000)
    {
        return "慢请求";      // 执行到这里就结束了，下面的代码不会再执行
    }

    return "正常";
}
```

### void 与有返回值的区别

| 返回类型 | 含义 | 例子 |
| --- | --- | --- |
| `void` | 只做事，不返回结果 | `PrintLevel(...)`、`Console.WriteLine(...)` |
| 具体类型 | 算出一个值交给调用方 | `int.TryParse(...)`、`logs.Count()` |

判断的办法很简单。调用的地方需不需要用到这个方法算出来的结果？需要，就返回值；只是顺便做点事，就用 `void`。

### 表达式体方法，一行写清

方法体只有一个 `return` 语句时，可以写成表达式体。

```csharp
static int Double(int value) => value * 2;

static string Describe(int ms) => ms > 1000 ? "慢请求" : "正常";
```

`=>` 右边的表达式就是返回值。这种写法在短方法里很常见。逻辑稍微长一点，就老老实实用花括号，不要为了省行数硬塞进一行。

## 5.4 默认参数与命名参数

### 默认参数，给了默认值，调用时就能省略

```csharp
static void PrintTable(List<string> rows, int limit = 10, bool numbered = false)
{
    var index = 1;
    for (var i = 0; i < rows.Count && i < limit; i++)
    {
        Console.WriteLine(numbered ? $"{index++,3}. {rows[i]}" : rows[i]);
    }
}

var rows = new List<string> { "a", "b", "c", "d" };

PrintTable(rows);                  // 用默认值：limit=10，numbered=false
PrintTable(rows, 3);               // limit=3
PrintTable(rows, 3, true);         // limit=3，numbered=true
```

规则只有一条，**有默认值的参数必须放在最后**。

### 命名参数，调用时写清楚每个值是什么

```csharp
PrintTable(rows, numbered: true);            // 跳过 limit，只指定 numbered
PrintTable(rows, limit: 5, numbered: true);  // 每个值都标明了名字
```

参数一多，只写值会看不出含义。`PrintTable(rows, 3, true)` 里的 `true` 是什么意思，要回头看定义才知道。命名参数可以让调用的地方自己说明白。

项目里也是这样写的。下面这段节选自 `src/LogLens.Cli/AppSettings.cs`，其中的 `cancellationToken:` 就是一个命名参数。

```csharp
var loaded = await JsonDefaults.ReadFromFileAsync<AppSettings>(environment.SettingsFile, cancellationToken: cancellationToken)
```

## 5.5 `out` 参数，一次返回两样东西

回想[第 2 章](/chapter/02)的 `int.TryParse`。

```csharp
if (int.TryParse(text, out var ms))
{
    Console.WriteLine(ms);       // 只有解析成功，ms 才有有效的值
}
```

为什么不用普通的返回值？因为这类方法需要同时返回两样东西，即成功还是失败（`bool`），以及解析出来的结果（`int`）。`out` 就是"额外多开一个输出口"的参数。

下面写一个类似的方法，把级别文字规范化。

```csharp
static bool TryParseLevel(string text, out string normalized)
{
    normalized = text.Trim().ToLowerInvariant();

    if (normalized is "info" or "warn" or "error" or "debug")
    {
        return true;
    }

    normalized = "unknown";
    return false;
}

// 用法
if (TryParseLevel("WARN", out var level))
{
    Console.WriteLine($"识别为 {level}");      // 识别为 warn
}
else
{
    Console.WriteLine("不认识的级别");
}
```

使用 `out` 参数时，有两条规则需要记住。

1. `out` 参数必须在方法返回之前被赋值，编译器会检查这一点。
2. 调用的时候，`out var x` 会自动声明变量 `x`，不用提前写一行 `var x;`。

现代 C# 里，需要返回多个值时，更常见的做法是返回元组或者类（[第 4 章](/chapter/04) 4.6 节、[第 6 章](/chapter/06)）。但 `out` 在 .NET 的基础 API 里随处可见，比如 `TryParse` 和 `TryGetValue`，所以需要看得懂。

项目里的解析代码也用到了它。`src/LogLens.Core/Infrastructure/TimeSpanParser.cs` 中有这样一行。

```csharp
if (!double.TryParse(span[numberStart..index], out var amount))
```

### `ref`，直接改调用方的变量

`out` 只负责输出，`ref` 则是把变量本身传进去，方法里的修改会直接反映到调用方。

```csharp
static void Reset(ref int value)
{
    value = 0;                 // 直接改掉调用方的那个变量
}

var x = 42;
Reset(ref x);                  // 调用时也要写 ref
Console.WriteLine(x);          // 0
```

`ref` 用得不多，知道它是什么意思就够了。在真实项目里滥用 `ref`，代码很难读懂。

## 5.6 重载，同名不同参

同名的方法，只要参数个数或参数类型不同，就叫**重载**（overload）。调用的时候，编译器会根据你传入的参数，选中对应的那一个版本。

```csharp
static string Format(int ms) => $"{ms} ms";

static string Format(int ms, string unit) => $"{ms} {unit}";
```

但如果把这两个方法直接写在顶层语句的文件末尾，编译会失败，编译器会报 `CS0128`，提示同一个作用域里已经有名为 `Format` 的函数。

原因在于，顶层语句里的方法会被编译器当作局部函数处理（5.7 节会讲），而**局部函数不能重载**。重载是类的成员才有的能力，所以要把它们放进一个类里。

```csharp
static class LogFormat
{
    public static string Format(int ms) => $"{ms} ms";

    public static string Format(int ms, string unit) => $"{ms / 1000.0:F2} {unit}";
}

Console.WriteLine(LogFormat.Format(1520));        // 1520 ms
Console.WriteLine(LogFormat.Format(1520, "s"));   // 1.52 s
```

这里的 `LogFormat` 只是用来放方法的类。类的完整写法在[第 6 章](/chapter/06)讲，现在先照着用。

还有一条规则，**只靠返回类型不同，不能重载**。如果 `int Foo()` 和 `string Foo()` 写在同一个类里，编译器会报 `CS0111`。原因是 `Foo();` 这样的调用，编译器无法判断该选哪一个，而调用的人也可能根本不在意返回值。

> 真实项目的方法几乎都写在类里。顶层语句适合十几行的练习程序，代码一旦变多，就该进入类的世界，[第 6 章](/chapter/06)会讲这部分。

## 5.7 局部函数，只在一个方法里用的小工具

如果某个辅助逻辑只属于某一个方法，可以把它写在那个方法的内部，这种函数叫**局部函数**。

```csharp
static void PrintReport(List<(string Level, int Ms)> logs)
{
    Console.WriteLine($"共 {logs.Count} 条");

    var problemCount = CountProblems();
    Console.WriteLine($"问题 {problemCount} 条");

    // 局部函数：只在 PrintReport 里能看见
    int CountProblems()
    {
        var count = 0;
        foreach (var log in logs)
        {
            if (log.Level is "warn" or "error")
            {
                count++;
            }
        }
        return count;
    }
}
```

局部函数的好处有两个。一是作用域最小，别的地方不会误用它。二是它可以直接读取外层方法的变量，比如这里的 `logs`，不必再当成参数传进去。

局部函数读取外层变量的做法，有一个专门的名字，叫**闭包**（closure）。项目里的 `src/LogLens.Core/Parsing/LogParserFactory.cs` 就用了这种写法，下面是其中一段节选。

```csharp
// 局部函数 + 闭包：把"评分规则"写在使用它的地方，读起来最顺
int Score(ILogParser parser)
{
    var success = 0;
    long lineNumber = 1;

    foreach (var line in sampleLines)
    {
        // ……（省略）
    }
    // ……
}
```

`sampleLines` 是外层方法的变量，`Score` 直接使用它。这个写法在[第 10 章](/chapter/10)讲 lambda 时还会再见到。

如果不希望局部函数捕获外层变量，可以加上 `static`。加了 `static` 之后，编译器会检查它是否用到了外层变量，用到了就报错。

```csharp
static int Double(int x) => x * 2;      // 局部函数也可以是 static，只使用自己的参数
```

## 5.8 匿名方法与 lambda 表达式

前面的方法都有名字，调用时写名字就行。但很多时候，一段逻辑只用一次，专门给它起个名字反而啰嗦。C# 允许把一段逻辑直接写在用的地方，当成一个值传来传去。这就是匿名方法和 lambda 表达式。

方法也可以存进变量里。这种能被当成值保存、传递的方法类型，叫**委托**（delegate）。.NET 提供了两个最常用的委托类型，`Func` 和 `Action`。

```csharp
Func<int, int> twice = x => x * 2;
Console.WriteLine(twice(21));    // 42
```

`Func<int, int>` 的意思是"接收一个 `int`，返回一个 `int` 的方法"。`Func` 的最后一个类型参数永远是返回值。`Action` 没有返回值。下表列出常见的几种。

| 类型 | 参数 | 返回值 | 例子 |
| --- | --- | --- | --- |
| `Func<TResult>` | 无 | 有 | `Func<int>`，不接收参数，返回 `int` |
| `Func<T, TResult>` | 一个 | 有 | `Func<int, int>`，接收 `int`，返回 `int` |
| `Func<T1, T2, TResult>` | 两个 | 有 | `Func<int, int, int>` |
| `Action` | 无 | 无 | `Action`，什么都不接收，也不返回 |
| `Action<T>` | 一个 | 无 | `Action<string>`，接收一个字符串 |

把一段逻辑交给变量，有三种写法。

| 写法 | 例子 | 说明 |
| --- | --- | --- |
| 具名方法 | `static int Twice(int x) => x * 2;`，再写 `Func<int, int> f = Twice;` | 先起名字，再把名字交给变量 |
| 匿名方法 | `delegate (string s) { return s.Length; }` | C# 2.0 的写法，必须写参数类型和 `return` |
| lambda 表达式 | `s => s.Length` | C# 3.0 起的写法，现在最常用 |

lambda 表达式的语法如下。

```csharp
Func<int, int> twice = x => x * 2;                     // 一个参数，右边是表达式
Func<int, int, int> add = (x, y) => x + y;             // 两个参数，括号必须写
Func<int> answer = () => 42;                           // 没有参数，括号也必须写
Action<string> say = msg => Console.WriteLine(msg);    // 没有返回值

Action<int> printBlock = n =>                          // 多行语句，用花括号
{
    var doubled = n * 2;
    Console.WriteLine(doubled);
};
```

读 lambda 时，`=>` 可以读作"变成"。左边是参数，右边是要做的事。

- 参数的类型通常由编译器根据前面的声明推断出来，所以不用写 `int`。
- 只有一个参数时，括号可以省略。没有参数或者有多个参数时，括号必须写。
- 右边是一个表达式时，表达式的值就是返回值。要写多行语句时，用花括号，并且自己写 `return`。

匿名方法的写法和 lambda 作用相同，但要写全参数类型和 `return`。

```csharp
Func<string, int> length = delegate (string s) { return s.Length; };
Console.WriteLine(length("abc"));    // 3
```

看到老代码里的 `delegate`，不用慌。现在多数情况下写 lambda 就够了。

### 方法可以接收一段逻辑

方法的参数可以是一个委托，调用的人决定传进去的是什么逻辑。

```csharp
static int Apply(int value, Func<int, int> op) => op(value);

Console.WriteLine(Apply(5, x => x * x));    // 25
Console.WriteLine(Apply(5, twice));         // 10，传进去的是 twice 这个变量
```

这种能力在项目里很常见。`src/LogLens.Studio/Services/WorkspaceService.cs` 第 73 行这样写。

```csharp
var report = await Task.Run(() => _analyzer.Analyze(ingestion), cancellationToken).ConfigureAwait(false);
```

`Task.Run` 接收的是一段要放到后台执行的逻辑，这里用 lambda 直接写在了调用的地方。[第 10 章](/chapter/10)的 LINQ 整个建立在这种能力之上，到时还会再见到。

### lambda 会记住外面的变量

lambda 可以使用定义它的方法里的变量，这叫**捕获**（capture）。

```csharp
int factor = 3;
Func<int, int> times = x => x * factor;
Console.WriteLine(times(2));    // 6

factor = 10;
Console.WriteLine(times(2));    // 20，lambda 读到的是 factor 现在的值
```

lambda 直接读的是 `factor` 这个变量，它没有保存一份 `factor` 的值。编译器为此通常会把 `factor` 放进一个自己生成的对象里，lambda 通过这个对象访问它。这和引用类型的道理相通，5.10 节会讲内存里的样子。[第 10 章](/chapter/10)讲延迟执行时，还会用到这一点。

## 5.9 值类型与引用类型

C# 的类型分成两大类，区分的依据是**变量里装的是什么**。

- **值类型**，变量直接装着数据本身。
- **引用类型**，变量里装的是一个地址（也叫引用），数据放在别的地方。

常见的类型可以这样分。

| 值类型 | 引用类型 |
| --- | --- |
| `int`、`double`、`bool`、`char` | `string` |
| 枚举，例如 `LogLevel` | 数组，例如 `int[]` |
| 元组，例如 `(string, int)` | `List<T>`、`Dictionary<TKey, TValue>` |
| `struct`，例如 `TimeRange`、`ByteSize`（[第 6 章](/chapter/06) 6.9 节） | `class`，例如 `LogEvent` |
| `record struct` | `record`（默认是引用类型）、委托（`Func`、`Action`） |

看声明方式就能分辨。用 `struct`、`enum`、元组和 `record struct` 声明的是值类型；用 `class`、`record`、`string` 和数组表示的是引用类型。`typeof(...).IsValueType` 可以在运行时查询一个类型是不是值类型。

```csharp
Console.WriteLine(typeof(int).IsValueType);         // True
Console.WriteLine(typeof(string).IsValueType);      // False
Console.WriteLine(typeof(LogEvent).IsValueType);    // False
```

有两点需要特别注意。

- **`string` 是引用类型，但它不能被修改。** 字符串一旦创建，内容就固定了。所以它用起来很像值类型，5.11 节会专门讲这一点。
- **值类型不能是 `null`，引用类型可以。** `int n = null;` 会报 `CS0037`。要表示"可能没有数字"，要写成 `int?`，[第 2 章](/chapter/02)讲过。

## 5.10 内存里的样子，栈与堆

[第 0 章](/chapter/00)的 0.5 节讲过，程序运行时内存大致分成栈和堆两块。这一节把它和值类型、引用类型对应起来。

- **栈**，每次调用方法，就在栈上分配一块区域，叫栈帧。它放这个方法的参数和局部变量。方法返回时，整块区域一起弹出。
- **堆**，`new` 出来的对象放在堆上。堆上的对象不会随着方法结束而消失，由垃圾回收器（GC）决定什么时候回收。

<img class="lt-img-light" src="/content/images/ch05-fig02-stack-heap.svg" alt="栈与堆中的变量和对象" />
<img class="lt-img-dark" src="/content/images/ch05-fig02-stack-heap-dark.svg" alt="栈与堆中的变量和对象" />

图中的 `count` 是值类型，栈帧里直接装着 `4`。`logs` 是引用类型，栈帧里装的是地址，列表本身放在堆上。写成代码就是这样。

```csharp
var count = 4;                        // 值类型：变量里直接就是 4
var logs = new List<LogEvent>();      // 引用类型：变量里是地址，列表在堆上
```

还有两点要说明。

1. **值类型不一定都在栈上。** 值类型如果是某个类的字段，它就和所在的对象住在一起，也就是在堆上。图中 `LogEvent` 对象的 `Ms` 和 `Level` 字段就是这样。把值类型装进 `object` 变量时（装箱），也会在堆上新建一个对象，[第 4 章](/chapter/04) 4.7 节讲过。
2. **栈和堆的分工是运行时的实现细节。** C# 语言本身并不规定哪个变量必须放在哪里。这里讲的是最常见的情况，用来帮助理解，不是铁律。

## 5.11 为什么值类型不受影响，引用类型会受影响

赋值和传参遵循同一条规则，都是把变量里装的东西复制一份。

- 值类型装的是数据，复制的就是数据。两个变量各有一份，互不影响。
- 引用类型装的是地址，复制的就是地址。两个变量指向同一个对象，通过任何一个修改对象，另一个都能看到。

<img class="lt-img-light" src="/content/images/ch05-fig01-value-ref.svg" alt="值类型复制数据，引用类型复制地址" />
<img class="lt-img-dark" src="/content/images/ch05-fig01-value-ref-dark.svg" alt="值类型复制数据，引用类型复制地址" />

### 赋值时

```csharp
int a = 1;
int b = a;               // 复制数值 1
b = 2;
Console.WriteLine(a);    // 1，a 不受影响

var list1 = new List<int> { 1 };
var list2 = list1;       // 复制地址，两个变量指向同一个列表
list2.Add(2);
Console.WriteLine(list1.Count);    // 2，list1 也能看到变化
```

元组和 class 的例子也是一样的。

```csharp
var t1 = (Name: "api", Ms: 45);    // 元组是值类型
var t2 = t1;
t2.Ms = 999;
Console.WriteLine(t1.Ms);          // 45，t2 只是一份副本

var c1 = new Counter { Value = 1 };    // Counter 是一个只有 int 字段 Value 的 class
var c2 = c1;
c2.Value = 99;
Console.WriteLine(c1.Value);           // 99，c1 和 c2 指向同一个对象
```

### 传参时

方法的参数也是变量。调用方法时，参数会得到一份复制，所以传参和赋值的规则完全相同。

```csharp
static void ChangeNumber(int number)
{
    number = 999;          // 改的是副本
}

var value = 1;
ChangeNumber(value);
Console.WriteLine(value);  // 1，外面的变量不受影响
```

<img class="lt-img-light" src="/content/images/ch05-fig03-param-copy.svg" alt="值类型参数是副本，引用类型参数是地址的副本" />
<img class="lt-img-dark" src="/content/images/ch05-fig03-param-copy-dark.svg" alt="值类型参数是副本，引用类型参数是地址的副本" />

引用类型的参数，复制的是地址。方法通过这个地址修改对象，外面能看到；但如果方法让参数指向一个新对象，外面的变量不会跟着变。

```csharp
static void AddItem(List<string> items)
{
    items.Add("新加的元素");       // 通过地址修改同一个列表
}

static void Reassign(List<string> items)
{
    items = new List<string>();    // 只是让方法里的副本指向新列表
}

var list = new List<string>();
AddItem(list);
Console.WriteLine(list.Count);     // 1，列表的内容被改了

Reassign(list);
Console.WriteLine(list.Count);     // 仍然是 1，外面的变量还指向原来的列表
```

把这些情况整理成一张表。

| 操作 | 值类型（`int`、元组、`struct`） | 引用类型（`class`、`List`、数组、`string`） |
| --- | --- | --- |
| `b = a` | 复制数据，两份独立 | 复制地址，两个变量指向同一个对象 |
| 方法里 `参数 = 新值` | 只改副本，外面不变 | 只改副本的指向，外面不变 |
| 方法里修改参数的内容（`参数.Add(...)`、`参数.字段 = ...`） | 只改副本，外面不变 | 改的是同一个对象，外面能看到 |

### 为什么 `string` 看起来像值类型

`string` 是引用类型，但它不能被修改。下面的方法看起来像是改了字符串，其实没有。

```csharp
static void ChangeString(string s)
{
    s = "changed";         // 只是让方法里的副本指向一个新字符串
}

var text = "orig";
ChangeString(text);
Console.WriteLine(text);    // orig
```

`string` 里没有"修改内容"的操作，所以表格的第三行对它没有意义。想得到不同的字符串，只能生成新的字符串，比如 `Replace` 会返回一个新字符串，原来的字符串保持不变。因此 `string` 在使用上表现得和值类型一样。

### 数组是引用类型

数组也是引用类型，传参时复制的是地址，所以修改元素会影响外面。

```csharp
static void ChangeArray(int[] items)
{
    items[0] = 100;        // 通过地址修改同一个数组
}

int[] arr = { 1, 2, 3 };
ChangeArray(arr);
Console.WriteLine(arr[0]);    // 100
```

### 想让方法替换调用方的变量，`ref`

如果确实需要让方法替换调用方的变量，就要用 `ref`。加了 `ref`，传过去的就是变量本身。

```csharp
static void Reset(ref int value)
{
    value = 0;             // 直接改掉调用方的那个变量
}

var x = 42;
Reset(ref x);              // 调用时也要写 ref
Console.WriteLine(x);      // 0
```

> 值类型传的是数据的副本，引用类型传的是地址的副本。拿到副本的方法，能通过地址修改对象；但给副本重新赋值，改不了调用方手里的地址。

## 5.12 `==` 与 `Equals`，比较的是值还是地址

`==` 比较的是什么，取决于类型。

- **值类型**，`==` 比较内容。`(Name: "api", Ms: 45) == (Name: "api", Ms: 45)` 的结果是 `True`。
- **引用类型**，`==` 默认比较地址，也就是两个变量是不是指向同一个对象。
- **`string`**，虽然是引用类型，但 `==` 比较的是内容。

```csharp
var l1 = new List<int> { 1 };
var l2 = new List<int> { 1 };
var l3 = l1;

Console.WriteLine(l1 == l2);     // False，两个不同的对象
Console.WriteLine(l1 == l3);     // True，指向同一个对象
Console.WriteLine(l1.Equals(l2));    // False，List 的 Equals 也是比较地址

string s1 = "ab";
string s2 = "a" + "b";
Console.WriteLine(s1 == s2);     // True，string 的 == 比较内容
```

想比较两个列表的内容是否一样，可以用 `SequenceEqual`，它会逐项比较。这是 LINQ 的方法，[第 10 章](/chapter/10)会讲。

```csharp
var l4 = new List<int> { 1, 2 };
var l5 = new List<int> { 1, 2 };
Console.WriteLine(l4.SequenceEqual(l5));    // True
```

| 写法 | 比较的是什么 |
| --- | --- |
| 值类型的 `a == b` | 内容 |
| `class`、`List`、数组的 `a == b` | 是不是同一个对象 |
| `string` 的 `a == b` | 内容 |
| `a.SequenceEqual(b)` | 两个序列的每一项是否相同 |

`record` 的 `==` 会按内容比较，这是 `record` 的特点，[第 6 章](/chapter/06) 6.8 节讲过。

## 5.13 作用域，变量的地盘

```csharp
var outer = "外面";

if (true)
{
    var inner = "里面";
    Console.WriteLine(outer);      // 可以看见外面的变量
    Console.WriteLine(inner);      // 在这里可以看见自己的变量
}

Console.WriteLine(inner);          // 编译错误：inner 在这里不存在
```

规则有三条。

- 变量从声明的那一行开始有效，到所在的 `{ }` 结束为止；
- 内层代码能看见外层的变量，外层代码看不见内层的变量；
- 同一个作用域里，不能声明两个同名的变量。

方法的参数和局部变量在方法结束后就不再存在，方法之外的代码看不到它们。

## 5.14 动手，把统计拆成方法

下面把[第 4 章](/chapter/04)的统计改写成方法。主流程只剩几行。方法放在 `LogReport` 类里，类的完整写法[第 6 章](/chapter/06)再讲，这里先把它当成一个收纳方法的盒子。

主流程如下。

```csharp
// ============================================
// 第 5 章 · 方法
// ============================================

var logs = LogReport.LoadDemoLogs();
Console.WriteLine($"共 {logs.Count} 条日志");
Console.WriteLine();

LogReport.PrintLevelDistribution(logs);
LogReport.PrintSlowest(logs, top: 3);
LogReport.PrintProblemsByModule(logs);
LogReport.PrintErrorRatio(logs);

var parsed = LogReport.TryParseLevel("WARN", out var level);
Console.WriteLine($"TryParseLevel(\"WARN\") → {level}，{(parsed ? "成功" : "失败")}");
Console.WriteLine($"按秒显示：{LogReport.Format(1520, "s")}");
```

`LogReport` 类如下。

```csharp
/// <summary>
/// 一组围绕"日志报告"的方法。
/// 现在只需理解：类是一个"方法的收纳盒"，用 <c>LogReport.Xxx()</c> 来调用。
/// </summary>
static class LogReport
{
    // 每次跑都返回同一批演示数据（真实项目里这里是读文件）
    public static List<(string Level, string Module, int Ms)> LoadDemoLogs() =>
    [
        ("info",  "api",   45),
        ("info",  "api",   62),
        ("warn",  "api",   968),
        ("error", "order", 1520),
        ("info",  "order", 23),
        ("error", "order", 2815),
        ("info",  "cache", 12),
        ("warn",  "order", 680),
    ];

    public static void PrintLevelDistribution(List<(string Level, string Module, int Ms)> logs)
    {
        Console.WriteLine("级别分布：");

        string[] levels = { "info", "warn", "error" };
        foreach (var level in levels)
        {
            Console.WriteLine($"  {level,-6}{CountLevel(logs, level)} 条");
        }

        Console.WriteLine();
    }

    // top 有默认值：不写就是 3
    public static void PrintSlowest(List<(string Level, string Module, int Ms)> logs, int top = 3)
    {
        Console.WriteLine($"最慢的 {top} 条：");

        // 每次在"还没打印过的"里找最大的一条，找到就标记
        var printed = new bool[logs.Count];
        for (var n = 0; n < top && n < logs.Count; n++)
        {
            var best = -1;
            for (var i = 0; i < logs.Count; i++)
            {
                if (!printed[i] && (best == -1 || logs[i].Ms > logs[best].Ms))
                {
                    best = i;
                }
            }

            printed[best] = true;
            var (level, module, ms) = logs[best];
            Console.WriteLine($"  {ms,5} ms  {module,-6}{level}");
        }

        Console.WriteLine();
    }

    public static void PrintProblemsByModule(List<(string Level, string Module, int Ms)> logs)
    {
        Console.WriteLine("各模块问题数：");

        // 按模块第一次出现的顺序记录问题数
        var modules = new List<string>();
        var problems = new Dictionary<string, int>();
        foreach (var log in logs)
        {
            if (log.Level != "warn" && log.Level != "error")
            {
                continue;
            }

            if (!problems.ContainsKey(log.Module))
            {
                modules.Add(log.Module);
                problems[log.Module] = 0;
            }
            problems[log.Module]++;
        }

        foreach (var module in modules)
        {
            Console.WriteLine($"  {module,-6}{problems[module]} 个");
        }

        Console.WriteLine();
    }

    public static void PrintErrorRatio(List<(string Level, string Module, int Ms)> logs)
    {
        var ratio = ErrorRatio(logs);
        Console.WriteLine($"error 占比 {AsPercent(ratio)}");

        // 局部函数：只在这个方法里有意义的格式化逻辑
        static string AsPercent(double value) => $"{value * 100:F1}%";
    }

    // 有返回值的方法：只负责算，不负责打印
    public static double ErrorRatio(List<(string Level, string Module, int Ms)> logs)
    {
        if (logs.Count == 0)
        {
            return 0;                  // 提前返回，避免除以 0
        }

        return CountLevel(logs, "error") / (double)logs.Count;
    }

    // 数一数某个级别出现了几次
    public static int CountLevel(List<(string Level, string Module, int Ms)> logs, string level)
    {
        var count = 0;
        foreach (var log in logs)
        {
            if (log.Level == level)
            {
                count++;
            }
        }
        return count;
    }

    // out 参数：成功/失败 + 规范化后的值，一次返回两样东西
    public static bool TryParseLevel(string text, out string normalized)
    {
        normalized = text.Trim().ToLowerInvariant();

        if (normalized is "info" or "warn" or "error" or "debug")
        {
            return true;
        }

        normalized = "unknown";
        return false;
    }

    // 重载：在类里就可以同名不同参了
    public static string Format(int ms) => $"{ms} ms";

    public static string Format(int ms, string unit) => unit == "s" ? $"{ms / 1000.0:F2} s" : $"{ms} {unit}";
}

```

运行结果（真实输出）如下。

```text
共 8 条日志

级别分布：
  info  4 条
  warn  2 条
  error 2 条

最慢的 3 条：
   2815 ms  order error
   1520 ms  order error
    968 ms  api   warn

各模块问题数：
  api   1 个
  order 3 个

error 占比 25.0%
TryParseLevel("WARN") → warn，成功
按秒显示：1.52 s
```

### 各个方法做什么

| 方法 | 做什么 | 为什么这样写 |
| --- | --- | --- |
| `LoadDemoLogs` | 返回一批演示数据 | 真实项目里这里会改成读文件，主流程不用动 |
| `PrintLevelDistribution` | 打印级别分布 | 级别按固定顺序输出，数数时调用 `CountLevel` |
| `PrintSlowest` | 打印最慢的若干条 | `top` 有默认值 3；每次在还没打印过的记录里找最大的一条 |
| `PrintProblemsByModule` | 打印各模块的问题数 | 按模块第一次出现的顺序输出，和[第 4 章](/chapter/04)的结果一致 |
| `PrintErrorRatio` | 打印 error 占比 | 只负责输出，计算交给 `ErrorRatio` |
| `ErrorRatio` | 返回 error 占比 | 有返回值，不打印东西；日志为空时提前返回 0，避免除以 0 |
| `CountLevel` | 数出某个级别的条数 | 被好几个方法共用，这就是"重复的代码收进方法"的效果 |
| `TryParseLevel` | 规范化级别文字 | 用 `out` 同时返回"是否成功"和"规范化的结果" |
| `Format` 两个重载 | 格式化耗时 | 必须放在类里才能重载 |

这一节要养成的习惯是**计算和输出分开**。`ErrorRatio` 只算数字，`PrintErrorRatio` 只负责打印。计算的部分不依赖控制台，可以单独测试，也可以在别的地方复用。

### 重构前后对比

| | 重构前（[第 4 章](/chapter/04)） | 重构后（第 5 章） |
| --- | --- | --- |
| 主流程 | 几十行平铺在一起 | 几行，读起来像目录 |
| 新增"按模块统计" | 复制粘贴一段循环 | 调用 `PrintProblemsByModule` |
| 想知道"哪几条最慢" | 从头读 | 直接找 `PrintSlowest` |
| 想测试占比的计算 | 很难单独测 | 直接调用 `ErrorRatio` |

拆开以后，阅读和修改更省力，但代码行数不一定变少。

## 5.15 常见错误

下面的错误码和含义来自 .NET 10 的编译器。提示文字会随系统语言变化，以错误码为准。

| 错误码 | 含义 | 常见原因 | 怎么改 |
| --- | --- | --- | --- |
| `CS0161` | 并非所有的代码路径都返回值 | 某个分支没有 `return` | 每条分支都返回值，或者在末尾补一个返回值 |
| `CS0162` | 检测到无法访问的代码 | `return` 后面还有语句 | 删掉多余的语句，或者用 `if` 包起来 |
| `CS7036` | 缺少必需的参数 | 调用时少传了参数 | 补上参数，或者给参数加默认值 |
| `CS1501` | 没有任何重载接受这么多参数 | 参数个数对不上 | 对照方法定义，检查个数和类型 |
| `CS0128` | 同一作用域里有重名的变量或函数 | 顶层语句里有同名的方法，或者同名变量 | 换名字；需要重载就放进类里 |
| `CS0111` | 类型中已经有同名、同参数的成员 | 只靠返回类型区分两个方法 | 改参数，或者改名字 |
| `CS0103` | 当前上下文中不存在这个名称 | 在 `{ }` 外面使用了里面声明的变量 | 把变量的声明挪到需要它的范围里 |
| `CS0177` | `out` 参数必须在返回前赋值 | 某条分支忘了给 `out` 参数赋值 | 每条返回路径上都先给 `out` 参数赋值 |
| `CS1620` | 实参必须带 `ref` 关键字 | 形参是 `ref`，调用时忘了写 `ref` | 调用时写成 `Reset(ref x)` |
| 方法里改了 `int`，外面没变 | 值类型传的是副本 | 误以为会改到外面的变量 | 用返回值接收结果，或者用 `ref`（慎用） |
| 方法里 `items = new ...`，外面没变 | 只改了方法内的变量指向 | 误以为能替换调用方的列表 | 直接修改内容（`Add`、`Clear`），或者返回新列表 |
| `CS0037` | 不能把 `null` 赋给值类型 | `int n = null;`，`int` 是值类型，不能为 `null` | 改成 `int?`，或者给一个默认值 |
| `CS1593` | 参数个数与委托不符 | `Func<int, int> f = (x, y) => x;`，委托只接收一个参数 | 对照委托类型，检查参数个数 |
| `CS0029` 与 `CS1662` | lambda 的返回类型与委托不符 | `Func<int, int> f = x => Console.WriteLine(x);`，`WriteLine` 没有返回值 | 需要返回值就 `return` 一个 `int`；只执行动作就用 `Action` |
| `CS0201` | 表达式不能单独作为语句 | `Action a = () => 5;`，`5` 什么都不做 | 写成有实际动作的语句，例如方法调用 |
| `CS0841` | 变量在声明之前就被使用 | lambda 捕获了后面才声明的变量 | 把变量的声明挪到 lambda 之前 |
| 比较两个 `List`，结果是 `False` | `==` 比较的是地址 | 两个列表内容相同，但是两个对象 | 用 `SequenceEqual` 比较内容（5.12 节） |

**练习 3**

```csharp
static void Play()
{
    const int answer = 42;
    var attempts = 0;

    while (true)
    {
        var guess = ReadGuess();
        if (guess is null)
        {
            Console.WriteLine("请输入整数。");
            continue;
        }

        attempts++;
        var verdict = Judge(guess.Value, answer);
        Console.WriteLine(verdict);

        if (verdict == "对了")
        {
            Console.WriteLine($"共猜了 {attempts} 次");
            return;
        }
    }
}

static int? ReadGuess()
{
    Console.Write("猜一个数字：");
    return int.TryParse(Console.ReadLine(), out var value) ? value : null;
}

static string Judge(int guess, int answer) =>
    guess == answer ? "对了" : guess < answer ? "小了" : "大了";
```

> `int?` 表示"可以为空的 `int`"，[第 2 章](/chapter/02)讲过可空标注。`guess.Value` 用来取出里面的值。

**练习 4**

输出 `1 2`。元组是值类型，`b = a` 复制了一份数据，`b.Ms = 2` 只改了副本，`a.Ms` 仍然是 1。`List` 是引用类型，`copy = list` 复制的是地址，`copy.Add(2)` 修改的是同一个对象，所以 `list.Count` 是 2。

**练习 6**

```csharp
static Func<int> MakeCounter()
{
    var count = 0;
    return () =>
    {
        count++;
        return count;
    };
}

var next = MakeCounter();
Console.WriteLine(next());    // 1
Console.WriteLine(next());    // 2
Console.WriteLine(next());    // 3
```

`count` 被 lambda 捕获。`MakeCounter` 返回之后，`count` 仍然存在，它住在堆上的一个对象里（5.10 节）。每次调用 `MakeCounter` 都会得到一个新的 `count`，所以两个计数器互不影响。再调用一次 `MakeCounter()` 得到的新计数器从 1 开始，原来的计数器则接着往下数，此时再调用会得到 4。
