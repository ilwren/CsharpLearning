## 3.1 if，条件成立才执行

```csharp
int ms = 1520;

if (ms > 1000)
{
    Console.WriteLine("这是一条慢请求");
}
```

`if` 后面的圆括号里是条件，它的结果必须是 `bool`。条件为 `true` 时，执行花括号里的语句。条件为 `false` 时，整个花括号跳过，程序接着往下走。

花括号 `{ }` 圈出的部分叫代码块。缩进是给人看的，编译器只认花括号。3.8 节的陷阱会用到这一点。

判断相等要用 `==`，不能用 `=`。写成 `if (ms = 1000)`，编译器会报 CS0029，因为 `ms = 1000` 的结果是 `int`，而 `if` 需要的是 `bool`。这一点 2.6 节讲过。

### 条件从哪里来

`if` 里的条件通常来自下面三种地方。

**比较运算**。`==`、`!=`、`<`、`<=`、`>`、`>=` 的结果都是 `bool`。

```csharp
int ms = 1520;

if (ms >= 1000)
{
    Console.WriteLine("慢");
}
```

**`bool` 变量**。把判断结果先存进一个变量，`if` 里只写变量名，读起来更清楚。

```csharp
string level = "critical";
bool isError = level == "error" || level == "critical";

if (isError)
{
    Console.WriteLine("需要立刻处理");
}
```

`if (isError == true)` 也能运行，但多写了一截，直接写 `if (isError)` 即可。

**返回 `bool` 的方法**。`string.IsNullOrWhiteSpace(line)` 和 `line.StartsWith("#")` 的返回值都是 `bool`，可以直接放进 `if` 的圆括号里。3.9 节的检查点就是这样用的。

### 组合条件与优先级

```csharp
bool a = true;
bool b = false;
bool c = false;

Console.WriteLine(a || b && c);
Console.WriteLine((a || b) && c);
```

输出如下。

```text
True
False
```

`!` 的优先级最高，其次是 `&&`，最后是 `||`。所以 `a || b && c` 先算 `b && c`，得到 `false`，再算 `a || false`，得到 `true`。想让 `||` 先算，就加上括号。2.6 节列过完整的优先级，`&&` 和 `||` 的短路也在那里讲过。平时写的时候，多加括号不会改变结果，读的人也不用去记优先级表。

### 不能把范围判断连着写

很多人可能会这样写。

```csharp
int x = 3;

if (1 < x < 5)
{
    Console.WriteLine("在范围内");
}
```

编译器报 CS0019。`1 < x` 先算，得到的是 `bool`，再拿这个 `bool` 去和 `5` 比较。`bool` 不能和 `int` 比大小。正确的写法是把两个条件分开，用 `&&` 连起来。

```csharp
int x = 3;

if (x > 1 && x < 5)
{
    Console.WriteLine("在范围内");
}
```

输出 `在范围内`。

### 字符串比较

2.8 节讲过，`==` 比较字符串时区分大小写。需要忽略大小写时，用 `string.Equals` 并指定比较方式。

```csharp
Console.WriteLine("ERROR" == "error");
Console.WriteLine(string.Equals("ERROR", "error", StringComparison.OrdinalIgnoreCase));
```

输出如下。

```text
False
True
```

另一种办法是先统一转成小写再比较，3.9 节的检查点就是这样做的。

### 判断字符串是否为空

```csharp
string? s1 = null;

Console.WriteLine(string.IsNullOrEmpty(s1));
Console.WriteLine(string.IsNullOrEmpty("  "));
Console.WriteLine(string.IsNullOrWhiteSpace("  "));
```

输出 `True`、`False`、`True`。`string.IsNullOrEmpty` 只挡住 `null` 和空字符串 `""`，像 `"  "` 这种只有空白的字符串它不认。`string.IsNullOrWhiteSpace` 连空白也挡住。读用户输入的时候，一般用后者。

### 先判断 null，再访问成员

```csharp
string? s1 = null;

if (s1 != null && s1.Length > 0)
{
    Console.WriteLine("有内容");
}
else
{
    Console.WriteLine("空");
}
```

输出 `空`。`&&` 左边为 `false` 时，右边不再计算，所以 `s1.Length` 根本不会被访问。

如果把两个条件的顺序对调，写成 `if (s1.Length > 0 && s1 != null)`，编译器会给出 CS8602 警告。运行时会抛出 `NullReferenceException`，程序崩溃。所以判断 `null` 要放在访问成员的前面。

### 小数不要直接用 == 比较

```csharp
Console.WriteLine(0.1 + 0.2 == 0.3);
Console.WriteLine(Math.Abs((0.1 + 0.2) - 0.3) < 1e-9);
```

输出 `False` 和 `True`。2.3 节讲过，`double` 存的是二进制的近似值，`0.1 + 0.2` 并不正好等于 `0.3`。判断两个小数是否相等，要看它们的差是否小到可以忽略，也就是比较差的绝对值和一个很小的数。金额一律用 `decimal`。

## 3.2 else if 与嵌套

### 从上往下检查

```csharp
int ms = 800;

if (ms > 1000)
{
    Console.WriteLine("慢请求");
}
else if (ms > 300)
{
    Console.WriteLine("一般");
}
else
{
    Console.WriteLine("快");
}
```

输出 `一般`。程序从上往下逐个检查条件，哪一个先成立，就执行哪一个代码块，后面的全部跳过。`else` 处理前面所有条件都不成立的情况。

<img class="lt-img-light" src="/content/images/ch03-fig01-if-chain.svg" alt="if、else if、else 的执行顺序" />
<img class="lt-img-dark" src="/content/images/ch03-fig01-if-chain-dark.svg" alt="if、else if、else 的执行顺序" />

因为是从上往下检查，条件的顺序会影响结果。下面两段代码只是把两个条件对调了位置。

```csharp
int ms = 1520;

if (ms > 300)
{
    Console.WriteLine("一般");
}
else if (ms > 1000)
{
    Console.WriteLine("慢请求");
}
```

输出的是 `一般`。1520 先满足了 `ms > 300`，`else if (ms > 1000)` 这一行永远不会被检查。写多个分支时，要把范围最严的条件放在最前面，或者让每个条件互不重叠。

### 嵌套 if

一个 `if` 里面还可以再放 `if`，这叫嵌套。内层的条件只有在外层成立时才会被检查。

```csharp
bool isLoggedIn = true;
bool isAdmin = false;

if (isLoggedIn)
{
    if (isAdmin)
    {
        Console.WriteLine("管理员");
    }
    else
    {
        Console.WriteLine("普通用户");
    }
}
else
{
    Console.WriteLine("请先登录");
}
```

输出 `普通用户`。嵌套的层数越多，缩进就越深，读起来越吃力。下面的卫语句可以减少层数。

### 悬挂 else

`if` 后面没有花括号时，只有紧跟的那一句属于它。遇到 `else`，它会跟最近的一个 `if` 配对，而不是跟缩进对齐的那个 `if` 配对。下面这段代码本想让 `else` 跟外层的 `if` 配对。

```csharp
bool hasFile = false;
bool isAdmin = true;

if (hasFile)
    if (isAdmin)
        Console.WriteLine("管理员，文件已打开");
else
    Console.WriteLine("没有文件");
```

输出什么都没有。`else` 实际跟的是内层的 `if (isAdmin)`。`hasFile` 为 `false`，内层的 `if` 根本不会被检查，`else` 也不执行。

加上花括号，结构就清楚了。

```csharp
bool hasFile = false;
bool isAdmin = true;

if (hasFile)
{
    if (isAdmin)
    {
        Console.WriteLine("管理员，文件已打开");
    }
}
else
{
    Console.WriteLine("没有文件");
}
```

输出 `没有文件`。嵌套的 `if` 只要有 `else`，就都加上花括号，这样不管缩进怎样，配对关系都一目了然。

### 卫语句，先把特殊情况挡在外面

卫语句（guard clause）指写在代码开头的判断。遇到不需要继续的情况，就提前结束，剩下的主流程留在最外层，不用再多套一层 `if`。

```csharp
string? line = Console.ReadLine();

if (line == null)
{
    Console.WriteLine("没有输入");
    return;
}

if (line.StartsWith("#"))
{
    Console.WriteLine("注释，跳过");
    return;
}

Console.WriteLine($"处理：{line}");
```

没有输入时输出 `没有输入`；输入 `# 注释` 时输出 `注释，跳过`；输入 `error 超时` 时输出 `处理：error 超时`。这里的 `return` 结束整个程序。[第 5 章](/chapter/05)讲方法以后，`return` 会结束当前的方法，写法是一样的。

## 3.3 switch，同一个变量对照多个固定值

同一个变量要和好几个固定的值比较时，用 `switch` 写会更清楚。

```csharp
int day = 6;

switch (day)
{
    case 6:
    case 7:
        Console.WriteLine("周末");
        break;
    default:
        Console.WriteLine("工作日");
        break;
}
```

输出 `周末`。`switch` 后面括号里的变量，依次和每个 `case` 后面的值比较。相等时，从那个 `case` 开始执行，一直到遇到 `break` 为止。`default` 相当于 `else`，前面的 `case` 都不相等时执行它。

### 分组与穿透

`case 6:` 和 `case 7:` 写在一起，表示两个值共用下面的代码。这叫分组。

每个有代码的 `case` 末尾都要有 `break`，或者 `return`、`continue`、`throw` 这类能离开这段代码的语句。漏掉以后，编译器会报 CS0163，不允许一个 `case` 的代码直接落到下一个 `case` 里。

```csharp
char grade = 'B';

switch (grade)
{
    case 'A':
    case 'B':
        Console.WriteLine("良好及以上");
        break;
    case 'C':
        Console.WriteLine("及格");
        break;
    default:
        Console.WriteLine("需要加油");
        break;
}
```

输出 `良好及以上`。`switch` 也能比较 `char`，上面的 `'A'`、`'B'` 都是字符。

### 字符串与大小写

`switch` 也可以比较字符串。3.9 节的检查点就是这样做的。比较字符串时同样区分大小写，所以通常先用 `ToLowerInvariant()` 统一成小写，再进入 `switch`。

```csharp
string level = "WARN".ToLowerInvariant();

switch (level)
{
    case "warn":
        Console.WriteLine("警告");
        break;
    default:
        Console.WriteLine("其他");
        break;
}
```

输出 `警告`。

### case 里声明的变量

整个 `switch` 的花括号是一个作用域，所有 `case` 共用它。在一个 `case` 里声明的变量，另一个 `case` 也能看到。所以下面的写法会报 CS0128，提示 `msg` 已经在这个作用域里定义过了。

```csharp
int n = 2;

switch (n)
{
    case 1:
        var msg = "一";
        Console.WriteLine(msg);
        break;
    case 2:
        var msg = "二";
        Console.WriteLine(msg);
        break;
}
```

改法是给每个会声明变量的 `case` 加上花括号，让变量只在它自己的代码块里有效。

```csharp
int n = 2;

switch (n)
{
    case 1:
    {
        var msg = "一";
        Console.WriteLine(msg);
        break;
    }
    case 2:
    {
        var msg = "二";
        Console.WriteLine(msg);
        break;
    }
}
```

输出 `二`。

`switch` 只能拿固定的值来比较。`> 1000` 这样的范围条件要用 `if`。

## 3.4 while，不知道要重复几次

`while` 适合这种情况。你不知道要重复几次，只知道什么时候应该停。

```csharp
int countdown = 3;

while (countdown > 0)
{
    Console.WriteLine($"倒计时 {countdown}");
    countdown--;
}

Console.WriteLine("开始！");
```

输出如下。

```text
倒计时 3
倒计时 2
倒计时 1
开始！
```

`while` 每次进入循环前，先检查条件。条件为 `true`，就执行一遍花括号里的代码，然后回到条件前再检查。`countdown--` 让变量每次减 1，条件最终变成 `false`，循环停止。这一行不能省，忘了它，循环就停不下来，见 [3.8 节](#s3-8)。

### do-while，至少执行一次

`do-while` 把条件放在最后检查。这意味着循环体至少会执行一次。

```csharp
int attempts = 0;

do
{
    attempts++;
    Console.WriteLine($"第 {attempts} 次尝试");
} while (attempts < 0);
```

输出 `第 1 次尝试`。条件 `attempts < 0` 一开始就是 `false`，但循环体已经执行了一次。这个写法适合“先做一次，再决定要不要重复”的场景，比如先显示一次菜单。

`while (...)` 后面要加分号。

## 3.5 for 与 foreach

### for，知道要重复几次

```csharp
for (int i = 1; i <= 3; i++)
{
    Console.WriteLine($"第 {i} 行");
}
```

输出三行。`for` 后面的圆括号里有三部分，中间用分号隔开。

| 部分 | 这里是 | 作用 |
| --- | --- | --- |
| 初始化 | `int i = 1` | 循环开始前执行一次，声明计数变量 |
| 条件 | `i <= 3` | 每次进入循环体前检查 |
| 变化 | `i++` | 每次循环体执行完，执行一次 |

`i` 只在这个 `for` 循环里有效，循环结束后它就不存在了。所以下一个 `for` 可以再次使用 `int i`。

### foreach，一个一个取出

`foreach` 不需要知道次数，它会依次取出一组东西里的每一项。

```csharp
foreach (char c in "LOG")
{
    Console.WriteLine(c);
}
```

输出 `L`、`O`、`G` 三行。字符串可以看成一串字符，所以能这样遍历。

3.9 节的检查点里，`Split` 切出来的一组字符串也用 `foreach` 逐个处理。数组和集合会在后面的章节细讲，这里只需要知道 `foreach` 会挨个取出每一项。

## 3.6 break 与 continue

`break` 直接结束离它最近的那一层循环。`continue` 跳过本轮剩下的代码，直接进入下一轮。

```csharp
for (int i = 1; i <= 10; i++)
{
    if (i % 2 == 0)
    {
        continue;
    }

    if (i > 7)
    {
        break;
    }

    Console.WriteLine(i);
}
```

输出 `1`、`3`、`5`、`7`。偶数被 `continue` 跳过，所以 2、4、6、8 都不会打印。到 9 时，`i > 7` 成立，`break` 结束整个循环，10 也就不会被处理。

### 嵌套循环中的 break

一个循环里面还可以再放一个循环。`break` 只会跳出它所在的那一层。

```csharp
for (int i = 1; i <= 3; i++)
{
    for (int j = 1; j <= 3; j++)
    {
        if (j == 2)
        {
            break;
        }

        Console.WriteLine($"{i}-{j}");
    }
}
```

输出 `1-1`、`2-1`、`3-1`。每次 `j` 到 2 时，内层循环被 `break` 结束，外层的 `i` 继续增加。`break` 不会一次跳出两层。

## 3.7 该选哪种循环

| 情况 | 用哪个 |
| --- | --- |
| 知道要重复几次 | `for` |
| 逐个处理一组东西 | `foreach` |
| 不知道几次，只知道什么时候停 | `while` |
| 至少要执行一次 | `do-while` |

这张表不用背。写的时候先问自己，次数是不是已知的，有没有一组要挨个处理的东西。

## 3.8 常见陷阱

### 陷阱一，if 后面多了分号

```csharp
int x = 3;

if (x > 5);
{
    Console.WriteLine("x 大于 5");
}
```

输出 `x 大于 5`，可是 `x` 明明是 3。`if (x > 5);` 后面的分号结束了 `if`，它只管这一个空语句。后面的花括号变成了一个普通的代码块，无论条件是什么，都会执行。编译器会给出 CS0642 警告。

`for` 后面多写分号也是同样的问题。`for (int i = 0; i < 3; i++);` 的循环体是空的，它只会把 `i` 数到 3，什么都不做。

### 陷阱二，省略花括号后，只有一句属于 if

```csharp
int y = 1;

if (y > 5)
    Console.WriteLine("y 大于 5");
    Console.WriteLine("这一句总会执行");
```

`if` 后面没有花括号时，只有紧跟的那一句属于 `if`。第二个 `WriteLine` 缩进看起来像属于 `if`，其实不属于。输出只有 `这一句总会执行`。

这个写法能省几行，但很容易在以后加一句代码时出错。本书的代码一律写花括号。

### 陷阱三，<= 比 < 多跑一次

```csharp
int count = 0;

for (int k = 0; k <= 5; k++)
{
    count++;
}

Console.WriteLine($"共执行 {count} 次");
```

输出 `共执行 6 次`。从 0 数到 5 一共是 6 个数，`k` 取到了 0、1、2、3、4、5。想要 5 次，就写 `k < 5`。

### 陷阱四，忘了改变条件，死循环

下面这段代码不要运行。

```csharp
int count = 0;

while (count < 5)
{
    Console.WriteLine(count);
}
```

`count` 从来没有变过，条件永远为 `true`，程序会一直打印 0，直到你按 Ctrl+C 强行停止。改法是在循环体里加一句 `count++;`。

### 陷阱五，读到输入结束还在等

`Console.ReadLine()` 在输入结束时返回 `null`。输入结束指的是管道关闭，或者在终端里按下结束键，Linux 和 macOS 上是 Ctrl+D，Windows 上是 Ctrl+Z 再回车。

如果循环里只在转换失败时才 `continue`，却不判断 `null`，那么 `int.TryParse(null, ...)` 会一直返回 `false`，循环永远停不下来。3.9 节的检查点用 `string.IsNullOrWhiteSpace` 判断空行和 `null`，就是为了避免这种情况。

## 3.9 动手，日志级别小助手

这个程序分成三部分。第一步循环读入每一行，第二步统计各类数量，第三步给出结论。整个程序只用到本章学过的写法。

在 `code/ch03-flow/` 文件夹里运行 `dotnet run`，然后按照上面的示例输入。

```csharp
// ============================================
// 第 3 章 · 条件与循环
// 运行方式：dotnet run
// ============================================

Console.WriteLine("请输入日志级别，空格分隔，例如 info warn error。");
Console.WriteLine("每行一条，输入空行结束。以 # 开头的行是注释，会被跳过。");

int total = 0;
int debugCount = 0;
int infoCount = 0;
int warnCount = 0;
int errorCount = 0;
int unknownCount = 0;

// 1) while 循环：一直读，直到用户输入空行
while (true)
{
    Console.Write("> ");
    var line = Console.ReadLine();

    // 标准输入结束（null）或空行，都停止读取
    if (string.IsNullOrWhiteSpace(line))
    {
        break;
    }

    // 注释行直接跳到下一轮
    if (line.StartsWith("#"))
    {
        continue;
    }

    // 2) 一行里可能有好几个级别，逐个处理
    var levels = line.Split(' ', StringSplitOptions.RemoveEmptyEntries);
    foreach (var raw in levels)
    {
        var level = raw.ToLowerInvariant();
        total++;

        // 3) switch：按级别分支。case 后面要写 break，防止穿透到下一个 case
        switch (level)
        {
            case "debug":
                debugCount++;
                break;
            case "info":
                infoCount++;
                break;
            case "warn":
                warnCount++;
                break;
            case "error":
            case "critical":            // critical 与 error 合并计数
                errorCount++;
                break;
            default:
                unknownCount++;
                break;
        }

        // 4) 需要处理的级别，立刻打印出来
        if (level == "error" || level == "critical" || level == "warn")
        {
            Console.WriteLine($"  需要处理：{level}");
        }
    }
}

// 5) 没有输入任何级别，直接结束
if (total == 0)
{
    Console.WriteLine("没有输入任何级别。");
    return;
}

int problems = errorCount + warnCount;
double percent = problems * 100.0 / total;

Console.WriteLine();
Console.WriteLine($"共 {total} 条，其中问题日志 {problems} 条（{percent:F1}%）");
Console.WriteLine($"分布：debug {debugCount}、info {infoCount}、warn {warnCount}、error {errorCount}、未知 {unknownCount}");

// 6) if / else if / else：给出整体结论
if (errorCount > 0)
{
    Console.WriteLine("结论：有错误，值得看一眼");
}
else if (warnCount > 0)
{
    Console.WriteLine("结论：有警告，可以留意");
}
else
{
    Console.WriteLine("结论：一切正常");
}

// 7) for 循环：用星号画一个简单的柱状图
Console.WriteLine();
Console.Write("错误 ");
for (int i = 0; i < errorCount; i++)
{
    Console.Write("#");
}
Console.WriteLine();

Console.Write("警告 ");
for (int i = 0; i < warnCount; i++)
{
    Console.Write("#");
}
Console.WriteLine();
```

### 逐段解释

| 代码 | 说明 |
| --- | --- |
| `while (true)` | 条件永远为 `true`，所以循环靠内部的 `break` 结束 |
| `string.IsNullOrWhiteSpace(line)` | 空行或 `null` 都返回 `true`，这时 `break` 结束输入，2.9 节讲过 |
| `line.StartsWith("#")` | 字符串方法，判断行是否以 `#` 开头，是注释就 `continue` 跳到下一行 |
| `Split(' ', StringSplitOptions.RemoveEmptyEntries)` | 按空格切开，连续的空格不会产生空字符串 |
| `foreach (var raw in levels)` | 挨个取出切好的每个级别，3.5 节讲过 |
| `switch (level)` | 每个 `case` 结尾都有 `break`，两个 `case` 写在一起表示共用一段代码 |
| `if (level == "error" \|\| ...)` | 需要处理的级别，立刻打印出来 |
| `problems * 100.0 / total` | 写成 `100.0` 而不是 `100`，结果才是小数，2.5 节讲过 |
| `if / else if / else` | 根据错误数和警告数，给出一句结论，3.2 节讲过 |
| `for (int i = 0; i < errorCount; i++)` | 循环次数由错误数决定，每次打印一个 `#` |

### 为什么两个 for 都能用 i

第一个 `for` 声明的 `int i` 只在它自己的循环里有效。第二个 `for` 再声明一次 `int i`，两者互不影响。3.5 节讲过这一点。

### 结论为什么放在最后

程序要先统计完所有输入，才能判断整体的情况。如果一边读一边下结论，结论就只针对前面几行，不代表整份日志。

## 3.10 常见错误

下面的错误编号来自编译器输出。错误信息的文字取决于系统语言，这里只写错误编号和原因。

| 错误编号 | 原因 | 怎么改 |
| --- | --- | --- |
| CS0029 | 把赋值写在了条件的位置，比如 `if (x = 5)` | 比较相等用 `==` |
| CS0019 | 把两个比较连着写，比如 `1 < x < 5`，左边先得到 `bool`，`bool` 不能和数字比较 | 拆成 `x > 1 && x < 5` |
| CS0163 | `case` 的代码末尾漏写了 `break` | 每个 `case` 结尾加 `break`，或用 `return` 之类离开 |
| CS0139 | `break` 写在了循环外面 | 把它放进循环里，或删掉 |
| CS0103 | 变量在 `if` 或 `for` 的花括号里声明，离开花括号后就找不到了 | 把声明移到花括号外面 |
| CS0128 | 多个 `case` 里声明了同名变量 | 每个声明变量的 `case` 加上花括号 |
| CS0642 警告 | `if (...);` 或 `for (...);` 后面多了分号 | 删掉分号 |

下面的代码会同时触发 CS0163、CS0139 和 CS0103，你可以在自己的项目里试一试。

```csharp
int level = 1;

switch (level)
{
    case 1:
        Console.WriteLine("一");
    case 2:
        Console.WriteLine("二");
        break;
}

break;

if (level > 0)
{
    int inside = 5;
}
Console.WriteLine(inside);
```
