## 6.1 从元组说起，面向对象要解决什么问题

[第 4 章](/chapter/04)用元组表示一条日志，代码如下。

```csharp
var logs = new List<(string Level, string Module, int Ms)>
{
    ("error", "order", 1520),
};
```

这样能跑，但有四个问题。

| 问题 | 具体表现 |
| --- | --- |
| 没有校验 | 有人写 `("错误", "", -5)`，编译器不会拦住 |
| 没有行为 | 想判断"是否慢请求"，得在每个调用的地方各写一遍 `ms > 1000` |
| 名字不清楚 | `Item1`、`Item2` 分别是什么？换个文件就忘了 |
| 改起来麻烦 | 以后想加一个 `Timestamp` 字段，所有用到它的地方都要改 |

类要解决的就是这四个问题。接下来用一个更具体的例子，把"面向对象"这件事讲清楚。

### 面向对象用大白话说

写程序时，最自然的做法是"数据放在变量里，操作写成函数"。这种写法叫**过程式**。

```csharp
static bool IsSlow(int durationMs) => durationMs > 1000;

var level = "error";
var module = "order";
var durationMs = 1520;
Console.WriteLine(IsSlow(durationMs));
```

只有一条日志还好。如果同一批数据要在五个地方判断是否慢，每个地方都得记得把 `durationMs` 传给 `IsSlow`。少传一个、传错顺序，编译器不一定能发现，而且慢请求的阈值要改时，得去五个地方改。

面向对象换一种分法，**把一组相关的数据，和只针对这组数据的操作，放在同一个类型里。**

```csharp
public class LogRow
{
    public required string Level { get; init; }
    public required string Module { get; init; }
    public int DurationMs { get; init; }

    public bool IsSlow => DurationMs > 1000;
}
```

```csharp
var row = new LogRow { Level = "error", Module = "order", DurationMs = 1520 };
Console.WriteLine(row.IsSlow);
```

这时判断规则跟着数据走。阈值从 1000 改成 2000，只改 `IsSlow` 这一行，所有调用的地方自动生效。调用的人也不用记住"慢"是怎么算的，问对象就行。

所以，类是**类型的定义**，规定一组数据有哪些、能做哪些操作。对象是**根据定义创建出来的具体实例**，每个对象都有自己的一份数据。`new LogRow { ... }` 就是创建一个对象。

### 面向对象的三大特性与抽象

面向对象常被概括为三大特性，外加一条贯穿其中的思路，即抽象。第一遍读时，只需要对每个词有个印象，细节在后面的章节展开。

- **封装**，把数据藏在类的里面，外面只能通过规定好的入口访问，入口里可以加规则。6.3 节的 `Limit` 属性，外面写 `0` 会被拒绝，就是封装的例子。
- **继承**，让一个类在另一个类的基础上扩展，复用已有的代码。[第 7 章](/chapter/07)讲。
- **多态**，同一个方法调用，由于对象的实际类型不同，执行的代码也不同。[第 7 章](/chapter/07)讲。
- **抽象**，只向外暴露调用的人需要知道的东西，隐藏实现细节。调用 `writer.Write("一行")` 的人不需要知道文件是怎么写进磁盘的。接口和抽象类是 C# 里实现抽象的主要工具，[第 7 章](/chapter/07)讲。

封装和抽象在本章已经能用上。继承和多态要等到[第 7 章](/chapter/07)学了继承以后，才能真正用起来。

### 什么时候该写成类

不是所有东西都要写成类。下面三个问题，有两个以上回答"是"，通常就该考虑建类。

1. 这几个数据是不是总是一起出现、一起使用？比如日志的级别、模块、耗时。
2. 有没有一些规则需要守住？比如耗时不能是负数。
3. 有没有一些操作只围绕这组数据？比如判断是否慢请求、生成显示文本。

只有一个数字、一个临时的中间结果，用一个变量就够了，不必为它造一个类。

## 6.2 第一个类

```csharp
public class LogEntry
{
    // 字段（field）：真正存放数据的地方，习惯上用 _ 开头，并且是 private
    private string _level;

    // 构造函数（constructor）：创建对象时运行的代码
    public LogEntry(string level)
    {
        _level = level;
    }

    // 属性（property）：对外的读写入口，可以在这里加检查
    public string Level
    {
        get => _level;
        set => _level = value;
    }
}
```

创建对象并使用它。

```csharp
var entry = new LogEntry("error");     // new 创建一个新对象，这叫实例化
Console.WriteLine(entry.Level);        // error
entry.Level = "warn";
```

### 几个必须分清的名词

| 名词 | 含义 |
| --- | --- |
| 类（class） | 类型的定义，规定一组数据和操作，本身不存放某一条具体的数据 |
| 对象（object），也叫实例（instance） | 根据类创建出来的一个具体东西，每个对象各有一份字段 |
| `new` | 创建一个新对象，并运行构造函数 |
| 字段（field） | 对象内部存放数据的变量，通常是 `private` |
| 属性（property） | 对外的读写入口，外部访问的通常是属性，而不是字段 |
| 构造函数（constructor） | 创建对象时自动执行的代码，负责初始化 |
| 方法（method） | 属于类的函数，能访问这个类的字段和属性 |

### 对象在内存里是什么样

[第 5 章](/chapter/05) 5.10 节讲过，对象放在堆上，变量里存的是它的地址。所以两个变量可以指向同一个对象。

```csharp
var a1 = new P0();           // P0 的定义见 6.3 节第一步
var a2 = a1;                 // 复制的是地址，不是对象本身
a2.Level = "changed";
Console.WriteLine($"a1.Level = {a1.Level}，同一对象：{ReferenceEquals(a1, a2)}");
```

```text
a1.Level = changed，同一对象：True
```

改的是同一个对象，所以 `a1` 也看到了变化。这一点在 6.8 节讲 `class` 与 `record` 的相等比较时还会用到。

### 字段的默认值

字段如果没有赋值，会取类型的默认值。这是 C# 保证的，字段永远不会处于"没有值"的未知状态。

```csharp
public class Defaults
{
    public int Count;
    public bool Done;
    public string? Name;
    public DateTimeOffset At;
}
```

```csharp
var d = new Defaults();
Console.WriteLine($"{d.Count} {d.Done} {d.Name ?? "null"} {d.At:O}");
```

```text
0 False null 0001-01-01T00:00:00.0000000+00:00
```

数字是 `0`，`bool` 是 `false`，引用类型（这里的 `string`）是 `null`，`DateTimeOffset` 是 0001 年 1 月 1 日。`string?` 中的 `?` 表示允许为 `null`，见[第 2 章](/chapter/02)。

### partial 类，一个类写在多处

一个类有时要写在好几个地方。在每个部分前面加上 `partial`，编译器就会把它们合并成一个类。

```csharp
public partial class Parser
{
    public string Name => "parser";
}

public partial class Parser
{
    public int Version => 2;
}
```

两个部分可以放在同一个文件里，也可以放在两个文件里。每一个部分都必须写 `partial`，并且要声明在同一个命名空间里。编译后它们合并成一个 `Parser`，`parser.Name` 和 `parser.Version` 都能用。`partial` 最常见的用途，是让代码生成器在另一个部分里补充代码，而你写的部分保持简短。

### partial 方法，声明和实现可以分开

`partial` 既能用在类上，也能用在方法上。partial 方法分成两步，**声明**（只写签名，结尾是分号）和**实现**（写方法体，可以在同一个类的另一个部分里）。

```csharp
public partial class Greeter
{
    partial void OnStart();         // 声明

    public void Run()
    {
        OnStart();                  // 调用
        Console.WriteLine("Greeter.Run 结束");
    }
}

public partial class Greeter
{
    partial void OnStart() => Console.WriteLine("OnStart 被调用");   // 实现
}
```

```text
OnStart 被调用
Greeter.Run 结束
```

partial 方法有几条规则，看下表即可。

| 情况 | 结果 |
| --- | --- |
| 返回 `void`，没有访问修饰符，也没有实现 | 允许。调用它的那一行会被编译器删除，什么都不做 |
| 返回 `void`，有实现 | 调用时执行实现 |
| 返回值不是 `void` | 必须写访问修饰符，例如 `private partial int Foo();`，并且必须有实现 |

没有实现的 `void` partial 方法，就是一个"可选的回调"，不实现，什么都不发生；实现了，才执行。

实际项目里，最常见的是配合源码生成器使用。`src/LogLens.Core/Analysis/MessageNormalizer.cs` 里的正则就是这样写的。

```csharp
[GeneratedRegex(@"\b0x[0-9a-fA-F]+\b")]
private static partial Regex HexPattern();
```

你只写一个 `partial` 方法的声明，正则的实现由编译器在编译期生成。这要求类是 `partial`，并且方法也是 `partial`。

## 6.3 属性，从最原始的写法到现代简写

属性是**外面看起来像字段、里面可以写代码**的成员。调用方写 `entry.Level`，和读字段的写法一样；但属性背后可以加检查、计算、转换。

下面按时间顺序，把属性从最朴素的写法一路写到现代简写。每一步都解决一个问题，并且会引出下一步。

### 第一步，公开字段，最朴素的写法

```csharp
public class P0
{
    public string Level = "info";
}
```

```csharp
var p0 = new P0();
p0.Level = "随便改";
```

这样能用，但有一个问题，外面可以随便改，你没有机会检查，也没有机会在数据变化时做任何事。以后想加校验，就得把它改成属性，而所有调用它的代码都要跟着改。所以建议一开始就写成属性。

### 第二步，手写属性，字段加 `get` 和 `set`

```csharp
public class P1
{
    private string _level = "info";

    public string Level
    {
        get => _level;
        set => _level = value;
    }
}
```

- `get` 是读取属性时运行的代码，通常直接返回字段。
- `set` 是写入属性时运行的代码，`value` 是调用方传进来的新值。

这时已经能加代码了，想校验，就在 `set` 里写 `if`。但字段 `_level` 仍然要自己声明。如果有十个属性，就要写十个字段和十组 `get`、`set`，大部分代码都是重复的。

### 第三步，自动属性，编译器替你写字段

```csharp
public class P2
{
    public string Level { get; set; } = "info";
}
```

`{ get; set; }` 的意思是，没有特殊逻辑，读写直接存取。编译器会替你生成一个隐藏字段，以及读写它的代码。你在代码里看不见这个字段，但它确实存在。

用反射可以看到它的名字。反射是让程序在运行时查看类型结构的功能，本书后面用得不多，这里只用来观察编译器生成的内容。

```csharp
static void Show(Type t)
{
    var fields = t.GetFields(BindingFlags.Instance | BindingFlags.NonPublic | BindingFlags.Public)
        .Select(f => f.Name);
    Console.WriteLine($"{t.Name} 的字段：{string.Join(", ", fields)}");
}

Show(typeof(P1));
Show(typeof(P2));
```

```text
P1 的字段：_level
P2 的字段：<Level>k__BackingField
```

`P1` 的字段是我们自己写的 `_level`。`P2` 的字段是编译器起的名字，尖括号和 `k__BackingField` 都是编译器的命名规则。这就是"语法糖"的第一个例子，本节后面专门讲。

自动属性自 C# 3 开始可用。

### 第四步，自动属性带初始值

```csharp
public class P2
{
    public string Level { get; set; } = "info";
}
```

`= "info"` 直接给属性一个初始值，对象创建时就是 `"info"`。以前要在构造函数里写 `Level = "info";`，现在一行就能完成。这个写法自 C# 6 开始可用。

### 第五步，只读属性，只能在构造函数里赋值

有些数据创建之后就不应该改，比如日志的级别。可以只写 `get`。

```csharp
public class P3
{
    public P3(string level) => Level = level;

    public string Level { get; }
}
```

`{ get; }` 没有 `set`，外面不能赋值。但在构造函数里仍然可以赋值，这是唯一能写入它的地方。

如果只想让外面不能改，但类内部的其他方法能改，可以写成 `{ get; private set; }`。

```csharp
public class PrivateSetDemo
{
    public string Level { get; private set; } = "info";

    public void Bump() => Level = "warn";
}
```

### 第六步，`init`，只能在创建时赋值

`init` 介于"随便改"和"完全只读"之间，创建对象时可以通过对象初始化器赋值，之后不能再改。

```csharp
public class P4
{
    public required string Level { get; init; }
}
```

```csharp
var p4 = new P4 { Level = "debug" };
// p4.Level = "error";     // 编译错误 CS8852：创建之后不能再赋值
```

`init` 在 C# 9 引入，适合"创建时确定、之后不变"的数据，比如日志的内容和 ID。项目里的 `LogEntry` 和 `AnalysisReport` 都用它。注意，`init` 能防止对象在别处被意外修改，但它和线程安全是两回事。

### 第七步，`required`，强制创建时必须赋值

`required` 在 C# 11 引入，要求创建对象时必须给这个属性赋值，漏了就编译失败。

```csharp
var bad = new P4 { };                 // 编译错误 CS9035：Level 必须设置
```

在 `required` 出现之前，漏写的属性只能在运行时发现，甚至悄悄变成 `null`。能在编译期发现的错误，就不要留到运行时。

### 第八步，计算属性，每次访问时现算

有些属性不存储数据，它的值由别的属性推导出来。这时可以用 `=>`。

```csharp
public class P5
{
    public required string Level { get; init; }

    public bool IsError => Level == "error";
}
```

`IsError` 没有对应的字段，每次读取时都会重新计算一次。它永远和 `Level` 保持一致，不会出现"两个属性不同步"的情况。`=>` 这种写法叫**表达式体成员**，C# 6 开始可用。

### 第九步，`field` 关键字，省掉手写的幕后字段

第二步中，手写属性需要自己声明字段。C# 14 引入的 `field` 关键字可以直接指代编译器生成的幕后字段，既保留检查逻辑，又不用写 `_limit`。

```csharp
public class NewLimit
{
    public int Limit
    {
        get => field;
        set
        {
            if (value <= 0)
            {
                throw new ArgumentOutOfRangeException(nameof(value), "上限必须大于 0");
            }

            field = value;
        }
    } = 20;
}
```

`= 20` 给这个属性一个初始值。这个写法与第二步的 `OldLimit` 行为完全一致。

```csharp
var neu = new NewLimit();
try { neu.Limit = 0; } catch (ArgumentOutOfRangeException) { Console.WriteLine("NewLimit 拒绝 0"); }
Console.WriteLine($"NewLimit = {neu.Limit}");
```

```text
NewLimit 拒绝 0
NewLimit = 20
```

`field` 在 .NET 10 默认的 C# 版本中可用。它是这一串简化里最新的一个。

### 属性写法的演变

| 步骤 | 写法 | 版本 | 解决的问题 |
| --- | --- | --- | --- |
| 1 | `public string Level;` | 最早就有 | 数据能存下来，但外面能随便改 |
| 2 | 手写 `get` 和 `set`，加 `_level` 字段 | 最早就有 | 可以加检查，但要自己写字段和重复代码 |
| 3 | `get => _level;` 表达式体访问器 | C# 7 | 把只有一行的 `get`、`set` 写得更短 |
| 4 | `{ get; set; }` 自动属性 | C# 3 | 不需要字段，编译器替你生成 |
| 5 | `{ get; set; } = "info";` 初始值 | C# 6 | 不必在构造函数里赋初值 |
| 6 | `{ get; }` 只读，构造函数里赋值 | C# 6 | 创建后不能被外面修改 |
| 7 | `{ get; init; }` | C# 9 | 允许创建时赋值，之后只读 |
| 8 | `required` | C# 11 | 漏了赋值，编译失败 |
| 9 | `=>` 计算属性 | C# 6 | 由别的数据推导，不重复存储 |
| 10 | `field` 关键字 | C# 14 | 保留校验逻辑，同时省掉幕后字段 |

这十步的写法都还能用。遇到老代码，认得出每种写法就够了；写新代码时，选最短、又能表达意图的那一种。

### 语法糖，写法变短，做的事没变

上表的第 4 步、第 9 步有一个共同点，**写的代码变少了，但程序做的事情没有变。** 这就是**语法糖**（syntactic sugar），编译器把简短的写法展开成原本的样子，展开前后的行为一致。

第 4 步的 `P2` 大致相当于第 2 步的 `P1`。

```csharp
// 你写的
public string Level { get; set; } = "info";

// 编译器大致展开成的样子（编译器起的字段名你写不出来，这里用 _levelBackingField 代替）
private string _levelBackingField = "info";
public string Level
{
    get => _levelBackingField;
    set => _levelBackingField = value;
}
```

前面的反射输出已经看到了，`P2` 确实多了一个隐藏字段。

日常写 C# 时经常碰到的语法糖，还有下面这些。

| 写法 | 大致展开成 |
| --- | --- |
| `foreach (var x in list)` | 调用 `GetEnumerator()`，然后用 `MoveNext()` 循环取值 |
| `using var w = new LogWriter(...);` | `try` 块加 `finally` 里调用 `Dispose()` |
| `$"{level} {ms} ms"` | 拼接字符串，并把值格式化成文本 |
| `order?.Module` | 先判断 `order` 是否为 `null`，不为 `null` 才取 `Module` |
| 表达式体 `=> x * 2` | 普通的方法体，`return x * 2;` |
| `record` 一行声明 | 构造函数、只读属性、`Equals`、`ToString` 等一整套代码，见 [6.8 节](#s6-8) |

这些展开都是为了让常见写法更短，不改变语义。

`required` 和 `init` 不完全是语法糖。它们在编译时会做检查，漏写或者创建后赋值会直接报错。

读懂语法糖的方法很简单，问自己"写成没有糖的样子是什么"。如果想确认编译器到底生成了什么，可以用反编译工具（比如 ILSpy）打开编译后的程序集，或者像上面那样用反射查看。

## 6.4 构造函数，创建对象时做初始化

```csharp
public class Duration
{
    // 构造函数：名字和类名一样，没有返回类型
    public Duration(int milliseconds)
    {
        if (milliseconds < 0)
        {
            throw new ArgumentOutOfRangeException(nameof(milliseconds), "耗时不能是负数");
        }

        Milliseconds = milliseconds;      // 检查通过之后才赋值
    }

    public int Milliseconds { get; }

    public double Seconds => Milliseconds / 1000.0;
}
```

```csharp
var d = new Duration(1520);
Console.WriteLine(d.Seconds);            // 1.52

var bad = new Duration(-1);              // 立即抛出异常，不会得到一个非法的对象
```

构造函数最重要的作用，在于保证对象一出生就是合法的，赋值只是手段。

### `new` 到底做了什么

`new Duration(1520)` 这一行，实际上按顺序完成四件事。

1. 在堆上分配一块内存，用来放这个对象的字段。
2. 所有字段先取默认值，数字为 `0`，引用为 `null`。
3. 执行字段初始化器，比如 `= "info"`。
4. 执行构造函数的函数体。

第 3 步早于第 4 步，下面的代码展示了这个顺序。

```csharp
public class OrderDemo
{
    public string Log { get; } = Trace("字段初始化器");

    public OrderDemo()
    {
        Log += " -> 构造函数体";
    }

    private static string Trace(string text) => text;
}
```

```csharp
var order = new OrderDemo();
Console.WriteLine(order.Log);
```

```text
字段初始化器 -> 构造函数体
```

### 默认构造函数，以及它什么时候消失

如果你一个构造函数都没写，编译器会提供一个没有参数的构造函数。但只要你写了任何一个构造函数，编译器就不再提供默认的那个。

```csharp
public class E2
{
    public E2(int x) => X = x;

    public int X { get; }
}

var e2 = new E2();      // 编译错误 CS7036：缺少与参数 x 对应的实参
```

这条规则常让人困惑，明明没有删代码，`new E2()` 却突然不能用了。原因就是你写了带参数的构造函数，编译器就不再替你准备无参的版本。

### 主构造函数（C# 12 起）

如果构造函数只是把参数存起来，可以写得更短。

```csharp
public class Duration(int milliseconds)
{
    public int Milliseconds { get; } = milliseconds;
    public double Seconds => Milliseconds / 1000.0;
}
```

参数 `milliseconds` 写在类名后面，可以直接在类里使用，编译器会在需要时自动保存它。这种写法适合参数只用于初始化的情况。如果构造函数里有校验逻辑，还是用普通写法更清楚。

### 构造函数重载与 `this(...)`

同一个类可以有多个构造函数，只要参数不同，规则就和方法重载一样。一个构造函数可以用 `this(...)` 把工作交给另一个构造函数，避免重复写初始化代码。

```csharp
public class LogQueryOptions
{
    public LogQueryOptions(string level) : this(level, limit: 20)
    {
    }

    public LogQueryOptions(string level, int limit)
    {
        Level = level;
        Limit = limit;
    }

    public string Level { get; }

    public int Limit { get; }
}
```

```csharp
var q1 = new LogQueryOptions("info");
var q2 = new LogQueryOptions("error", 50);
Console.WriteLine($"q1 = {q1.Level}/{q1.Limit}，q2 = {q2.Level}/{q2.Limit}");
```

```text
q1 = info/20，q2 = error/50
```

`LogQueryOptions("info")` 先调用 `this(level, limit: 20)`，由带两个参数的版本完成初始化。两个构造函数的初始化逻辑只写了一份。

### 对象初始化器

```csharp
var entry = new LogEntry
{
    Level = "error",
    Message = "连接超时",
    DurationMs = 1520,
};
```

这种写法叫**对象初始化器**。它先调用构造函数，再按花括号里的内容给属性赋值。它只能给属性赋值，不能传参数。所以，如果某个值必须有、并且要经过计算，用构造函数参数更明确；如果只是可选的配置项，用对象初始化器更自然。

### 静态构造函数（了解）

加了 `static` 的构造函数，会在类第一次被使用之前执行一次。它没有参数，也不能手动调用。

```csharp
public class Clock
{
    public static readonly DateTimeOffset StartedAt;

    static Clock()
    {
        StartedAt = DateTimeOffset.Now;
        Console.WriteLine("静态构造函数执行");
    }

    public Clock()
    {
        Console.WriteLine("实例构造函数执行");
    }
}
```

```csharp
Console.WriteLine("main 开始");
_ = new Clock();
_ = new Clock();
```

```text
main 开始
静态构造函数执行
实例构造函数执行
实例构造函数执行
```

静态构造函数只执行一次，适合为整个类准备一份共用的数据。它和 6.5 节的静态字段配合使用。

### 对象用完之后的收尾，IDisposable

有些对象占用的是外部资源，比如文件、网络连接。这些资源用完后要及时释放，否则文件会一直被占用。

做法是让类实现 `IDisposable` 接口，在 `Dispose` 方法里释放资源。`using` 会保证离开作用域时调用 `Dispose`。

```csharp
public sealed class LogWriter2 : IDisposable
{
    public LogWriter2(string name)
    {
        Name = name;
        Console.WriteLine($"打开 {name}");
    }

    public string Name { get; }

    public void Write(string text) => Console.WriteLine($"  写入 {text}");

    public void Dispose() => Console.WriteLine($"关闭 {Name}");
}
```

```csharp
using (var w = new LogWriter2("b.log"))
{
    w.Write("x");
}
```

```text
打开 b.log
  写入 x
关闭 b.log
```

`using (...) { }` 是语句块形式，花括号结束时调用 `Dispose`。`using var w = ...;` 是声明形式，它在所在的代码块结束时调用 `Dispose`，写法更短，但释放的时机取决于代码块的边界。两种写法都会调用 `Dispose`。

有两点要记住。

- **不要指望垃圾回收器来关闭文件。** 垃圾回收器决定回收对象的时机，你无法控制，文件可能过很久才被关闭。显式调用 `Dispose`（用 `using`）才是可靠的做法。
- 类的析构函数（写作 `~LogWriter2()`）也由垃圾回收器调用，时机不确定，所以不用它来释放文件。

项目里的 `src/LogLens.Cli/Ui/Spinner.cs` 也实现了 `IDisposable`，它的 `Dispose` 会释放内部的 `CancellationTokenSource`。

## 6.5 `static`，属于类，不属于对象

普通的字段和方法属于对象，每个对象各有一份。加上 `static` 后，成员属于类本身，所有对象共用一份，也不需要创建对象就能访问。

| | 实例成员（不带 `static`） | 静态成员（带 `static`） |
| --- | --- | --- |
| 属于谁 | 每个对象各有一份 | 整个类共用一份 |
| 怎么访问 | `obj.Member` | `ClassName.Member` |
| 能访问什么 | 实例成员和静态成员 | 只能访问静态成员 |
| 例子 | `entry.IsSlow` | `Math.Round(x)`、`File.Exists(path)` |

### 静态字段，所有对象共享

```csharp
public class RequestCounter
{
    private static int _total;
    private int _mine;

    public RequestCounter()
    {
        _total++;
        _mine++;
    }

    public static int Total => _total;

    public int Mine => _mine;
}
```

```csharp
var rc1 = new RequestCounter();
var rc2 = new RequestCounter();
Console.WriteLine($"总数 {RequestCounter.Total}，rc1 {rc1.Mine}，rc2 {rc2.Mine}");
```

```text
总数 2，rc1 1，rc2 1
```

`_total` 是静态的，两次 `new` 都加在同一个数字上，所以总数是 2。`_mine` 每个对象各有一份，所以两个对象都是 1。

静态字段是全局共享的状态，用得太多会让程序难以理解，任何地方都可以修改它，你很难知道是哪一行改的。尽量只在确实需要全局共享的时候使用，比如计数器、缓存、配置。

### 静态方法不能访问实例成员

静态方法没有 `this`，不属于任何一个对象，所以它不能直接访问实例字段。

```csharp
class E1
{
    private int _x;
    public static int Get() => _x;      // 编译错误 CS0120：静态方法不能访问实例字段
}
```

要访问实例成员，就需要一个对象，并且通过对象来访问。

### 静态类

如果一个类里全部都是静态成员，可以把整个类声明为 `static class`。它不能被实例化。

```csharp
public static class TextTools
{
    public static string Shout(string s) => s.ToUpperInvariant() + "!";
}
```

```csharp
Console.WriteLine(TextTools.Shout("ok"));
// var tt = new TextTools();      // 编译错误 CS0712：不能创建静态类的实例
```

```text
OK!
```

`Math`、`Path`、`File` 都是静态类。它们只是一组相关的函数，没有需要记住的状态。

### `const` 与 `static readonly`

```csharp
public const int MaxRows = 20000;                                       // 编译期就确定
public static readonly DateTimeOffset StartedAt = DateTimeOffset.Now;   // 程序运行时确定一次
```

- `const` 的值永远不变，并且能在编译期算出来，比如数字、字符串、`bool`。它隐式就是静态的，不需要写 `static`。
- `static readonly` 只需要初始化一次，但值要到运行时才能确定，比如当前时间，或者读取配置的结果。

## 6.6 访问修饰符，决定谁能看见我

访问修饰符规定成员能被谁访问。C# 一共有六种。

```csharp
public class Protections
{
    private int A1;                     // 只有本类能访问
    protected int A2;                   // 本类和子类能访问
    internal int A3;                    // 同一个程序集（同一个项目）里能访问
    protected internal int A4;          // 子类，或者同一个程序集里能访问
    private protected int A5;           // 同一个程序集里的子类能访问
    public int A6;                      // 任何地方都能访问
}
```

| 修饰符 | 可见范围 | 什么时候用 |
| --- | --- | --- |
| `private` | 只有本类 | 内部实现细节，优先用它 |
| `protected` | 本类和子类 | 留给继承使用，[第 7 章](/chapter/07)讲 |
| `internal` | 同一个程序集（项目） | 项目内部共享，不对外公开 |
| `protected internal` | 子类，或同一程序集 | 两种范围取并集 |
| `private protected` | 同一程序集里的子类 | 两种范围取交集 |
| `public` | 任何地方 | 有意提供给外部的接口 |

这里有两个默认值。

- **类的成员默认是 `private`。** 你不写修饰符，它就是 `private`。
- **顶层类型默认是 `internal`。** 你写一个不带修饰符的 `class`，它只在本项目里可见。

原则是，默认 `private`，能不公开就不公开。公开的东西越多，以后改代码时越容易影响别人。

```csharp
public class LogEntry
{
    private int _retryCount;             // 只有本类能访问
    public string Level { get; set; }    // 任何地方都能访问
}
```

```csharp
Console.WriteLine(entry._retryCount);    // ❌ CS0122: 不可访问，因为它具有一定的保护级别
```

这个编译错误正是在保护内部实现，这也是 `private` 的用途。

还有一个常见的修饰符 `sealed`，表示这个类不能再被继承，[第 7 章](/chapter/07)讲继承时会用到。项目里 `LogLens.Core` 的公开类型基本都是 `sealed`。

### 嵌套类，只给外面的类用

类可以写在另一个类的内部，叫**嵌套类**。它常用来表示"只在这个类内部才有意义的东西"。

```csharp
public class LogReport
{
    private static int _createdRows;   // 私有静态字段，嵌套类也能访问

    private readonly List<Row> _rows = new();

    public enum Mode
    {
        Summary,
        Full,
    }

    public void Add(string level) => _rows.Add(new Row(level));

    public string Summary() => string.Join(", ", _rows.Select(r => r.Level));

    public static int CreatedRows => _createdRows;

    private sealed class Row
    {
        public Row(string level)
        {
            Level = level;
            _createdRows++;            // 嵌套类可以访问外层的私有静态成员
        }

        public string Level { get; }
    }
}
```

```csharp
var report = new LogReport();
report.Add("error");
report.Add("warn");
report.Add("error");
Console.WriteLine(report.Summary());
Console.WriteLine($"模式：{LogReport.Mode.Full}，创建过的 Row 数：{LogReport.CreatedRows}");
```

```text
error, warn, error
模式：Full，创建过的 Row 数：3
```

几点说明。

- `Row` 是 `private`，外面的代码无法创建它，也无法拿到它的类型。`new LogReport.Row("x")` 会报 CS0122。
- `Row` 里面可以访问 `LogReport` 的私有成员，这是嵌套类的特点。反过来，`LogReport` 也可以访问 `Row` 的私有成员。
- 外面写的是 `LogReport.Mode.Full`，嵌套的名字要带上外层的类名。
- 嵌套的层数不要太深。一两层能让代码更紧凑，层层嵌套就很难读。

项目里有两处真实的嵌套类。`src/LogLens.Core/Analysis/LogAnalyzer.cs` 第 202 行的 `ClusterAccumulator`，是分析过程中的临时累加器，只给 `LogAnalyzer` 自己用。`src/LogLens.Core/Reporting/JsonReportWriter.cs` 第 97 行开始的一组 `ReportDto`，是输出 JSON 时用的数据结构，同样是 `private`，外面看不到。两处的目的都一样，内部细节不暴露给外面。

## 6.7 命名空间，把类分门别类

每个类都有一个全名，包括它所在的**命名空间**。比如 `LogLens.Core.Models.LogEntry`，前面的 `LogLens.Core.Models` 就是命名空间。

命名空间解决两个问题。

- **避免重名**，你写的 `LogEntry` 和别人库里的 `LogEntry` 可以共存，因为它们的全名不同。
- **表达归属**，看到 `LogLens.Core.Parsing`，就知道这是解析相关的代码。

### 写法

文件开头可以用**文件级命名空间**，整个文件都在这个命名空间里，不用多一层花括号。

```csharp
namespace LogLens.Tutorial.Ch06.Demo;

public class Entry
{
    public string Message { get; init; } = string.Empty;
}
```

其他文件要使用它，有三种方式。

```csharp
// 方式一：写全名
var e1 = new LogLens.Tutorial.Ch06.Demo.Entry();

// 方式二：引入命名空间，之后可以直接写类名
using LogLens.Tutorial.Ch06.Demo;
var e2 = new Entry();

// 方式三：给全名起一个别名
using Log = LogLens.Tutorial.Ch06.Demo.Entry;
var e3 = new Log();
```

如果忘了引入命名空间，编译器会报 CS0246，找不到类型或命名空间。

### `using static`，直接使用静态成员

`using static` 可以把一个静态类的成员直接引入，不用每次写类名。

```csharp
using static System.Math;

Console.WriteLine($"Max = {Max(3, 7)}，Sqrt = {Sqrt(16)}");
```

```text
Max = 7，Sqrt = 4
```

这种写法适合大量使用某个静态类的情况，比如数学计算。如果只用了一两次，直接写 `Math.Max` 更清楚，读的人一眼就知道 `Max` 从哪里来。

### `global using`，全项目可见

`global using` 把一个命名空间设为整个项目都可见，一般写在一个单独的文件里。

```csharp
// GlobalUsings.cs
global using LogLens.Tutorial.Ch06.Demo;
```

这样项目里所有文件都不用再写这一行。新建的 .NET 项目默认开启 `ImplicitUsings`，所以 `System`、`System.Linq`、`System.Collections.Generic` 这些常用命名空间已经自动可用，不用自己写。

### 项目中的命名空间

LogLens 的命名空间大体按层次划分，这些名字在后续章节都会用到。

- `LogLens.Core.Parsing`，解析日志
- `LogLens.Core.Analysis`，分析日志
- `LogLens.Core.Query`，查询语言
- `LogLens.Studio.ViewModels`，界面逻辑

## 6.8 `record`，为数据而生的类

先看普通的 `class`。它判断两个对象是否"相等"，比较的是"是不是同一个对象"。

```csharp
public class Note
{
    public required string Level { get; init; }
    public required string Message { get; init; }
}
```

```csharp
var a = new Note { Level = "error", Message = "超时" };
var b = new Note { Level = "error", Message = "超时" };
Console.WriteLine(a == b);          // False，两个不同的对象
```

```text
False
```

两个对象的内容完全相同，但 `==` 的结果仍然是 `False`。这对于"一个东西"的情况是对的，比如一个文件句柄，两个句柄就是两个不同的东西。但对于"一份数据"，比如一条日志的摘要，人们通常期望"内容一样就算相等"。

这时候用 `record`。

```csharp
public record LogSummary(string Level, string Module, int DurationMs);
```

```csharp
var x = new LogSummary("error", "order", 1520);
var y = new LogSummary("error", "order", 1520);

Console.WriteLine(x == y);          // True，内容相等
Console.WriteLine(x);               // LogSummary { Level = error, Module = order, DurationMs = 1520 }
```

```text
True
LogSummary { Level = error, Module = order, DurationMs = 1520 }
```

这一行声明，编译器替你生成了很多代码。

- 一个构造函数，参数就是括号里的三个值。
- 三个只读属性，`Level`、`Module`、`DurationMs`，都是 `{ get; init; }`。
- 按内容比较的 `Equals` 和 `==`。
- 可读的 `ToString()`，输出结果就是上面那行。
- 解构方法 `Deconstruct`，见下文。

用反射可以列出编译器生成的方法（去掉了属性的访问器）。

```csharp
var names = typeof(LogSummary)
    .GetMethods(BindingFlags.Public | BindingFlags.NonPublic | BindingFlags.Instance | BindingFlags.Static | BindingFlags.DeclaredOnly)
    .Select(m => m.Name)
    .Where(n => !n.StartsWith("get_") && !n.StartsWith("set_"))
    .OrderBy(n => n);
Console.WriteLine(string.Join(", ", names));
```

```text
<Clone>$, Deconstruct, Equals, Equals, GetHashCode, op_Equality, op_Inequality, PrintMembers, ToString
```

`Equals` 出现两次，是因为一个接受 `object`，一个接受同类型的参数。`op_Equality` 和 `op_Inequality` 是 `==` 和 `!=` 背后的方法。`<Clone>$` 是 `with` 用来复制对象的方法，下面就讲它。`PrintMembers` 是 `ToString` 用来拼接文本的方法。这就是语法糖的一个完整例子，你写一行，编译器展开成一整套代码。

### `with`，基于旧对象创建新对象

`record` 的属性是只读的，所以不能直接修改它。想要"和旧对象一样，只改其中一两个值"，用 `with`。

```csharp
var slow = y with { DurationMs = 3000 };
Console.WriteLine($"{slow.DurationMs} {y.DurationMs}");
```

```text
3000 1520
```

`with` 复制出一个新对象，只改指定的属性，原对象 `y` 保持不变。分析结果需要换一组参数重新计算时，这种写法很顺手。项目里 `src/LogLens.Studio/Services/WorkspaceService.cs` 第 131 行就用 `with` 生成了新的快照。

### 解构，一次取出多个值

```csharp
var (level, module, ms) = x;
Console.WriteLine($"{level}/{module}/{ms}");
```

```text
error/order/1520
```

`record` 按声明的顺序提供 `Deconstruct`，所以可以用 `var (...) = ...` 一次取出所有值。普通的 `class` 默认没有这个能力，需要自己写 `Deconstruct` 方法。

### `record` 的一个陷阱，集合属性按引用比较

`record` 按每个属性比较相等。如果属性本身是一个集合，比较的仍然是集合的引用，而不是集合里的内容。

```csharp
public record Batch(List<string> Lines);
```

```csharp
var b1 = new Batch(new List<string> { "a" });
var b2 = new Batch(new List<string> { "a" });
Console.WriteLine($"Batch ==：{b1 == b2}，内容相同：{b1.Lines.SequenceEqual(b2.Lines)}");
```

```text
Batch ==：False，内容相同：True
```

两个 `Batch` 的 `Lines` 是两个不同的 `List`，所以 `==` 为 `False`。要比较内容，要用 `SequenceEqual`，它逐个比较集合里的元素。这和[第 5 章](/chapter/05) 5.12 节"`==` 与 `Equals`"讲的是同一个问题。写 `record` 时，如果有集合属性，要记得这个陷阱。

### 匿名类型，临时打包一组数据

有时只需要临时把几个值打包在一起，不值得为它定义一个具名类型。这时可以用**匿名类型**。

```csharp
var a = new { Level = "error", Ms = 1520 };
var b = new { Level = "error", Ms = 1520 };
var c = new { Level = "warn", Ms = 1520 };

Console.WriteLine(a);
Console.WriteLine($"Equals：{a.Equals(b)}，==：{a == b}，同一类型：{a.GetType() == b.GetType()}，换了值仍同类型：{a.GetType() == c.GetType()}");
```

```text
{ Level = error, Ms = 1520 }
Equals：True，==：False，同一类型：True，换了值仍同类型：True
```

匿名类型有几个特点。

- 类型名由编译器自动生成，你不用写。`var` 接收它。
- 属性是只读的，`a.Level = "warn";` 会报 CS0200。
- `Equals` 按内容比较，所以 `a.Equals(b)` 为 `True`。但 `==` 没有重载，比较的是引用，所以 `a == b` 为 `False`。这一点和 `class` 一样。
- 属性名和类型完全相同、顺序也相同的两个匿名类型，编译器认为它们是同一个类型。属性名、类型或顺序不同，就是另一个类型。
- 匿名类型也支持 `with`，会得到一个新的匿名对象。
- 不能在方法的参数或返回类型里写出它的名字。要把它传出方法，只能转成 `object`，或者定义一个具名的 `record`。

匿名类型最常见的用途，是在 LINQ 查询里对数据做投影，把需要的字段挑出来、顺便算一个新值。

```csharp
var projected = new[]
    {
        new { Level = "error", Module = "order" },
        new { Level = "info", Module = "api" },
    }
    .Select(item => new { item.Level, Upper = item.Module.ToUpperInvariant() })
    .ToList();

foreach (var item in projected)
{
    Console.WriteLine($"{item.Level} {item.Upper}");
}
```

```text
error ORDER
info API
```

`Select` 和 `ToList` 会在[第 10 章](/chapter/10)系统讲，这里只需要知道，`new { ... }` 在 `Select` 里生成了一个新的匿名对象，`item.Level` 和 `item.Upper` 直接可用。

项目里目前没有匿名类型的用例，因为项目的数据都有明确的名字，用 `record` 更清楚。匿名类型适合临时的、只在一个方法里用的中间数据。

### class 还是 record？

判断时只问一句，这个类型代表"一个东西"，还是"一份数据"？

- **选 `class`**，它有行为，有身份（两个对象即使内容一样，也代表不同的东西），并且状态会随时间变化。比如 `LogAnalyzer`、`WorkspaceService`。
- **选 `record`**，它主要用来承载数据，内容相同就视为相等，创建后不变，并且经常需要复制修改。比如 `LogEntry`、`AnalysisReport`。

项目里的 `LogEntry`、`AnalysisReport`、`WorkspaceSnapshot` 都是 `sealed record`，它们是数据。`LogAnalyzer` 和 `LogParserFactory` 是 `sealed class`，它们有行为。

### 手写 Equals 与 GetHashCode（了解）

有时候 `class` 也需要按内容比较，但不想改成 `record`。这时要手写 `Equals` 和 `GetHashCode`，并且两者必须一致，内容相等的两个对象，哈希码也必须相等。

```csharp
public class Tag
{
    public Tag(string name) => Name = name;

    public string Name { get; }

    public override bool Equals(object? obj) => obj is Tag other && other.Name == Name;

    public override int GetHashCode() => Name.GetHashCode();
}
```

```csharp
var tagA = new Tag("api");
var tagB = new Tag("api");

Console.WriteLine($"Equals: {tagA.Equals(tagB)}");
Console.WriteLine($"==: {tagA == tagB}");

var set = new HashSet<Tag> { tagA };
Console.WriteLine($"HashSet 找得到: {set.Contains(tagB)}");
```

```text
Equals: True
==: False
HashSet 找得到: True
```

`HashSet<T>` 先用哈希码找到大致的位置，再用 `Equals` 比较。如果哈希码不一致，内容相同的对象也找不到。`==` 仍然比较引用，改它需要重载运算符，这里不展开。`record` 已经替你写好了这些，所以一般不需要手写。

## 6.9 `struct`，轻量的值类型

`struct` 和 `class` 的区别在于，`struct` 是值类型。[第 5 章](/chapter/05) 5.9 节讲过，两者的差别在于变量里存的是什么。

- `class` 变量存的是地址，赋值只是复制地址，两个变量指向同一个对象；
- `struct` 变量存的是内容本身，赋值会复制整份内容，两个变量各自独立。

```csharp
public struct Point
{
    public int X;
    public int Y;
}
```

```csharp
var pt1 = new Point { X = 1, Y = 2 };
var pt2 = pt1;                          // 复制整份内容
pt2.X = 9;
Console.WriteLine($"pt1.X = {pt1.X}，pt2.X = {pt2.X}");
```

```text
pt1.X = 1，pt2.X = 9
```

修改 `pt2` 不影响 `pt1`。换成 `class`，两个变量就会指向同一个对象，修改会互相影响。

`struct` 的默认值也和 `class` 不同。`default(Point)` 得到的是所有字段都为 `0` 的值，它本身永远不是 `null`。

```csharp
var pd = default(Point);
Console.WriteLine($"默认值：({pd.X}, {pd.Y})");
```

```text
默认值：(0, 0)
```

### `struct` 与 `class` 对照

| | `class` | `struct` |
| --- | --- | --- |
| 变量里存的是 | 地址 | 内容本身 |
| 赋值 | 复制地址，两个变量指向同一个对象 | 复制整份内容，两个变量各自独立 |
| 默认值 | `null` | 所有字段为默认值，不会是 `null` |
| 能不能是 `null` | 能 | 普通的 `struct` 不能，要用 `Nullable<T>` 或 `T?` |
| 适合 | 有身份、较大、会被多处共享的对象 | 小而简单、按值使用的数据 |

### 只读与 `record struct`

`struct` 的字段可以被修改，这会带来一些麻烦。`readonly struct` 规定创建之后不能修改，`readonly record struct` 在此基础上，还自动有内容相等、`ToString` 和 `with`。项目里的 `TimeRange` 就是这样写的。

```csharp
public readonly record struct TimeRange2(DateTimeOffset Start, DateTimeOffset End);
```

```csharp
var range = new TimeRange2(DateTimeOffset.UnixEpoch, DateTimeOffset.UnixEpoch.AddHours(1));
Console.WriteLine(range.End - range.Start);
```

```text
01:00:00
```

### 可变 `struct` 的坑

如果 `struct` 的字段可以修改，它在集合里会出现一个很容易踩的坑。

```csharp
var list = new List<Point> { new Point { X = 1 } };
list[0].X = 5;                  // 编译错误 CS1612：不能修改返回值
```

`list[0]` 取出来的是一份副本，修改副本没有意义，所以编译器拒绝这样写。要修改，应该先取出来、改好、再放回去，或者把 `struct` 改成不可变的。

### 什么时候用 `struct`

.NET 的设计指南建议，只有同时满足下面几条，才考虑用 `struct`。

- 数据很小，通常不超过 16 字节，比如坐标、时间段、大小；
- 创建之后不需要修改，也就是 `readonly`；
- 不需要"身份"，两个值相等就可以互相替换。

不满足时，用 `class` 或 `record`。新手默认用 `class` 或 `record` 就够了。

## 6.10 动手写一个完整的 `LogEntry`

下面的程序就是本章的配套代码（`code/ch06-objects/Program.cs`）。它先使用 `LogEntry` 和 `LogSummary`，然后在程序末尾定义它们。

这里的 `LogEntry` 写成 `class`，是为了练习校验和计算属性。项目里的 `LogEntry` 是 `sealed record`，字段更多，但同样使用 `required` 和 `init`，见 [6.13 节](#s6-13)。

```csharp
// ============================================
// 第 6 章 · 类与对象
// 运行方式：dotnet run
// ============================================

var entries = new List<LogEntry>
{
    new()
    {
        Timestamp = DateTimeOffset.Parse("2026-11-01 12:00:00"),
        Level = "INFO",
        Module = "api",
        Message = "GET /orders",
        DurationMs = 45,
    },
    new()
    {
        Timestamp = DateTimeOffset.Parse("2026-11-01 12:00:05"),
        Level = "warn",
        Module = "api",
        Message = "数据库查询较慢",
        DurationMs = 968,
    },
    new()
    {
        Timestamp = DateTimeOffset.Parse("2026-11-01 12:00:09"),
        Level = "error",
        Module = "order",
        Message = "处理订单失败",
        DurationMs = 1520,
    },
};

// 1) 对象自带的行为：判定规则只写一次（在 IsSlow 里）
foreach (var entry in entries.OrderByDescending(entry => entry.DurationMs))
{
    var slowTag = entry.IsSlow ? "  ← 慢" : string.Empty;
    Console.WriteLine(
        $"{entry.Timestamp:yyyy-MM-dd HH:mm:ss} {entry.LevelTag} {entry.Module,-6}{entry.Message}  ({entry.DurationMs} ms){slowTag}");
}

// 2) 统计：还是第 4 章的 LINQ，只是现在操作的是对象
Console.WriteLine();
var byLevel = entries
    .GroupBy(entry => entry.Level, StringComparer.OrdinalIgnoreCase)
    .Select(group => $"{group.Key.ToUpperInvariant()} {group.Count()}");
Console.WriteLine($"级别分布：{string.Join(" · ", byLevel)}");

// 3) record 的值相等：内容一样就算相等
var recordA = new LogSummary("error", "order", 1520);
var recordB = new LogSummary("error", "order", 1520);
Console.WriteLine($"是否等同（值语义）：{recordA == recordB}");

// 4) with：基于旧对象派生新对象，原对象不变
var shorter = recordA with { DurationMs = 300 };
Console.WriteLine($"with 之后：{shorter}（原对象仍是 {recordA.DurationMs} ms）");

// 5) 非法的耗时会被挡住：init 里就校验，坏对象活不下来
try
{
    _ = new LogEntry
    {
        Timestamp = DateTimeOffset.Now,
        Level = "error",
        Module = "order",
        Message = "负耗时",
        DurationMs = -5,
    };
}
catch (ArgumentOutOfRangeException ex)
{
    Console.WriteLine($"构造失败（符合预期）：{ex.Message.Split('(')[0].Trim()}");
}

// ---------- 下面开始定义类型 ----------

/// <summary>
/// 一条解析后的日志。
/// 用 class 而不是 record：它有校验、有行为（IsSlow/LevelTag），并且创建后不应被随意修改。
/// </summary>
public class LogEntry
{
    private string _level = "info";

    /// <summary>时间。init 表示"只能创建时赋值"。</summary>
    public required DateTimeOffset Timestamp { get; init; }

    /// <summary>级别。在 init 里统一规范化，所以 "INFO"/" error " 都会被存成小写。</summary>
    public required string Level
    {
        get => _level;
        init => _level = Normalize(value);
    }

    /// <summary>模块名（谁打的这条日志）。</summary>
    public required string Module { get; init; }

    /// <summary>消息正文。</summary>
    public required string Message { get; init; }

    /// <summary>耗时（毫秒）。负数在这里就被挡住（C# 14 的 field 关键字）。</summary>
    public int DurationMs
    {
        get;
        init => field = value < 0
            ? throw new ArgumentOutOfRangeException(nameof(value), "耗时不能是负数")
            : value;
    }

    // ---- 计算属性：由上面几个值推导，不额外占内存 ----

    /// <summary>是否算"慢请求"（判定规则只写这一处）。</summary>
    public bool IsSlow => DurationMs > 1000;

    /// <summary>级别的大写标签，补齐 5 位便于对齐显示。</summary>
    public string LevelTag => Level.ToUpperInvariant().PadRight(5);

    /// <summary>是否是问题日志（warn 及以上）。</summary>
    public bool IsProblem => Level is "warn" or "error" or "critical";

    private static string Normalize(string level) =>
        string.IsNullOrWhiteSpace(level) ? "info" : level.Trim().ToLowerInvariant();
}

/// <summary>一份摘要。record 意味着"内容相同即相等"，适合当数据传递。</summary>
public record LogSummary(string Level, string Module, int DurationMs);
```

运行结果如下。

```text

2026-11-01 12:00:05 WARN  api   数据库查询较慢  (968 ms)
2026-11-01 12:00:00 INFO  api   GET /orders  (45 ms)

级别分布：INFO 1 · WARN 1 · ERROR 1
是否等同（值语义）：True
with 之后：LogSummary { Level = error, Module = order, DurationMs = 300 }（原对象仍是 1520 ms）
构造失败（符合预期）：耗时不能是负数
```

最后两行分别来自 `with` 和异常处理。`with` 没有改动原对象，非法耗时在创建时就被挡住了。

### 逐段解释

| 代码 | 说明 |
| --- | --- |
| `new() { ... }` | 目标类型 `new`，省略类型名，直接写对象初始化器 |
| `required` | 少写一个必填项就编译失败 |
| `init` | 只能在创建时赋值，之后只读 |
| `private string _level` 加 `init => _level = Normalize(value)` | 写入时统一规范化，`INFO`、` error ` 都会被存成小写 |
| `field`（C# 14） | 在属性访问器里直接使用编译器生成的幕后字段，不用手写字段名 |
| `init => field = ...` 中的校验 | 负耗时在创建时就被挡住，不会产生非法对象 |
| `=>` 计算属性 | `IsSlow`、`LevelTag`、`IsProblem` 每次访问时现算，不额外保存 |
| `record LogSummary(...)` | 一行定义构造函数、只读属性、值相等和 `ToString` |

`field` 关键字是 C# 14 的新写法。项目里 `src/LogLens.Studio/Models/StudioSettings.cs` 的 `MaxRows` 就用它限制取值范围。

```csharp
public int MaxRows
{
    get => field;
    set => field = Math.Clamp(value, 100, 1_000_000);
} = 20000;
```

以前要手写一个 `_maxRows` 字段，现在可以省掉。

## 6.11 常见错误

| 报错 | 原因 | 怎么改 |
| --- | --- | --- |
| `CS0246` 找不到类型或命名空间 | 忘了 `using`，或者类名拼错 | 加上 `using` 语句，检查大小写 |
| `CS0122` 不可访问，具有一定的保护级别 | 访问了 `private` 成员或私有嵌套类 | 改用公开的属性或方法；改可见性前先想清楚 |
| `CS7036` 缺少与所需参数对应的实参 | 调用构造函数时没有传参数，或者类里只有带参数的构造函数 | 补上参数，或者补一个无参构造函数 |
| `CS9035` 必须设置必需的成员 | `required` 成员没有在初始化器里赋值 | 在初始化器里补上 |
| `CS8852` `init` 属性只能在创建时赋值 | 对象创建之后又给 `init` 属性赋值 | 把值放进初始化器，或者改用可写属性 |
| `CS0200` 属性只读，不能赋值 | 对只有 `get` 的属性（包括匿名类型的属性）赋值 | 去掉对它的赋值，或者给属性加上 `set` |
| `CS0120` 需要对象引用才能访问非静态成员 | 静态方法里访问了实例字段或实例方法 | 把成员改为静态，或者通过对象访问 |
| `CS0712` 不能创建静态类的实例 | 对 `static class` 使用了 `new` | 直接用 `类名.成员` 调用 |
| `CS1612` 不能修改返回值 | 直接修改集合元素里的 `struct` 字段 | 先取出副本修改，再放回去；或改为不可变的 `struct` |
| `CS0117` 类型中不包含此定义 | 名字拼错，或者调用了不存在的成员，比如 `Math.Foo` | 对照文档检查名字 |
| `CS8795` 分部方法必须有实现部分 | 带访问修饰符的 `partial` 方法没有实现 | 补上实现，或者去掉访问修饰符（仅限 `void`） |
| `CS8796` 返回值非 `void` 的分部方法必须有访问修饰符 | `partial int Foo();` 没有写 `private` 等修饰符 | 加上访问修饰符，并提供实现 |
| `CS8803` 顶层语句之后不能再出现类型定义 | 类写在了顶层语句的中间 | 把类型定义移到文件末尾，或放到单独的文件里 |
| `NullReferenceException` | 对值为 `null` 的变量调用成员 | 先判空，或者检查是不是忘了 `new` |
| 两个内容相同的对象 `==` 结果为 `False` | 用的是 `class` | 需要按内容比较时，改用 `record`，或手写 `Equals` |

```text
info: 1
```

**练习 6**

两个版本对 `0` 的处理一致，都会拒绝，并且保留原来的值 `20`。

```csharp
var old = new OldLimit();
var neu = new NewLimit();

try { old.Limit = 0; } catch (ArgumentOutOfRangeException) { Console.WriteLine("OldLimit 拒绝 0"); }
try { neu.Limit = 0; } catch (ArgumentOutOfRangeException) { Console.WriteLine("NewLimit 拒绝 0"); }
Console.WriteLine($"OldLimit = {old.Limit}，NewLimit = {neu.Limit}");
```

```text
OldLimit 拒绝 0
NewLimit 拒绝 0
OldLimit = 20，NewLimit = 20
```

`OldLimit` 就是 6.3 节第二步的写法，手写 `_limit` 字段加校验；`NewLimit` 是第九步的写法，用 `field` 代替字段，其余逻辑相同。
