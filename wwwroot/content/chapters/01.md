**需要准备的东西**

- [第 0 章](/chapter/00)装好的 .NET 10 SDK。运行 `dotnet --version`，看到以 `10.` 开头的版本号就可以。
- 一个终端。Windows 可以用 Windows Terminal 或命令提示符（cmd），macOS 用“终端”，Linux 用你习惯的 shell。
- 一个能编辑纯文本的编辑器。VS Code 就够用，[第 0 章](/chapter/00)已经装过。

- 一次报出十几条错，不知道先看哪一条。1.12 节会教你从第一条读起。
- 双击运行时窗口一闪而过。程序结束时窗口随之关闭，所以本章统一在终端里运行。

## 1.1 终端，用文字和电脑说话

图形界面靠点按钮做事，终端靠一行一行的命令做事。终端本身只是一个窗口，里面运行着一个叫 shell 的程序。你敲进去的命令交给它，它读懂之后去执行，再把结果打印在窗口里。

后面要做的 LogLens 是一个命令行程序，没有按钮，只有文字输入和文字输出。所以从第一章开始，就要习惯在终端里工作。

下面这些命令够你用到[第 3 章](/chapter/03)。Windows 的命令提示符（cmd）使用另一套名字，表格的第三列给出对应写法。

| 想做的事 | Linux 与 macOS | Windows（cmd） | 说明 |
| --- | --- | --- | --- |
| 看当前位置 | `pwd` | `cd`（不带参数） | 显示完整路径 |
| 列出文件和文件夹 | `ls` | `dir` | 列出当前文件夹的内容 |
| 进入某个文件夹 | `cd 文件夹名` | `cd 文件夹名` | 名字里有空格时要加引号 |
| 回到上一级 | `cd ..` | `cd ..` | 两个点表示上一级 |
| 新建文件夹 | `mkdir 文件夹名` | `mkdir 文件夹名` | |
| 清空屏幕 | `clear` | `cls` | 只清屏，不影响文件 |

下面是一段 Linux 下的终端记录。Windows 的 cmd 中，`pwd` 换成 `cd`，`ls` 换成 `dir`，路径格式也不同，但含义一样。

```text
$ pwd
/home/user/ch01-try
$ mkdir ch01-try
$ cd ch01-try
$ pwd
/home/user/ch01-try
```

`$` 是提示符，表示“轮到你输入了”，不需要敲进去。Windows 的 cmd 提示符一般长成 `C:\Users\你的名字>`，道理相同。

## 1.3 用 `dotnet new` 建项目

进入一个你打算存放练习的文件夹，然后运行下面的命令。

```text
$ mkdir ch01-try
$ cd ch01-try
$ dotnet new console
The template "Console App" was created successfully.

Processing post-creation actions...
Restoring .../ch01-try/ch01-try.csproj:
  Determining projects to restore...
  Restored .../ch01-try/ch01-try.csproj (in 92 ms).
Restore succeeded.
```

输出里的 `...` 是为了缩短路径。`Restore succeeded` 表示 SDK 已经把项目需要的依赖准备好了。

`dotnet new console` 会在当前文件夹里生成一个控制台项目，项目名取自文件夹名，所以这里叫 `ch01-try`。如果不想先建文件夹，可以直接写 `dotnet new console -o ch01-try`，效果一样。

```text
$ ls
Program.cs
ch01-try.csproj
obj
```

Windows 的 cmd 中用 `dir` 查看同样的内容，输出格式略有不同。你看到的就是一个最小项目的全部内容。`obj` 是 restore 过程生成的文件夹，下一节再细看。

<a id="s1-4" class="lt-anchor-target"></a>

## 1.4 项目里的三样东西

- `.csproj` 是项目说明书，告诉 SDK 用哪个版本编译、用哪些选项编译。
- `Program.cs` 是代码本身。扩展名 `.cs` 表示这是 C# 源文件。
- `obj/` 是编译过程留下的中间文件。你不需要读它，也不要手动修改，更不要把它提交到 Git。

`.csproj` 的内容如下。

```xml
<Project Sdk="Microsoft.NET.Sdk">

  <PropertyGroup>
    <OutputType>Exe</OutputType>
    <TargetFramework>net10.0</TargetFramework>
    <ImplicitUsings>enable</ImplicitUsings>
    <Nullable>enable</Nullable>
  </PropertyGroup>

</Project>
```

这四行设置，我们逐一说明。

| 设置 | 含义 | 改成别的会怎样 |
| --- | --- | --- |
| `OutputType` 为 `Exe` | 生成可以直接运行的程序 | 改成 `Library` 会生成类库，不能直接运行 |
| `TargetFramework` 为 `net10.0` | 面向 .NET 10 编译 | 本书所有输出都在 net10.0 下得到，建议保持不变 |
| `ImplicitUsings` 为 `enable` | 让 SDK 自动引入常用的命名空间 | 保持 `enable`，本章不展开 |
| `Nullable` 为 `enable` | 开启空值检查，提醒你哪些值可能是 null | 关掉后，空值问题要等到运行时才暴露 |

<a id="s1-5" class="lt-anchor-target"></a>

## 1.5 `Program.cs` 与顶层语句

项目模板只给了一行代码。

```csharp
Console.WriteLine("Hello, World!");
```

这一行里有四个部分。`Console` 是系统提供的一个工具箱，第 16 章会讲它的本质。`WriteLine` 是这个工具箱里的一个动作，意思是“打印并换行”。圆括号里是交给它的内容。双引号包住的文字叫字符串，行末的分号表示这句话结束了。

很多老教材里的 C# 程序是这样写的。

```csharp
using System;

namespace HelloWorld
{
    class Program
    {
        static void Main(string[] args)
        {
            Console.WriteLine("Hello, World!");
        }
    }
}
```

这两种写法都会打印 `Hello, World!`。区别在于，老写法里真正要做的事只占一行，其余都是外壳，包括命名空间、类和 `Main` 方法。这些外壳对初学者毫无帮助。老写法里的 `using`、`namespace` 和 `class` 暂时不必看懂，现在只需要知道它们是外壳。

现代 C# 允许你直接写顶层语句，也就是模板里的那一行。编译器会替你生成 `Main`，程序的入口仍然在那里，只是不用你亲手写。传统写法 12 行，顶层语句 1 行，差的正是这些外壳。本书全部使用顶层语句。

有一条规则要记住。同一个项目里，只能有一个文件包含顶层语句。如果两个文件都写了，编译器会报 CS8802，这个错误在 1.13 节能查到。

<a id="s1-6" class="lt-anchor-target"></a>

## 1.6 `Console` 为什么能直接用

`Console` 是 .NET 提供的一个工具，它的全名是 `System.Console`。前面的 `System` 叫命名空间，可以先把它理解成分类用的文件夹。

本书的项目都开启了 `ImplicitUsings`，SDK 会替你引入 `System` 等常用的命名空间，所以代码里可以直接写 `Console`。命名空间、`using` 和隐式引入的细节，留到后面讲新语法的章节再看，现在不必深究。

遇到找不到名称的编译错误时（1.13 节有 CS0103 的例子），先对照拼写和大小写，再看看是不是漏了什么。

<a id="s1-7" class="lt-anchor-target"></a>

## 1.7 输出，`WriteLine`、`Write` 与转义

`WriteLine` 打印后换行，`Write` 打印后不换行。看下面的例子。

```csharp
Console.WriteLine("第一行");
Console.Write("这一段不换行，");
Console.Write("接着这一段。");
Console.WriteLine();
```

输出如下。

```text
第一行
这一段不换行，接着这一段。
```

最后那个不带参数的 `Console.WriteLine();` 只打印一个空行。

字符串里的反斜杠叫转义符，它让你写出无法直接打出的字符。下表列出最常用的几个。

| 写法 | 效果 |
| --- | --- |
| `\n` | 换行 |
| `\t` | 制表符，用来对齐，效果接近四个空格 |
| `\"` | 一个双引号。字符串本身用双引号包住，所以内部的双引号要转义 |
| `\\` | 一个反斜杠。路径 `C:\Users` 要写成 `C:\\Users` |
| `\u4F60` | 按编码写出一个字符，这里是“你” |

下面是一段代码和它的输出。

```csharp
Console.WriteLine("第一行\n第二行");
Console.WriteLine("列1\t列2\t列3");
Console.WriteLine("他说：\"你好\"");
Console.WriteLine("路径是 C:\\Users\\demo");
Console.WriteLine("Unicode 字符：\u4F60\u597D");
```

```text
第一行
第二行
列1	列2	列3
他说："你好"
路径是 C:\Users\demo
Unicode 字符：你好
```

如果不想一个个转义，可以在字符串前面加 `@`，这叫逐字字符串。`@` 之后的内容原样保留，只有双引号要写两遍。

```csharp
Console.WriteLine(@"逐字字符串里的 \n 保持原样");
Console.WriteLine(@"逐字字符串里的 ""引号"" 要写两遍");
```

```text
逐字字符串里的 \n 保持原样
逐字字符串里的 "引号" 要写两遍
```

路径和正则表达式经常用到逐字字符串，[第 2 章](/chapter/02)的日期格式里会再遇到它。

<a id="s1-8" class="lt-anchor-target"></a>

## 1.8 注释，写给读代码的人

注释是写给人看的，编译器会完全忽略它们。C# 有三种写法。

```csharp
// 单行注释：从 // 开始，到这一行结束为止

/*
   多行注释：从 /* 开始，到 */ 结束
   中间可以写很多行
*/

Console.WriteLine("代码照常执行");   // 行尾也可以加注释
```

注释里最容易犯的错误有两种，一种是什么都不写，另一种是把代码翻译成中文。

```csharp
// 不好：读代码就能看懂的事，注释只是在重复
i++;   // i 加 1

// 好：说明代码为什么这样做
i++;   // 跳过表头那一行，从第一条数据开始统计
```

判断标准很简单，代码说明“做了什么”，注释说明“为什么这么做”。以后写的注释大多都按这个标准来。

<a id="s1-9" class="lt-anchor-target"></a>

## 1.9 输入，`ReadLine` 与 null

接收用户输入用 `Console.ReadLine()`。程序停下来等待，用户敲完一行并回车，这一行文字就交给你。

```csharp
Console.Write("请问你叫什么名字？ ");
string? name = Console.ReadLine();
Console.WriteLine("你好，" + name);
```

这里有两个新东西。第一个是 `string? name`，其中 `string` 表示文字，后面的 `?` 表示这个变量可能是 null。第二个是 `=`，它的意思是“把右边的东西放进左边的变量”，不是数学里的“等于”。判断相等要用 `==`，[第 3 章](/chapter/03)会讲。

null 表示“什么都没有”。什么时候会得到 null？比如输入已经结束，在 Linux 和 macOS 的终端里按 `Ctrl+D`，在 Windows 里按 `Ctrl+Z` 再回车。只按回车则得到空字符串，这和 null 不同。

所以程序里常用 `string.IsNullOrWhiteSpace(name)` 来检查。如果 `name` 是 null、空字符串或者全是空格，它返回 `true`。练习 2 会让你看到 null 拼进文字后是什么样子。

## 1.10 检查点 `ch01-hello`

本章的完整程序放在 `tutorial/code/ch01-hello/Program.cs`。下面是它的全部内容，逐段的说明都写在注释里。

```csharp
// ============================================================
// 第 1 章 · 我的第一个程序
//
// 三种运行方式，效果不同：
//   dotnet run                  在终端里等你输入名字
//   dotnet run -- 小明          名字从命令行参数传进来，不再提问
//   echo 小红 | dotnet run      名字从管道灌进来（别的程序的输出也能这样接）
// ============================================================

// 1) 打印一个标题栏，让输出看起来像一张卡片
Console.WriteLine("==============================");
Console.WriteLine("  LogLens 学习打卡");
Console.WriteLine("==============================");
Console.WriteLine();

// 2) 拿到名字：有命令行参数就用参数，没有才问用户
string? name;
if (args.Length > 0)
{
    name = args[0];
}
else
{
    Console.Write("请问你叫什么名字？ ");
    name = Console.ReadLine();
}

// 3) 如果名字是 null、空字符串或只有空格，就用"陌生人"代替
if (string.IsNullOrWhiteSpace(name))
{
    name = "陌生人";
}

// 4) 拼一句问候并打印
Console.WriteLine();
Console.WriteLine($"你好，{name}！");
Console.WriteLine("从今天起，你是一名会写程序的人了。");
```

这段代码里有三个前面没讲过的东西。

`args` 是命令行参数，程序启动时，`dotnet run --` 后面写的文字会按空格拆开，装进 `args` 这个数组。`args[0]` 就是第一个参数。数组的编号从 0 开始，[第 2 章](/chapter/02)会细讲。

`if ... else` 是二选一。条件成立时执行第一个大括号里的内容，否则执行 `else` 后面的内容。[第 3 章](/chapter/03)会系统讲它。

`$"你好，{name}！"` 是字符串插值。以 `$` 开头的字符串里，花括号中的内容会被替换成变量的值。[第 2 章](/chapter/02) 2.8 节会详细讲，现在先照着用。

下面是三种运行方式的输出。进入 `tutorial/code/ch01-hello` 文件夹后，依次运行下面的命令。

```text
$ dotnet run < /dev/null
==============================
  LogLens 学习打卡
==============================

请问你叫什么名字？
你好，陌生人！
从今天起，你是一名会写程序的人了。
```

这里的 `< /dev/null` 表示输入为空，相当于不给程序任何键盘输入，所以程序立即得到 null 并使用“陌生人”。Windows 的 cmd 中写成 `< nul`，效果相同。不加这一项的话，程序会停下来等你输入。

```text
$ dotnet run -- 小明
==============================
  LogLens 学习打卡
==============================


你好，小明！
从今天起，你是一名会写程序的人了。
```

`--` 把它后面的内容交给程序，而不是交给 `dotnet` 自己。这次程序没有提问，直接用了参数。

```text
$ echo 小红 | dotnet run
==============================
  LogLens 学习打卡
==============================

请问你叫什么名字？
你好，小红！
从今天起，你是一名会写程序的人了。
```

`|` 是管道，它把左边命令的输出接到右边命令的输入。这里 `echo` 把“小红”送进了程序，程序的 `ReadLine` 收到的正是它。以后学习命令行工具时，你会经常用到这种写法。

## 1.11 运行的几种方式，以及 `bin` 和 `obj`

上一节已经用到了 `dotnet run`。它其实是两步合在一起。先编译，再运行。

<img class="lt-img-light" src="/content/images/ch01-fig01-loop.svg" alt="编辑、构建、运行的循环" />
<img class="lt-img-dark" src="/content/images/ch01-fig01-loop-dark.svg" alt="编辑、构建、运行的循环" />

写代码的日常就是这个循环。下面的表格把各个命令拆开来看。

| 命令 | 做的事 |
| --- | --- |
| `dotnet build` | 只编译，不运行。生成 `bin` 和 `obj` |
| `dotnet run` | 需要时先编译，然后运行 |
| `dotnet run --no-build` | 直接运行上一次编译的结果，不重新编译 |
| `dotnet run --project 路径` | 在别的文件夹里运行指定的项目 |
| `dotnet bin/Debug/net10.0/ch01-try.dll` | 直接运行编译产物，不经过 SDK |
| `dotnet clean` | 删除 `bin` 和 `obj` 里的产物 |

一次 `dotnet build` 成功时，末尾会显示如下内容。

```text
    0 Warning(s)
    0 Error(s)

Time Elapsed 00:00:01.68
```

编译之后，项目里会多出 `bin` 文件夹。这是编译后的结果。

```text
bin/Debug/net10.0/ch01-try
bin/Debug/net10.0/ch01-try.deps.json
bin/Debug/net10.0/ch01-try.dll
bin/Debug/net10.0/ch01-try.pdb
bin/Debug/net10.0/ch01-try.runtimeconfig.json
```

`ch01-try.dll` 是真正被运行的程序，`.pdb` 是调试信息，供后面学调试时使用。`bin` 和 `obj` 都是生成的东西，可以随时删掉再重新编译。LogLens 项目的 `.gitignore` 里就写着 `bin/` 和 `obj/`，让 Git 忽略它们。

为什么不建议双击运行？因为 Windows 的双击只会打开一个窗口，程序一结束窗口就关了，你看不清输出，也看不见报错。用终端运行，结果会一直留在屏幕上，报错也完整可读。

## 1.12 读懂一条报错

写错代码是常态，编译器说的话要学会读。先看一个例子，这里少了一个分号。

```csharp
Console.WriteLine("你好")
```

编译时，中文界面下的输出如下。

```text
  正在确定要还原的项目…
  所有项目均是最新的，无法还原。
.../missing_semicolon/Program.cs(1,24): error CS1002: 应输入 ; [.../missing_semicolon.csproj]

生成失败。

.../missing_semicolon/Program.cs(1,24): error CS1002: 应输入 ; [.../missing_semicolon.csproj]
    0 个警告
    1 个错误

已用时间 00:00:01.39
```

路径用 `...` 缩短了，中间重复出现的同一行也省略了一次。输出里出现了 `生成失败` 和 `1 个错误`，说明编译没有通过。

要让报错显示成中文，在运行命令前设置环境变量。Linux 和 macOS 用 `export DOTNET_CLI_UI_LANGUAGE=zh-CN`，Windows 的 cmd 用 `set DOTNET_CLI_UI_LANGUAGE=zh-CN`。这两条命令只对当前窗口有效。不设置也没关系，英文报错的错误码完全相同，搜索错误码就能找到官方说明。

<img class="lt-img-light" src="/content/images/ch01-fig02-error.svg" alt="一条报错的五个组成部分" />
<img class="lt-img-dark" src="/content/images/ch01-fig02-error-dark.svg" alt="一条报错的五个组成部分" />

上图把这条报错拆成了五个部分。

1. 位置包括文件名、行号和列号。`(1,24)` 表示第 1 行第 24 列，编译器在这里发现了问题。
2. 级别说明严重程度，`error` 必须修改，程序无法生成；`warning` 是警告，程序仍能生成，但最好也看一眼。
3. 错误码，`CS1002` 是固定编号。同样的错误在不同电脑上编号一样，所以可以拿它去搜索。
4. 说明是编译器的判断。这里它想要一个分号。
5. 所属项目是哪个 `.csproj` 报的错。项目多的时候，靠它定位是哪一个项目。

读报错有三条实用的习惯。第一，从第一条错误读起，修完再重新编译，因为后面的错误常常是前面那一个引起的。第二，先看行号，再看代码，行号附近往往就是问题所在。第三，遇到你看不懂的错误码，先去 1.13 节查表，查不到再搜索。

编译失败时，`dotnet run` 不会运行程序，它会在末尾提示如下内容。

```text
The build failed. Fix the build errors and run again.
```

（英文界面的提示，意思是“编译失败，修好错误后再运行”。）

## 1.13 常见错误速查

下面的报错在 `zh-CN` 界面下显示，路径已省略。

| 错误码 | 中文报错（节选） | 常见原因 | 怎么改 |
| --- | --- | --- | --- |
| CS1002 | 应输入 ; | 语句末尾少了分号 | 在行尾补上 `;` |
| CS0103 | 当前上下文中不存在名称“Consol” | 拼写或大小写错，例如 `Consol`、`console` | 对照拼写，C# 区分大小写 |
| CS1056 | 意外的字符““” | 粘进了中文引号 `“”` | 换成英文引号 `"` |
| CS1010 | 常量中有换行符 | 字符串的结束引号缺失，后面的内容被当成字符串的一部分 | 补上结束的 `"` |
| CS1513 | 应输入 } | 大括号没有配对 | 检查每个 `{` 是否有对应的 `}` |
| CS8803 | 顶级语句必须位于命名空间和类型声明之前。 | 顶层语句写在了 `class` 后面 | 把顶层语句移到类的前面 |
| CS8802 | 只有一个编译单元可具有顶级语句。 | 同一个项目里两个文件都写了顶层语句 | 只保留一个文件的顶层语句 |
| CS0029 | 无法将类型“int”隐式转换为“bool” | 把 `if (x = 5)` 中的 `=` 当成判断相等 | 判断相等用 `==`，[第 3 章](/chapter/03)细讲 |
| CS7022 | 程序的入口点是全局代码；将忽略“P.Main(string[])”入口点。 | 顶层语句和 `Main` 方法同时存在 | 这是警告，删掉其中一个 |
| NETSDK1045 | 当前 .NET SDK 不支持面向 .NET 11.0。 | `TargetFramework` 写的版本比 SDK 还新 | 改回 `net10.0` |

CS0029 常常还伴随一条警告。在 `var x = 5;` 与 `if (x = 5)` 组成的例子里，编译器还会给出 CS0219，说变量 `x` 被赋值却没有被使用。这是因为 `x = 5` 的结果被当成判断条件，而 `int` 不能当成 `bool`。

表格里的错误只是常见的一部分。遇到表里没有的错误码，就按 1.12 节的五个部分去拆开读。

## 1.14 编译错误与运行时错误

前面的错误都发生在编译阶段，程序根本没有生成。还有一类错误要等程序跑起来才会出现，叫运行时错误。看下面这个练习的参考答案，它要求用户输入两个参数。

```csharp
string name = args[0];
string age = args[1];
Console.WriteLine($"{name} 今年 {age} 岁。");
```

如果只传一个参数，`dotnet run -- 小林` 就会让程序崩溃，输出如下。

```text
Unhandled exception. System.IndexOutOfRangeException: Index was outside the bounds of the array.
   at Program.<Main>$(String[] args) in .../Program.cs:line 4
```

编译器无法预料用户会传几个参数，所以这段代码能通过编译。运行到 `args[1]` 时，数组里根本没有第二个元素，程序只好抛出异常并退出。退出码在 Linux 上是 134，Windows 上会显示另一个数字，具体取决于系统。

两类错误的区别可以这样记。编译错误是编译器看了代码就能发现的，运行时错误要靠实际运行、输入不同的数据才能暴露。1.16 节的练习 3 会让你亲手碰到一次这种错误。

## 1.17 这一章的知识，在 LogLens 里出现在哪

本书的项目是 LogLens，一个命令行日志分析工具。它的代码在 `src/` 文件夹里。`src/` 下有 144 个 C# 文件，约 1.6 万行（16,328 行），测试代码另有 7 个文件、约 700 行。下面三个位置和本章的知识直接相关。

- `src/LogLens.Cli/Ui/Banner.cs`（33 行），启动时打印 logo 和提示语，核心就是 `Console.WriteLine`。logo 用原始字符串字面量写成，颜色则由辅助类 `Ansi` 加上。
- `src/LogLens.Cli/ReplRunner.cs` 第 43 行是 `Console.ReadLine()`。它位于一个 `while` 循环里，每次读取一行命令；读到 null 时说明输入已经结束，程序就退出。循环的写法[第 3 章](/chapter/03)会讲。
- `src/LogLens.Cli/Ui/ConsoleTable.cs`（152 行），负责画表格的边框。列宽不能简单地用 `string.Length` 计算，因为一个汉字在终端里占两列，所以代码里用的是 `Ansi.DisplayWidth`。

你可以现在就打开 `Banner.cs` 看一看。里面的字符画和颜色你暂时看不懂，但 `Console.WriteLine` 你已经会用了。
