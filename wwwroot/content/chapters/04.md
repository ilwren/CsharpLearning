# 第 4 章 集合，一组数据怎么存放

> **本章你会做出什么**
>
> 一个小型的日志统计程序。它把一批日志放进集合，统计每个级别出现了几次，找出涉及哪些模块，找出最慢的一条，最后用 `StringBuilder` 拼出一份文本报告。
>
> ```text
> 共 8 条日志
>
> 级别分布：
>   info  4 条
>   warn  2 条
>   error 2 条
>
> 涉及 3 个模块
>
> 最慢的一条：2815 ms，order，error
>
> 各模块问题数：
>   api   1 个
>   order 3 个
> ```
>
> 做这一章之前，需要会用 `for`、`foreach`、`if`、`Console.WriteLine`，并知道 `int` 和字符串的基本用法（第 2、3 章讲过）。这一章讲集合本身，它是什么，有哪些特性，数组、`List<T>`、`Dictionary<TKey, TValue>`、`HashSet<T>` 和 `ArrayList` 各自怎样增、删、改、查，以及 `StringBuilder` 为什么适合拼接文本。
>
> 对集合做筛选、排序、分组的 LINQ 不放在这一章。它要用到方法、lambda、匿名类型和迭代器，这些内容都还没有讲到，所以单独放在后面的一章。

## 4.1 什么是集合

一个变量只能放一个值。`int ms = 1520;` 里的 `ms` 只能是一个整数。如果要放一批日志的耗时，就需要一种能装很多值的容器，这种容器就是集合。

集合是把多个值放在一起、统一管理的容器。程序里常见的集合有好几种，本章讲其中五种，每一种的规则都不一样。

<img class="lt-img-light" src="/content/images/ch04-fig01-family.svg" alt="集合家族" />
<img class="lt-img-dark" src="/content/images/ch04-fig01-family-dark.svg" alt="集合家族" />

前四种集合，也就是数组、`List<T>`、`Dictionary<TKey, TValue>` 和 `HashSet<T>`，都实现了 `IEnumerable<T>`。它的意思是“能按顺序一个一个取出元素”，也就是能被 `foreach` 遍历。因此，只关心“能遍历”的代码可以只接收 `IEnumerable<T>`，不用关心它到底是哪一种集合。`ArrayList` 实现的是它的非泛型版本，见 [4.7 节](#s4-7)。

```csharp
IEnumerable<string> names = new List<string> { "info", "warn" };
foreach (var n in names)
{
    Console.WriteLine(n);
}
```

输出 `info` 和 `warn`。

### 集合的五个特性

选集合之前，先看下面这张表。表里的每一列，都是判断“该用哪种集合”时要问的问题。

| 类型 | 有顺序吗 | 能重复吗 | 能改变大小吗 | 怎么找元素 |
| --- | --- | --- | --- | --- |
| `Array` 数组 | 有，按下标 | 能 | 不能 | 按下标 |
| `List<T>` | 有，按下标 | 能 | 能 | 按下标，或按值查找 |
| `Dictionary<TKey, TValue>` | 不保证 | 键不能，值能 | 能 | 按键 |
| `HashSet<T>` | 不保证 | 不能 | 能 | 按值（判断有没有） |
| `ArrayList`（非泛型） | 有，按下标 | 能 | 能 | 按下标，元素是 `object` |

这张表里包含五个特性，逐个解释如下。

**第一，是否有顺序。** 数组和 `List<T>` 的元素按放入的先后排列，第几个元素可以用下标取出。字典和 `HashSet<T>` 不保证顺序，遍历时的顺序可能和放入的顺序不同，代码里不要依赖它。

**第二，是否允许重复。** 数组和 `List<T>` 可以放相同的值。`Dictionary<TKey, TValue>` 的键不能重复，但不同的键可以对应相同的值。`HashSet<T>` 里每个值只能出现一次。

**第三，能否改变大小。** 数组一旦创建，长度就固定了。其余三种都可以随时增加或删除元素。

**第四，怎么找元素。** 数组和 `List<T>` 用下标找，比如 `levels[0]`。字典用键找，比如 `counts["info"]`。判断一个值在不在集合里，`List<T>` 要从头逐个比较，数据多的时候会慢；`HashSet<T>` 和 `Dictionary<TKey, TValue>` 则是直接定位，数据多的时候仍然很快。

**第五，判断“相等”的标准。** `List<T>.Contains`、`HashSet<T>.Contains` 这类方法，判断两个元素是否相等，用的是 `Equals`。字符串和元组是按内容比较的，内容相同就相等。自己写的类默认按引用比较，即两个对象必须是同一个才算相等。

```csharp
var a1 = new Item { Name = "api" };
var a2 = new Item { Name = "api" };
var items = new List<Item> { a1 };
Console.WriteLine(items.Contains(a2));
Console.WriteLine(items.Contains(a1));

var tupleList = new List<(string, int)> { ("api", 1) };
Console.WriteLine(tupleList.Contains(("api", 1)));

class Item
{
    public string Name = "";
}
```

输出 `False`、`True`、`True`。`a1` 和 `a2` 的 `Name` 相同，但它们是两个不同的对象，所以第一个结果是 `False`。如果希望按内容比较，需要在类里重写 `Equals`，这一点要等到后面讲类的章节再说。

> 这些集合都不是线程安全的。多个线程同时修改同一个集合，结果不可预料。多线程的情况放到后面的异步章节再讲。

## 4.2 数组，固定长度的一排格子

数组是最简单的集合。它的特点可以归纳为四条，依次是元素类型相同，长度创建后固定，下标从 0 开始，内存里的格子连续排列。

<img class="lt-img-light" src="/content/images/ch04-fig02-array.svg" alt="数组的连续存放" />
<img class="lt-img-dark" src="/content/images/ch04-fig02-array-dark.svg" alt="数组的连续存放" />

### 创建数组

创建数组有三种常见写法。

```csharp
int[] scores = { 90, 85, 77 };
int[] scores2 = new int[] { 90, 85, 77 };
int[] scores3 = new int[3];
Console.WriteLine($"{scores2[1]} {scores3[0]}");
```

输出 `85 0`。前两种写法效果相同，都直接给出了三个元素。第三种只声明了 3 个位置，每个位置都是 `int` 的默认值 0。

### 增删改查

数组的四种操作，只有“删”需要特别说明。

**查**，用下标读取。下标从 0 开始，第一个是 `[0]`，最后一个是 `[Length - 1]`。长度用 `Length` 取得。

```csharp
Console.WriteLine(scores[1]);
```

输出 `85`。

**改**，用下标赋值。

```csharp
scores[1] = 88;
Console.WriteLine(string.Join(",", scores));
```

输出 `90,88,77`。`string.Join` 把数组的所有元素用逗号连成一个字符串，方便一次看到全部内容。

**增**，数组没有 `Add` 方法，长度不能增加。要放入更多元素，只能新建一个更大的数组，再把旧的内容复制过去。

**删**，同样做不到原地删除。`Array.Resize` 可以新建一个指定长度的数组，并把前面的元素复制过去，结果就像截掉了后面的元素。

```csharp
Array.Resize(ref scores, 2);
Console.WriteLine(string.Join(",", scores));
Console.WriteLine(scores.Length);
```

输出 `90,88` 和 `2`。`ref` 的用法要等讲方法的章节再细说，这里照着写就行。需要注意，`Array.Resize` 产生的是一个新数组，如果别的变量还指着旧数组，它们看到的仍然是旧的内容。

### 越界

下标超出范围时，读和写都会出错。

```csharp
try
{
    scores[5] = 1;
}
catch (Exception e)
{
    Console.WriteLine(e.GetType().Name);
}
```

输出 `IndexOutOfRangeException`。这是运行时的错误，编译能通过。C 语言里越界读写往往不报错，读到的是别处的内存。C# 直接抛出异常，问题在出现的地方就会暴露出来。

数组适合的场景是数量确定，之后不需要增删，并且需要按位置快速访问。例如一周七天的温度，或者一个固定大小的图像像素缓冲区。

## 4.3 `List<T>`，能长能短的列表

`List<T>` 是最常用的集合。`<T>` 是泛型参数，表示“这个列表装什么类型，由你决定”。[第 8 章](/chapter/08)会细讲泛型。

`List<T>` 的内部其实也是一个数组。它有两个相关的数字。

- `Count` 是列表里实际有几个元素。
- `Capacity` 是内部数组的大小，也就是还能放多少个元素而不必扩容。

放入的元素超过 `Capacity` 时，`List<T>` 会自动换成一个更大的数组，并把旧的元素复制过去。这一步对使用者是透明的，但它说明了一件事，即 `List<T>` 的增删，在中间插入或删除时，要挪动后面的元素。

<img class="lt-img-light" src="/content/images/ch04-fig03-list.svg" alt="List 的插入与删除" />
<img class="lt-img-dark" src="/content/images/ch04-fig03-list-dark.svg" alt="List 的插入与删除" />

### 创建

```csharp
var levels = new List<string>();
levels.Add("info");
levels.AddRange(new[] { "warn", "error", "info" });
levels.Insert(1, "debug");
Console.WriteLine(string.Join(",", levels));
Console.WriteLine(levels.Count);
```

输出 `info,debug,warn,error,info` 和 `5`。`Add` 在末尾追加一个元素，`AddRange` 一次追加多个，`Insert(1, "debug")` 在下标 1 的位置插入，原来下标 1 及之后的元素都向后挪了一格。

如果事先知道大概要放多少个元素，可以在创建时指定容量，减少扩容的次数。

```csharp
var big = new List<int>(100);
Console.WriteLine(big.Capacity);
Console.WriteLine(big.Count);
```

输出 `100` 和 `0`。容量只是预留的空间，它不会改变 `Count`。

### 读取

| 方法 | 作用 | 找不到时 |
| --- | --- | --- |
| `levels[i]` | 按下标取值 | 下标超出范围时抛出异常 |
| `IndexOf(x)` | 第一次出现的下标 | 返回 `-1` |
| `LastIndexOf(x)` | 最后一次出现的下标 | 返回 `-1` |
| `Contains(x)` | 是否包含 | 返回 `false` |
| `Find(条件)` | 第一个符合条件的元素 | 返回该类型的默认值，字符串是 `null` |
| `FindIndex(条件)` | 第一个符合条件的下标 | 返回 `-1` |
| `Exists(条件)` | 是否存在符合条件的元素 | 返回 `false` |

```csharp
Console.WriteLine(levels.IndexOf("error"));
Console.WriteLine(levels.IndexOf("fatal"));
Console.WriteLine(levels.LastIndexOf("info"));
Console.WriteLine(levels.Contains("warn"));
Console.WriteLine(levels.Find(l => l.StartsWith("e")));
Console.WriteLine(levels.Find(l => l.StartsWith("z")) == null);
Console.WriteLine(levels.FindIndex(l => l == "warn"));
Console.WriteLine(levels.Exists(l => l == "debug"));
```

输出依次是 `3`、`-1`、`4`、`True`、`error`、`True`、`2`、`True`。

`IndexOf` 返回 `-1` 而不是抛出异常，所以用它的结果做下标之前，一定要先判断是不是 `-1`。

```csharp
int pos = levels.IndexOf("fatal");
if (pos >= 0)
{
    Console.WriteLine(levels[pos]);
}
```

`Find` 和 `FindIndex` 的参数是一个条件，`l => l.StartsWith("e")` 是 lambda 表达式，专门用来写这种条件。它的来历在[第 9 章](/chapter/09) 9.3 节讲，这里先照着写。

### 修改

修改某个位置的元素，直接赋值给下标即可。

```csharp
levels[0] = "INFO";
Console.WriteLine(levels[0]);
```

输出 `INFO`。如果要把每个元素都改掉，用 `for` 配合下标。

```csharp
for (int i = 0; i < levels.Count; i++)
{
    levels[i] = levels[i].ToLowerInvariant();
}
```

不能用 `foreach` 直接改变元素。`foreach` 里的变量只是一个副本，给它赋值会出编译错误。

```csharp
foreach (var l in levels)
{
    l = l.ToUpperInvariant();   // 编译错误 CS1656，不能给 foreach 的变量赋值
}
```

### 删除

| 方法 | 作用 | 返回值 |
| --- | --- | --- |
| `Remove(x)` | 删除第一个等于 `x` 的元素 | 找到并删除返回 `true`，否则返回 `false` |
| `RemoveAt(i)` | 删除下标 `i` 的元素 | 无返回值，下标越界时抛出异常 |
| `RemoveAll(条件)` | 删除所有符合条件的元素 | 返回删除了几个 |
| `Clear()` | 清空所有元素 | 无返回值 |

```csharp
levels.Clear();
levels.AddRange(new[] { "debug", "info", "warn", "error", "info" });

Console.WriteLine(levels.Remove("fatal"));
Console.WriteLine(levels.Remove("info"));
Console.WriteLine(string.Join(",", levels));

levels.RemoveAt(0);
Console.WriteLine(string.Join(",", levels));

Console.WriteLine(levels.RemoveAll(l => l == "info"));
Console.WriteLine(string.Join(",", levels));
```

输出依次是 `False`、`True`、`debug,warn,error,info`、`warn,error,info`、`1`、`warn,error`。`Remove` 只删除第一个匹配的元素，后面相同的元素不受影响。

删除时有一个容易忽略的陷阱。下面的代码想删掉所有的 `debug`，但是从前往后删时，后面的元素会前移，`for` 的下标却继续加一，于是漏掉了紧跟在后面的那个元素。

```csharp
var nums = new List<string> { "debug", "debug", "info" };
for (int i = 0; i < nums.Count; i++)
{
    if (nums[i] == "debug")
    {
        nums.RemoveAt(i);
    }
}
Console.WriteLine(string.Join(",", nums));
```

输出 `debug,info`，第二个 `debug` 没有被删掉。程序没有报错，结果却不对，这种错误最难发现。正确的做法有两种。一是从后往前删。

```csharp
var nums2 = new List<string> { "debug", "debug", "info" };
for (int i = nums2.Count - 1; i >= 0; i--)
{
    if (nums2[i] == "debug")
    {
        nums2.RemoveAt(i);
    }
}
Console.WriteLine(string.Join(",", nums2));
```

输出 `info`。二是直接用 `RemoveAll`，它会把符合条件的元素一次删干净，最省事。

用 `foreach` 遍历的同时删除元素，会抛出 `InvalidOperationException`。这个错误在 4.10 节还会再讲。

### `List<T>` 与数组怎么选

数量不确定、需要增删，用 `List<T>`。数量固定，并且不需要增删，用数组。在实际项目里，`List<T>` 比数组常见得多。

> C# 12 之后可以用集合表达式创建列表，写法更短，`List<string> a = ["info", "warn", "error"];`。它和 `new List<string> { ... }` 的效果相同。LogLens 的 `QueryEngine.cs` 里就有 `[.. ordered]` 这样的写法。

## 4.4 `Dictionary<TKey, TValue>`，靠键找值

数组和列表靠下标找，也就是第几个。字典靠键找，也就是叫什么名字。键和值成对存放，键是找值的依据。

<img class="lt-img-light" src="/content/images/ch04-fig04-dictionary.svg" alt="Dictionary 按键找值" />
<img class="lt-img-dark" src="/content/images/ch04-fig04-dictionary-dark.svg" alt="Dictionary 按键找值" />

字典的规则有三条。

**键不能重复。** 同一个键只能对应一个值，而且键不能是 `null`。

**值可以重复。** 不同的键可以对应相同的值。

**键区分大小写。** `"info"` 和 `"INFO"` 是两个不同的键。

字典的遍历顺序不保证和放入的顺序相同。代码里需要固定顺序时，先排序，再遍历排好序的结果。

### 创建与新增

```csharp
var counts = new Dictionary<string, int>
{
    ["info"] = 4,
    ["warn"] = 2,
};
counts.Add("error", 1);
Console.WriteLine(counts.Count);
```

输出 `3`。`Add` 和下面的索引器赋值，都能新增键值对，但遇到已经存在的键时，两者的行为不同。

```csharp
try
{
    counts.Add("info", 9);
}
catch (Exception e)
{
    Console.WriteLine(e.GetType().Name);
}
```

输出 `ArgumentException`。`Add` 遇到已存在的键会抛出异常。索引器赋值则不会。

```csharp
counts["info"] = 5;
counts["debug"] = 0;
Console.WriteLine(counts["info"]);
Console.WriteLine(counts.Count);
```

输出 `5` 和 `4`。键已存在时，索引器赋值会覆盖旧的值；键不存在时，会新增一项。日常写代码时，多数人使用索引器赋值。

### 读取

```csharp
Console.WriteLine(counts.ContainsKey("warn"));
Console.WriteLine(counts.ContainsValue(2));
Console.WriteLine(counts.TryGetValue("fatal", out var fatal));
Console.WriteLine(fatal);
Console.WriteLine(string.Join(",", counts.Keys));
Console.WriteLine(string.Join(",", counts.Values));
```

输出依次是 `True`、`True`、`False`、`0`、`info,warn,error,debug`、`5,2,1,0`。

| 写法 | 作用 | 键不存在时 |
| --- | --- | --- |
| `counts["info"]` | 取值 | 抛出 `KeyNotFoundException` |
| `ContainsKey(key)` | 判断键是否存在 | 返回 `false` |
| `ContainsValue(value)` | 判断某个值是否存在，要逐个比较 | 返回 `false` |
| `TryGetValue(key, out var v)` | 安全取值 | 返回 `false`，`v` 为默认值 |

键不确定时，应该先用 `TryGetValue` 判断，而不是直接用下标。

```csharp
if (counts.TryGetValue("fatal", out var fatalCount))
{
    Console.WriteLine($"fatal 有 {fatalCount} 条");
}
else
{
    Console.WriteLine("没有 fatal");
}
```

输出 `没有 fatal`。`out var` 的写法和 2.10 节的 `TryParse` 相同。

### 修改

```csharp
counts["warn"] += 1;
Console.WriteLine(counts["warn"]);
```

输出 `3`。修改就是对键赋新值。计数是字典最常见的用法，有两种写法。

```csharp
var levels = new List<string> { "info", "warn", "info", "error", "info" };
var tally = new Dictionary<string, int>();
foreach (var level in levels)
{
    if (tally.ContainsKey(level))
    {
        tally[level]++;
    }
    else
    {
        tally[level] = 1;
    }
}
```

这段代码的结果是 `info` 出现 3 次，`warn` 和 `error` 各 1 次。另一种写法是用 `TryGetValue` 取出当前次数，没有时为 0。

```csharp
tally.TryGetValue(level, out var current);
tally[level] = current + 1;
```

两种写法结果相同。前一种更直观，后一种更短。

### 删除

```csharp
Console.WriteLine(counts.Remove("INFO"));
Console.WriteLine(counts.Remove("fatal"));
Console.WriteLine(counts.Count);
counts.Clear();
Console.WriteLine(counts.Count);
```

输出 `False`、`False`、`4`、`0`。键不存在时，`Remove` 返回 `false`，不会抛出异常。`INFO` 和 `info` 不是同一个键，所以删除 `INFO` 失败。

### 遍历

```csharp
foreach (var pair in counts)
{
    Console.WriteLine($"{pair.Key} → {pair.Value}");
}

foreach (var (key, value) in counts)
{
    Console.WriteLine($"{key} → {value}");
}
```

两段代码的输出相同。每个元素的类型是 `KeyValuePair<TKey, TValue>`，用 `.Key` 和 `.Value` 取出。第二段代码把两个值直接拆成两个变量。

遍历时修改字典，要分情况看。遍历时新增键，会抛出 `InvalidOperationException`。遍历时删除，在当前版本不会报错，但这种写法不清楚，不建议依赖。比较稳妥的做法是先把要删的键收集到一个列表里，遍历结束后再删。

## 4.5 `HashSet<T>`，只关心“有没有”

`HashSet<T>` 只保存值，不保存键，也不关心顺序。它有两个特点，每个值只能出现一次，判断一个值在不在集合里，速度不随数量明显变慢。

它适合两类场景，一是去重，二是判断某个东西是否在一组东西里面，例如“这个模块是不是在忽略列表中”。

### 创建与增删查

```csharp
var names = new HashSet<string>();
Console.WriteLine(names.Add("api"));
Console.WriteLine(names.Add("api"));
names.Add("order");
Console.WriteLine(names.Count);
Console.WriteLine(names.Contains("order"));
Console.WriteLine(names.Remove("api"));
Console.WriteLine(names.Remove("api"));
```

输出依次是 `True`、`False`、`2`、`True`、`True`、`False`。`Add` 的返回值告诉你这个值是不是新加入的。第二次添加 `"api"` 时，它已经存在，所以返回 `false`，集合不变。

`HashSet<T>` 没有下标，也没有“修改”这个操作。修改一个元素，等于先删除旧的，再添加新的。

### 去重

把一个列表转成 `HashSet<T>`，就能去掉重复的元素。

```csharp
var levels = new List<string> { "info", "warn", "info", "error", "info" };
var unique = new HashSet<string>(levels);
Console.WriteLine(unique.Count);
```

输出 `3`。

### 集合运算

`HashSet<T>` 提供了数学上的集合运算。这些方法会直接修改调用它的那个集合，所以如果还需要原来的内容，要先复制一份。

```csharp
var a = new HashSet<int> { 1, 2, 3, 4 };
var b = new HashSet<int> { 3, 4, 5 };

var union = new HashSet<int>(a);
union.UnionWith(b);
Console.WriteLine(string.Join(",", union));

var inter = new HashSet<int>(a);
inter.IntersectWith(b);
Console.WriteLine(string.Join(",", inter));

var diff = new HashSet<int>(a);
diff.ExceptWith(b);
Console.WriteLine(string.Join(",", diff));

Console.WriteLine(new HashSet<int> { 3, 4 }.IsSubsetOf(a));
```

输出依次是 `1,2,3,4,5`、`3,4`、`1,2`、`True`。

| 方法 | 含义 | 结果 |
| --- | --- | --- |
| `UnionWith(b)` | 并集，两边的元素都要 | 包含 a 和 b 的全部元素 |
| `IntersectWith(b)` | 交集，两边都有的才要 | 只保留同时在 a、b 中的元素 |
| `ExceptWith(b)` | 差集，a 有而 b 没有的 | 从 a 中去掉 b 包含的元素 |
| `IsSubsetOf(a)` | 是否是 a 的子集 | 所有元素都在 a 中则为 `true` |

## 4.6 元组，临时把几个值捆在一起

元组不是集合，它只是临时把几个值捆在一起。有时只需要传递或存放三个相关的值，为它专门写一个类又显得太重，这时就用元组。

```csharp
var entry = ("error", "order", 1520);
Console.WriteLine(entry.Item1);
```

输出 `error`。没有起名字的元组，元素只能用 `Item1`、`Item2` 这样的名字访问，不容易看懂。给每个元素起个名字，读起来就清楚了。

```csharp
var named = (Level: "error", Module: "order", Ms: 1520);
Console.WriteLine($"{named.Level} / {named.Ms}ms");
```

输出 `error / 1520ms`。最后，可以把元组拆成几个独立的变量。

```csharp
var (level, module, ms) = named;
Console.WriteLine($"{level} {module} {ms}");
```

输出 `error order 1520`。这种写法叫解构，一行就能把三个值分别放进三个变量。

元组可以放进集合里，这样就得到了“每个元素都由几个字段组成”的列表。

```csharp
var logsTuple = new List<(string Level, string Module, int Ms)>
{
    ("info", "api", 45),
    ("error", "order", 1520),
};

foreach (var log in logsTuple)
{
    Console.WriteLine($"{log.Level} {log.Module} {log.Ms}");
}
```

输出两行，分别是 `info api 45` 和 `error order 1520`。

> **什么时候用元组，什么时候写类？** 临时数据，比如方法内部的一小段流程，用元组。要被多个地方使用、带有行为或校验的数据，写成类。后面的章节会讲类和 `record`。LogLens 里的 `AnalysisReport` 就是用 `record` 定义的，它要在多个文件之间传递。

## 4.7 ArrayList，专门存 object 的旧式集合

前面的集合都是泛型的。`List<int>` 只能放 `int`，`Dictionary<string, int>` 的键只能是字符串，编译器会替我们检查类型。

泛型是 .NET 2.0 才加入的。在那之前，集合只能存 `object`，最常见的就是 `ArrayList`。它已经很少用于新代码，但旧代码和一些老接口里还能见到，所以需要认识。`Hashtable` 是它的字典版本，同样属于旧式集合，这里不展开。

`object` 是所有类型的共同基类。`int` 这样的值放进 `object` 变量时，要先装箱，也就是把值包进一个对象里。取出来时要用强制转换拆回去，这叫拆箱。

`ArrayList` 位于 `System.Collections` 命名空间，要先写 `using`。

```csharp
using System.Collections;

var mixed = new ArrayList();
mixed.Add(1);
mixed.Add("warn");
mixed.Add(3.5);
mixed.Add(true);
Console.WriteLine(mixed.Count);

foreach (object item in mixed)
{
    Console.WriteLine($"{item} 的类型是 {item.GetType().Name}");
}
```

输出四行，依次是 `1 的类型是 Int32`、`warn 的类型是 String`、`3.5 的类型是 Double`、`True 的类型是 Boolean`。这个集合可以混着放不同类型的值，这正是它的特点。

取出来的值要自己转换。

```csharp
int first = (int)mixed[0];
Console.WriteLine(first + 1);

string text = (string)mixed[1];
Console.WriteLine(text.ToUpper());
```

输出 `2` 和 `WARN`。如果转换的类型不对，错误要等到运行时才会出现。

```csharp
try
{
    string bad = (string)mixed[0];
    Console.WriteLine(bad);
}
catch (InvalidCastException e)
{
    Console.WriteLine(e.GetType().Name);
}
```

输出 `InvalidCastException`。编译器不会提前发现这个错误，因为它无法知道 `mixed[0]` 里装的到底是什么。

下面的代码展示了装箱和拆箱，以及 `ArrayList` 的查找。

```csharp
var numbers = new ArrayList();
numbers.Add(42);
object boxed = 42;
int back = (int)boxed;
Console.WriteLine(back);
Console.WriteLine(numbers.Contains(42));
Console.WriteLine(numbers.IndexOf(42));
```

输出 `42`、`True`、`0`。`Add(42)` 时，42 被装箱；`Contains(42)` 能找到它，比较的是内容，和 4.1 节讲的相等规则一样。

增、删、改、查的方法名和 `List<T>` 基本相同。

```csharp
numbers.Insert(0, 7);
Console.WriteLine(string.Join(",", numbers.ToArray()));
numbers.RemoveAt(0);
numbers.Remove(42);
Console.WriteLine(numbers.Count);
```

输出 `7,42` 和 `0`。

### 和泛型集合对比

| 比较项 | `ArrayList` | `List<object>` | `List<int>` |
| --- | --- | --- | --- |
| 能放什么 | 任何类型，混着放 | 任何类型，混着放 | 只能放 `int` |
| 取出时要不要转换 | 要，如 `(int)` | 要 | 不要 |
| 类型错误何时发现 | 运行时 | 运行时 | 编译时 |
| 值类型的存取 | 每次都装箱或拆箱 | 每次都装箱或拆箱 | 不装箱 |
| 命名空间 | `System.Collections` | `System.Collections.Generic` | `System.Collections.Generic` |

下面这行代码在编译时就会报错。

```csharp
int n = mixed[0];   // 编译错误 CS0266：无法隐式转换 object 到 int
```

本教材的项目开启了可空检查（`<Nullable>enable</Nullable>`），所以对 `ArrayList` 的元素做强制转换时，编译器还会给出 CS8600、CS8602 这类警告。它的意思是 `ArrayList` 的 `[]` 返回的是可能为 `null` 的 `object`，而且它没有告诉你里面到底是什么类型。这也是非泛型集合不好用的原因之一。

新代码里用 `List<T>` 就可以。遇到 `ArrayList` 的时候，多半是在读旧代码，或者要把它改写成泛型版本。

## 4.8 StringBuilder，可以修改的文本

字符串一旦创建，内容就不能改。`ToUpper()` 返回的是一个新字符串，原来的字符串没有变。

```csharp
string s = "info";
s.ToUpper();
Console.WriteLine(s);

string t = s.ToUpper();
Console.WriteLine(t);
```

输出 `info` 和 `INFO`。

`StringBuilder` 是一个可以原地修改的字符序列，位于 `System.Text` 命名空间。严格说，它不是集合，它没有实现 `IEnumerable<T>`，不能 `foreach`，也没有 `Count`，要用 `Length` 取得长度。但它和集合一样，是用来装东西、并且可以增、删、改的容器，装的是字符。所以把它放在集合这一章的最后讲。

```csharp
using System.Text;

var sb = new StringBuilder();
sb.Append("info");
sb.Append(' ');
sb.Append(45);
Console.WriteLine(sb.ToString());
Console.WriteLine(sb.Length);
```

输出 `info 45` 和 `7`。接着修改它。

```csharp
sb.Insert(0, "[LOG] ");
Console.WriteLine(sb.ToString());
sb.Replace("info", "INFO");
Console.WriteLine(sb.ToString());
sb.Remove(0, 6);
Console.WriteLine(sb.ToString());
Console.WriteLine(sb[0]);
sb.Clear();
Console.WriteLine(sb.Length);
```

输出依次是 `[LOG] info 45`、`[LOG] INFO 45`、`INFO 45`、`I`、`0`。

| 方法或属性 | 作用 |
| --- | --- |
| `Append(x)` | 在末尾追加，`x` 可以是字符串、字符或数字 |
| `AppendLine(x)` | 追加内容，并在末尾换行 |
| `Insert(i, x)` | 在下标 `i` 的位置插入 |
| `Replace(旧, 新)` | 把所有“旧”的内容换成“新” |
| `Remove(i, n)` | 从下标 `i` 开始，删除 `n` 个字符 |
| `Clear()` | 清空全部内容 |
| `ToString()` | 得到普通字符串 |
| `Length` | 当前的字符数 |
| `sb[i]` | 取出下标 `i` 的字符 |

`Append` 的返回值就是 `StringBuilder` 自己，所以可以连着写。

```csharp
Console.WriteLine(new StringBuilder().Append("a").Append("b").ToString());
```

输出 `ab`。

### 为什么不用 `+=` 反复拼接

下面两段代码的结果相同，区别在于做法。

```csharp
string line = "";
var builder = new StringBuilder();
for (int i = 0; i < 3; i++)
{
    line += i.ToString();
    builder.Append(i);
}
Console.WriteLine(line);
Console.WriteLine(builder.ToString());
Console.WriteLine(line == builder.ToString());
```

输出 `012`、`012`、`True`。每执行一次 `+=`，都会创建一个新字符串，并把旧的内容复制过去。循环次数少的时候看不出差别，循环次数多、文本很长时，反复复制会很慢。`StringBuilder` 内部有一块可以继续写入的缓冲区，追加时不必每次都重新复制。

一条原则是拼接一两次，用插值字符串 `$"..."` 就够了。在循环里不断拼接，或者要生成多行报告，用 `StringBuilder`。

## 4.9 动手，完整程序

下面的程序把本章的内容放在一起，其中 `List` 存放日志，`Dictionary` 统计级别数量，`HashSet` 去重模块名，最后用 `StringBuilder` 拼出报告。日志数据先写在代码里，后面的章节会改为从文件读取。

```csharp
// ============================================
// 第 4 章 · 集合
// 运行方式：dotnet run
// ============================================

using System.Text;

// 1) 准备一批日志（实际场景从文件读取，后面的章节会做）
var logs = new List<(string Level, string Module, int Ms)>
{
    ("info", "api", 45),
    ("info", "api", 62),
    ("warn", "api", 968),
    ("error", "order", 1520),
    ("info", "order", 23),
    ("error", "order", 2815),
    ("info", "cache", 12),
    ("warn", "order", 680),
};

var report = new StringBuilder();
report.AppendLine($"共 {logs.Count} 条日志");
report.AppendLine();

// 2) 级别计数：Dictionary 记录每个级别出现的次数
var levelCounts = new Dictionary<string, int>();
foreach (var log in logs)
{
    if (levelCounts.ContainsKey(log.Level))
    {
        levelCounts[log.Level]++;
    }
    else
    {
        levelCounts[log.Level] = 1;
    }
}

report.AppendLine("级别分布：");
string[] levelOrder = { "info", "warn", "error" };
foreach (var level in levelOrder)
{
    if (levelCounts.TryGetValue(level, out var count))
    {
        report.AppendLine($"  {level,-6}{count} 条");
    }
}
report.AppendLine();

// 3) 模块去重：HashSet 只保留不重复的模块名，List 记下第一次出现的顺序
var seen = new HashSet<string>();
var modules = new List<string>();
foreach (var log in logs)
{
    if (seen.Add(log.Module))
    {
        modules.Add(log.Module);
    }
}
report.AppendLine($"涉及 {seen.Count} 个模块");
report.AppendLine();

// 4) 最慢的一条：用循环找最大值
var slowest = logs[0];
foreach (var log in logs)
{
    if (log.Ms > slowest.Ms)
    {
        slowest = log;
    }
}
report.AppendLine($"最慢的一条：{slowest.Ms} ms，{slowest.Module}，{slowest.Level}");
report.AppendLine();

// 5) 每个模块的问题数（warn 和 error）
var problems = new Dictionary<string, int>();
foreach (var log in logs)
{
    if (log.Level != "warn" && log.Level != "error")
    {
        continue;
    }
    problems.TryGetValue(log.Module, out var current);
    problems[log.Module] = current + 1;
}

report.AppendLine("各模块问题数：");
foreach (var module in modules)
{
    if (problems.TryGetValue(module, out var n))
    {
        report.AppendLine($"  {module,-6}{n} 个");
    }
}

Console.Write(report.ToString());
```

输出如下。

```text
共 8 条日志

级别分布：
  info  4 条
  warn  2 条
  error 2 条

涉及 3 个模块

最慢的一条：2815 ms，order，error

各模块问题数：
  api   1 个
  order 3 个
```

### 逐段解释

| 代码 | 说明 |
| --- | --- |
| `using System.Text;` | `StringBuilder` 所在的命名空间，要写在程序最前面 |
| `List<(string Level, string Module, int Ms)>` | 装元组的列表，三个字段都有名字 |
| `report.AppendLine(...)` | 把一行文字追加到报告末尾，最后一次性输出 |
| `levelCounts[log.Level]` 的计数 | 第一次出现时写入 1，之后每次加 1 |
| `string[] levelOrder` | 决定输出的顺序。字典的遍历顺序不保证，所以按固定的顺序去取值 |
| `seen.Add(log.Module)` | `Add` 在第一次加入时返回 `true`，据此把模块名记进 `modules` 列表 |
| `modules` 列表 | `HashSet` 不保证顺序，需要稳定的输出顺序时，用列表记下第一次出现的顺序 |
| `problems.TryGetValue(log.Module, out var current)` | 取出当前的数量，没有时为 0，再加 1 |
| `continue` | 跳过不需要统计的日志，直接进入下一轮 |
| `{level,-6}` | 左对齐，占 6 个字符宽，[第 2 章](/chapter/02)讲过 |

## 4.10 常见错误

| 异常或报错 | 原因 | 怎么改 |
| --- | --- | --- |
| `IndexOutOfRangeException` | 数组下标超出范围 | 下标从 0 开始，最大是 `Length - 1` |
| `ArgumentOutOfRangeException` | `List<T>` 下标超出范围，或 `RemoveAt` 的下标越界 | 用 `Count` 判断，`Count - 1` 是最后一个下标 |
| `KeyNotFoundException` | 字典取了不存在的键 | 用 `TryGetValue`，或先用 `ContainsKey` 判断 |
| `ArgumentException`，来自 `Add` | 字典的键重复 | 改用索引器赋值，或先用 `ContainsKey` 判断 |
| `ArgumentNullException` | 字典的键是 `null` | 放入前检查键是否为 `null` |
| `InvalidCastException` | 从 `ArrayList` 取出的值，强制转换成了错误的类型 | 改用 `List<T>`；转换前用 `is` 判断类型 |
| `InvalidOperationException`，遍历时修改 | 在 `foreach` 中增删同一个集合 | 遍历一个副本，或收集完再修改 |
| 结果少删了几条，但没有报错 | 用 `for` 从前往后删除，下标错位 | 从后往前删，或用 `RemoveAll` |
| `CS0029` | 元组的值和声明的类型不符 | 检查每个位置的类型 |
| `CS0266` | 把 `object` 直接赋给 `int` 等具体类型 | 显式转换，或改用泛型集合 |
| `CS0428` | 数组上写了不带括号的 `.Count` | 数组用 `Length` |
| `CS1061` | `List<T>` 上写了 `.Length` | `List<T>` 用 `Count` |
| `CS1656` | 给 `foreach` 的变量赋值 | 需要修改元素时，用 `for` 配合下标 |

### 遍历时修改集合

下面的代码会抛出 `InvalidOperationException`。

```csharp
foreach (var log in logs)
{
    if (log.Level == "debug")
    {
        logs.Remove(log);
    }
}
```

`foreach` 正在遍历 `logs`，中途又改了它，遍历器就无法继续。正确的写法有两种。第一种是遍历一个副本，然后修改原来的集合。

```csharp
var copy = new List<(string Level, string Module, int Ms)>(logs);
foreach (var log in copy)
{
    if (log.Level == "debug")
    {
        logs.Remove(log);
    }
}
```

第二种是先把要删的元素收集到另一个列表里，遍历结束后再统一删除。如果只是要按条件删除，`RemoveAll` 最省事。

### 删除时漏掉元素

4.3 节已经讲过，从前往后用 `for` 删除会漏掉元素。这种错误不会抛出异常，只是结果不对，所以要特别留意。删除的时候，记住两个办法，一是从后往前删，二是用 `RemoveAll`。，或者用 `RemoveAll`。

```csharp
        problems++;
    }
}
Console.WriteLine(kept);
Console.WriteLine(problems);
```

输出 `7` 和 `4`。

```csharp
var items = new ArrayList { 1, "two", 3, "four", 5 };
int sum = 0;
var words = new StringBuilder();
foreach (object item in items)
{
    if (item is int n)
    {
        sum += n;
    }
    else if (item is string s)
    {
        if (words.Length > 0)
        {
            words.Append(", ");
        }
        words.Append(s);
    }
}
Console.WriteLine($"int 之和 {sum}");
Console.WriteLine($"字符串 {words}");
```
