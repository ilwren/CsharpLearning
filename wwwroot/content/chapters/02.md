## 2.1 变量是带标签的盒子

```csharp
int count = 42;
```

这行代码可以这样读。准备一个装整数的盒子，贴上标签 `count`，往里放 42。

拆开看，它由四部分组成。

| 部分 | 名称 | 作用 |
| --- | --- | --- |
| `int` | 类型 | 这个盒子只能装整数 |
| `count` | 变量名 | 以后用这个名字取出盒子里的东西 |
| `=` | 赋值 | 把右边的值放进左边的盒子 |
| `42` | 值 | 实际装进去的内容 |

变量的内容可以改。下面的代码先读出 42，再加上 8，把结果放回同一个盒子。

```csharp
Console.WriteLine(count);      // 42
count = count + 8;             // 取出 42，加 8，再放回去
Console.WriteLine(count);      // 50
```

`count = count + 8;` 作为数学等式是不成立的，作为赋值语句却很常见。读的时候先算右边，再把结果放进左边的盒子。

## 2.2 整数有八种大小，怎么选

C# 的整数类型一共有八种。它们的区别在于能装多大的数，以及能不能装负数。

| 类型 | 最小值 | 最大值 | 占用字节数 |
| --- | --- | --- | --- |
| `sbyte` | -128 | 127 | 1 |
| `byte` | 0 | 255 | 1 |
| `short` | -32768 | 32767 | 2 |
| `ushort` | 0 | 65535 | 2 |
| `int` | -2147483648 | 2147483647 | 4 |
| `uint` | 0 | 4294967295 | 4 |
| `long` | -9223372036854775808 | 9223372036854775807 | 8 |
| `ulong` | 0 | 18446744073709551615 | 8 |

这张表不需要背。写代码时，大多数整数用 `int` 就够了，它能表示约 21 亿。行数、耗时的毫秒数、重试次数，都远远用不到这么大的范围。

文件大小、时间戳这类可能超过 21 亿的数，用 `long`。`byte` 常用来读取二进制数据，本书后面的章节几乎用不到，知道它存在就行。

直接写在代码里的整数，比如 `42`，默认是 `int`。数字很长时可以用下划线分组，方便阅读。

```csharp
long fileSize = 8_000_000_000;      // 下划线只是为了好读，编译后和不写一样
```

这行代码必须用 `long`。`8_000_000_000` 超过了 `int` 的最大值，放进 `int` 会被编译器拒绝。

## 2.3 小数与字符

### 三种小数类型

C# 有三种常用的小数类型。它们在精度、占用和写法上不一样。

| 类型 | 大约有效位数 | 占用字节数 | 字面量写法 | 适合做什么 |
| --- | --- | --- | --- | --- |
| `float` | 7 位 | 4 | 后面加 `f`，如 `1.5f` | 图形、游戏中的大量坐标，本书很少用 |
| `double` | 15 到 16 位 | 8 | 直接写，如 `1.52` | 测量值、统计结果、科学计算 |
| `decimal` | 28 到 29 位 | 16 | 后面加 `m`，如 `19.99m` | 金额、账单等必须精确的十进制数 |

先看 `double` 的表现。

```csharp
Console.WriteLine(0.1 + 0.2);          // 0.30000000000000004
Console.WriteLine(0.1 + 0.2 == 0.3);   // False
Console.WriteLine(Math.Abs((0.1 + 0.2) - 0.3) < 1e-9);   // True
```

十进制的 `0.1` 在二进制里除不尽，计算机只能存一个近似值。加起来以后，误差会露出来。几乎所有用二进制存小数的语言都会遇到这个问题。

`decimal` 按十进制存数，所以 `0.1` 是精确的。

```csharp
Console.WriteLine(0.1m + 0.2m);        // 0.3
Console.WriteLine(0.1 * 3);            // 0.30000000000000004
Console.WriteLine(0.1m * 3);           // 0.3
```

处理金额时，写成 `decimal`，字面量后面要加 `m`。

```csharp
decimal price = 19.99m;
decimal total = price * 3;
Console.WriteLine(total);              // 59.97
```

`1.0 / 3` 这样除不尽的结果，显示位数也能看出三种类型的差别。

```csharp
Console.WriteLine(1.0 / 3);            // 0.3333333333333333
Console.WriteLine(1.0f / 3);           // 0.33333334
Console.WriteLine(1.0m / 3);           // 0.3333333333333333333333333333
```

这里的规则很简单。展示给人看的 `double` 没有问题，格式化时会四舍五入。需要判断两个小数是否相等时，要比较它们的差是否足够小，不能直接用 `==`。钱一律用 `decimal`。

`double` 超出范围时不会报错，结果会变成 `Infinity`。

```csharp
Console.WriteLine(1e308 * 10);         // Infinity
```

### 字符类型 char

`char` 表示一个字符，字面量用单引号括起来。

```csharp
char c = 'A';
Console.WriteLine(c);                  // A
Console.WriteLine(c + 1);              // 66
Console.WriteLine((char)(c + 1));      // B
```

`c + 1` 得到的是数字 66，因为字符在计算机里本来就是编号。`'A'` 的编号是 65，加 1 就是 66。想要得到字符，需要用 `(char)` 转回去。

中文字符也是一个 `char`。

```csharp
Console.WriteLine('中');               // 中
Console.WriteLine('\u4E2D');           // 中
Console.WriteLine((int)'中');          // 20013
Console.WriteLine("中".Length);        // 1
```

`\u4E2D` 是用编码写字符的方式，`4E2D` 就是“中”的编号。平时直接写字符就可以。

有些字符比较少见，比如部分 emoji，一个 `char` 放不下，要用两个 `char` 拼在一起。

```csharp
Console.WriteLine("😀".Length);                        // 2
Console.WriteLine(char.IsSurrogate("😀"[0]));          // True
```

这种情况很少在入门代码里遇到。知道它存在，就不会在字符串长度上感到意外。

`char` 还有几个常用的判断方法。

```csharp
Console.WriteLine(char.IsDigit('5'));  // True
Console.WriteLine(char.IsLetter('中')); // True
```

## 2.4 布尔值与默认值

`bool` 只有两个值，`true` 和 `false`。它是后面所有判断语句的基础，[第 3 章](/chapter/03)会大量用到。

```csharp
bool isSlow = 1520 > 1000;             // true
Console.WriteLine(isSlow);             // True
```

C# 的每种类型都有一个默认值。变量声明后不给初值，编译器不会替你填。`default` 关键字可以取出某个类型的默认值。

| 类型 | 默认值 |
| --- | --- |
| `int` | `0` |
| `bool` | `False` |
| `char` | `'\0'`，编号为 0 的空字符 |
| `string` | `null` |
| `DateTime` | 公元 1 年 1 月 1 日 |

```csharp
Console.WriteLine(default(int));       // 0
Console.WriteLine(default(bool));      // False
Console.WriteLine(default(DateTime).Year);   // 1

int dflt = default;                    // 写 default 时，编译器会根据左边的类型推断
Console.WriteLine(dflt);               // 0
```

### `var`，让编译器推断类型

```csharp
int count = 42;        // 显式写出类型
var count2 = 42;       // 让编译器推断，它也知道这是 int
```

`var` 只是让编译器来写类型，类型由右边的值决定。上面两行的效果完全相同。

本书的习惯如下。

```csharp
var items = new List<string>();       // 右边已经写了类型，左边不必重复
var name = Console.ReadLine();        // 一眼能看出是 string
int total = 0;                        // 简单的字面量，直接写清楚更直观
```

`var` 一旦推断出类型，就不能再换成别的类型。

```csharp
var x = 1;
x = "a";                              // 编译错误：x 是 int，不能放字符串
```

这个错误的报错原文见 [2.14 节](#s2-14)。

### 常量是不会变的值

```csharp
const int MaxRows = 20_000;           // 数字里的下划线只是方便阅读
const string AppName = "LogLens";
```

`const` 表示这个值在编译时就已经确定，程序运行期间不会改变。它的主要用途是替代“魔法数字”。

```csharp
if (rows > 20000) { ... }             // 20000 是什么意思？从哪来的？
if (rows > MaxRows) { ... }           // 名字本身就说明了意图
```

### 命名规范

下面是本书使用的命名规则。它们是 C# 社区的通用约定，团队协作时也会用到。

| 对象 | 规范 | 例子 |
| --- | --- | --- |
| 局部变量、参数 | 小驼峰 camelCase | `logCount`、`selectedRow` |
| 常量 | 大驼峰 PascalCase | `MaxRows`、`DefaultTimeout` |
| 方法、类、属性 | 大驼峰 PascalCase | `Analyze()`、`LogEvent`、`IsRunning` |
| 接口 | 以 `I` 开头 | `ILogParser` |

名字要能看出用途。`int a` 过几个月自己也可能看不懂，`int errorCount` 一看就明白。本书的类名与 API 用英文，注释和文档用中文。

## 2.5 运算与溢出

### 基本运算

```csharp
int a = 7;
int b = 2;

Console.WriteLine(a + b);      // 9
Console.WriteLine(a - b);      // 5
Console.WriteLine(a * b);      // 14
Console.WriteLine(a / b);      // 3
Console.WriteLine(a % b);      // 1，取余数
```

`%` 取的是除法的余数。判断一个数是不是偶数，可以写 `n % 2 == 0`。

### 陷阱，整数相除会丢掉小数

```csharp
Console.WriteLine(7 / 2);              // 3
Console.WriteLine(7 / 2.0);            // 3.5
Console.WriteLine((double)7 / 2);      // 3.5
```

两个操作数都是 `int`，结果也是 `int`，小数部分直接被截掉，不会四舍五入。只要其中一个是小数，或者先把其中一个转成 `double`，结果就保留了小数。

统计百分比时最容易踩到这个坑。下面的代码在错误数和总数都是整数时，结果永远是 0。

```csharp
int errors = 3;
int total = 120;
Console.WriteLine(errors / total * 100);          // 0
Console.WriteLine(errors / (double)total * 100);  // 2.5
```

先转成 `double` 再相除，就能得到正确的比例。

### 溢出，超出范围会绕回去

整数超出范围，运行时默认会悄悄绕回去。

```csharp
int big = int.MaxValue;
big++;
Console.WriteLine(big);                // -2147483648
```

`int.MaxValue` 是 `int` 能装的最大值。再加 1，结果绕到了最小值。程序不会报错，只会得到一个错误的数。

如果希望溢出时直接抛出异常，可以用 `checked`。

```csharp
int a = int.MaxValue;
try
{
    checked
    {
        int b = a + 1;
        Console.WriteLine(b);
    }
}
catch (OverflowException e)
{
    Console.WriteLine($"{e.GetType().Name}: {e.Message}");
}
// 输出：OverflowException: Arithmetic operation resulted in an overflow.
```

异常信息的文字取决于系统语言，这里是英文原文。`unchecked` 则表示明确允许绕回，它和默认行为相同。

```csharp
int wrapped = unchecked(a + 1);
Console.WriteLine(wrapped);            // -2147483648
```

编译器能看出来的溢出，会直接报错。下面这行中，两个数都是常量，编译器在编译时就算出了结果，发现它超出了 `int` 的范围。

```csharp
int x = int.MaxValue + 1;              // 编译错误 CS0220
```

同样，把字面量直接赋给一个装不下它的类型，也会报错。

```csharp
byte b = 300;                          // 编译错误 CS0031，byte 最大是 255
```

## 2.6 常用运算符

前面已经用过 `+`、`==`、`&&` 这些符号，它们都是运算符。这一节把最常用的运算符分一下类，讲清楚优先级，再讲几个容易出错的地方。

### 按用途分类

| 类别 | 运算符 | 作用 |
| --- | --- | --- |
| 算术 | `+`、`-`、`*`、`/`、`%` | 加、减、乘、除，以及取余数 |
| 比较 | `==`、`!=`、`<`、`>`、`<=`、`>=` | 比较两个值，结果是 `bool` |
| 逻辑 | `&&`、`\|\|`、`!` | 并且、或者、取反 |
| 赋值 | `=`、`+=`、`-=`、`*=`、`/=`、`%=` | 把右边的值放进左边 |
| 自增自减 | `++`、`--` | 加 1 或减 1 |
| 条件 | `?:` | 根据条件二选一 |
| 空合并 | `??` | 左边是 null 时取右边的值 |
| 成员访问 | `.`、`?.`、`[]`、`()` | 访问成员、取下标、调用方法 |

### 优先级，先算哪一步

一个式子里有多个运算符时，优先级高的先算。下表从上到下，优先级依次降低。同一行的运算符优先级相同。

| 优先级 | 运算符 |
| --- | --- |
| 1 | `()`、`.`、`[]`、`x++`、`x--` |
| 2 | `+`、`-`、`!`、`++x`、`--x`、`(类型)` |
| 3 | `*`、`/`、`%` |
| 4 | `+`、`-` |
| 5 | `<`、`>`、`<=`、`>=` |
| 6 | `==`、`!=` |
| 7 | `&&` |
| 8 | `\|\|` |
| 9 | `??` |
| 10 | `?:` |
| 11 | `=`、`+=`、`-=` 等 |

同一级别的多数运算符从左往右算。

```csharp
Console.WriteLine(2 + 3 * 4);             // 14，先乘后加
Console.WriteLine((2 + 3) * 4);           // 20，括号里的先算
Console.WriteLine(10 - 4 - 3);            // 3，同一级从左往右，相当于 (10 - 4) - 3
Console.WriteLine(2 * 3 % 4);             // 2，先算 2 * 3 得 6，再算 6 % 4
```

如果拿不准顺序，就加括号。括号不会让代码出错，只会让读的人少猜一步。

### `+` 的陷阱，既是加法也是拼接

`+` 从左往右算。左边的两个值都是数字时，它做加法；只要其中有一边是字符串，它就做拼接。

```csharp
Console.WriteLine(1 + 2 + "x");           // 3x，先算 1 + 2 得 3，再拼上 "x"
Console.WriteLine("x" + 1 + 2);           // x12，先拼成 "x1"，再拼成 "x12"
Console.WriteLine("x" + (1 + 2));         // x3，括号让 1 + 2 先算
```

### 复合赋值与自增自减

```csharp
int x = 10;
x += 5;                                   // 等价于 x = x + 5，结果 15
x *= 2;                                   // 结果 30
x %= 7;                                   // 结果 2
```

`+=`、`-=`、`*=`、`/=`、`%=` 都是“先算，再放回去”的简写。

`++` 和 `--` 表示加 1 与减 1。它们写在变量的前面还是后面，结果会不同。

```csharp
int i = 5;
Console.WriteLine(i++);                   // 5，先用旧值，然后再加 1
Console.WriteLine(i);                     // 6
Console.WriteLine(++i);                   // 7，先加 1，再用新值
```

单独写成一行时，`i++` 和 `++i` 的效果一样。只有放进别的式子里，两者才有区别。`--` 的规则完全相同。

### 比较，`=` 与 `==` 不要混用

`=` 是赋值，`==` 是比较相等。`!=` 表示不相等。比较的结果都是 `bool`。

```csharp
int x = 1;
if (x = 5) { }                            // 编译错误 CS0029，if 需要 bool，而 x = 5 得到的是 int
```

```csharp
Console.WriteLine(1.0 == 1);              // True，值相等就算相等
Console.WriteLine("abc" == "abc");        // True，比较的是内容
Console.WriteLine("abc" != "ABC");        // True，大小写不同
```

字符串的 `==` 默认区分大小写。要忽略大小写，用 `StringComparison.OrdinalIgnoreCase`，见 [2.8 节](#s2-8)。

### 逻辑运算与短路

`&&` 和 `||` 分别表示“并且”和“或者”，`!` 把 `bool` 取反。`&&` 和 `||` 两边都要是 `bool`。

```csharp
bool Touch(string tag)
{
    Console.WriteLine($"执行 {tag}");
    return false;
}

Console.WriteLine(Touch("A") && Touch("B"));   // 只打印“执行 A”，结果 False
Console.WriteLine(Touch("C") || Touch("D"));   // 打印“执行 C”和“执行 D”，结果 False
```

`Touch` 只是为了演示执行过程，函数的写法后面再讲。第一行里，左边的 `Touch("A")` 已经是 false，`&&` 就不再执行右边，`Touch("B")` 根本没有被调用。这叫短路。`||` 也一样，左边是 true 时右边不会执行。

短路让我们能先检查，再访问。

```csharp
string? s = null;
if (s != null && s.Length > 0)
{
    Console.WriteLine("有内容");
}
```

`s` 是 null 时，`s != null` 得到 false，`s.Length` 就不会被执行，程序不会崩溃。

`&` 和 `|` 也能用在 `bool` 上，但两边都会执行，没有短路。

```csharp
string? s = null;
if (s != null & s.Length > 0) { }         // s 为 null 时，s.Length 仍然会执行，运行时抛出 NullReferenceException
```

判断条件时，用 `&&` 和 `||`。`&` 和 `|` 用在 `bool` 上时两边都会执行，平时很少用。

### 三元运算符，二选一

问号前面是条件。条件成立时取问号后面、冒号前面的值，否则取冒号后面的值。它是 `if` 的简短写法，`if` 在[第 3 章](/chapter/03)才讲。

```csharp
int count = 0;
string tag = count > 0 ? "有" : "无";    // count 大于 0 时是“有”，否则是“无”
Console.WriteLine(tag);                   // 无
```

运算符还能由类自己定义，这叫运算符重载，放到后面讲类的时候再说。

## 2.7 转换与舍入

数字类型之间经常需要互相转换，有的会自动完成，有的要自己写。

### 显式转换，强制截断

把大类型转成小类型，或者把小数转成整数，要用括号写出类型，这叫显式转换。

```csharp
double d = 3.9;
Console.WriteLine((int)d);             // 3，直接截掉小数，不是四舍五入
Console.WriteLine((int)-3.9);          // -3，朝 0 的方向截断
```

如果数值超出目标类型的范围，显式转换不会报错，只会得到一个没有意义的数。

```csharp
long big = 5_000_000_000;
int back = (int)big;
Console.WriteLine(back);               // 705032704
```

这个结果没有任何提示。所以写显式转换之前，先确认数值在范围之内。

### 隐式转换，小类型放进大类型

反方向是安全的。`int` 能装进 `long`，编译器会自动完成，不需要写括号。

```csharp
int i = 42;
long l = i;
Console.WriteLine(l);                  // 42
```

大类型放进小类型就不行了，编译器会要求你写出强制转换。

```csharp
long big = 5;
int i = big;                           // 编译错误 CS0266
```

报错的完整原文见 [2.14 节](#s2-14)。这时可以写成 `int i = (int)big;`，但要先想清楚，超出范围的部分会发生什么。

### 舍入，Round、Floor、Ceiling 与 Truncate

把小数变成整数，有好几种方式，它们的结果不同。

```csharp
Console.WriteLine(Math.Round(2.5));                       // 2
Console.WriteLine(Math.Round(3.5));                       // 4
Console.WriteLine(Math.Round(2.5, MidpointRounding.AwayFromZero));   // 3
Console.WriteLine(Math.Floor(2.7));                       // 2，向下取整
Console.WriteLine(Math.Ceiling(2.1));                     // 3，向上取整
Console.WriteLine(Math.Truncate(-2.7));                   // -2，朝 0 截断
Console.WriteLine(Convert.ToInt32(2.5));                  // 2
```

`Math.Round` 默认遇到恰好在中间的数（比如 2.5）时，会舍入到最近的偶数，所以 2.5 得到 2，3.5 得到 4。这叫银行家舍入，目的是让大量数据累加时偏差不会总朝一个方向。如果想要“遇到 .5 就进位”，要像上面那样指定 `MidpointRounding.AwayFromZero`。

`Convert.ToInt32` 对小数做的也是这种舍入。

## 2.8 字符串，拼接、插值与格式化

字符串是 `string` 类型，用双引号括起来。它是你以后用得最多的类型之一。字符串处理的更多内容，后面的章节会陆续讲到，这里先掌握日常写法。

### 拼接与插值

最直接的办法是用 `+` 拼接。

```csharp
var name = "小明";
var msg = "你好，" + name + "！";      // 你好，小明！
```

更推荐的写法是插值。字符串前面加 `$`，花括号里可以写任何表达式。

```csharp
var msg2 = $"你好，{name}！";           // 效果相同，但读起来清楚得多

int count = 1520;
Console.WriteLine($"耗时 {count} ms，约 {count / 1000.0:F2} 秒");
// 耗时 1520 ms，约 1.52 秒
```

### 格式化，`{值,宽度}` 与 `{值:格式}`

花括号里用冒号加格式串，可以控制数字的显示方式。这一点在做报表时非常有用。

下表以 `1520.5` 为例。

| 写法 | 显示效果 | 说明 |
| --- | --- | --- |
| `{x:N0}` | `1,520` | 千分位，不保留小数 |
| `{x:N0}`（`x` 为 1520.6） | `1,521` | 同一个格式，四舍五入的结果不同 |
| `{x:N2}` | `1,520.50` | 千分位，两位小数 |
| `{x:F2}` | `1520.50` | 两位小数，没有千分位 |
| `{x:P1}` | `152,050.0%` | 百分比，值乘以 100 再显示 |
| `{x,8}` | `  1520.5` | 右对齐，占 8 个字符宽 |
| `{x,-8}` | `1520.5  ` | 左对齐，占 8 个字符宽 |

`N0` 对 1520.5 得到 `1,520`，而不是 `1,521`。恰好在中间的数会舍入到偶数，和 2.7 节的 `Math.Round` 一致。

千分位用 `N` 开头的格式，`N` 来自 Number。`F` 开头的格式只控制小数位数，不加千分位。这两个字母混淆了，是常见的错误之一，2.14 节会再提到。

百分比格式会把数值乘以 100 再显示，所以 `0.5` 显示为 `50.0%`，`1` 显示为 `100.0%`。百分号前是否带空格，取决于系统的区域设置，中文环境下通常不带。

```csharp
Console.WriteLine($"{count,8}|");      //     1520|
Console.WriteLine($"{count,-8}|");     // 1520    |
```

日期时间也用同样的格式语法。

```csharp
var when = new DateTimeOffset(2026, 11, 1, 21, 30, 0, TimeSpan.FromHours(8));
Console.WriteLine($"{when:yyyy-MM-dd HH:mm:ss}");     // 2026-11-01 21:30:00
Console.WriteLine($"{when:yyyy年M月d日 HH时mm分}");   // 2026年11月1日 21时30分
```

时间格式的细节放在 2.11 节。

### 常用字符串方法

下面的代码都以同一行文本为例。

```csharp
var line = "  2026-11-01 ERROR 连接超时  ";

Console.WriteLine(line.Trim());                 // 2026-11-01 ERROR 连接超时
Console.WriteLine(line.Length);                 // 25，包括前后的空格
Console.WriteLine(line.Contains("ERROR"));      // True
Console.WriteLine(line.Replace("ERROR", "错误"));
Console.WriteLine(line.Trim().Split(' ').Length);       // 3
Console.WriteLine($"[{line.PadRight(30)}]");            // 右边补空格到 30 个字符
Console.WriteLine(line.Trim().Substring(2, 10));        // 26-11-01 E
```

`Trim` 去掉前后的空白，`Length` 数字符个数，`Contains` 判断是否包含某段文字，`Replace` 替换文字，`Split` 按分隔符切开，`PadRight` 在右边补空格，`Substring` 截取一段。`Split` 返回的是数组，[第 4 章](/chapter/04)会讲数组和集合。

### 字符串是不可变的

字符串方法不会修改原字符串，它会返回一个新字符串。

```csharp
var t = "  ERROR  ";
t.Trim();                              // 返回了新字符串，但没有人接住它
Console.WriteLine($"[{t}]");           // [  ERROR  ]

t = t.Trim();                          // 把新字符串赋回 t
Console.WriteLine($"[{t}]");           // [ERROR]
```

这是字符串最常见的误解。调用方法之后，要么把结果赋值回去，要么把它直接用在别处。

### 比较字符串，注意大小写

```csharp
Console.WriteLine("A" == "a");         // False，默认区分大小写
Console.WriteLine(string.Equals("ERROR", "error", StringComparison.OrdinalIgnoreCase));  // True
Console.WriteLine("连接超时".Contains("超时", StringComparison.OrdinalIgnoreCase));      // True
```

日志里的级别、模块名，大小写往往不统一，比较时加上 `StringComparison.OrdinalIgnoreCase`，就不用担心大小写问题。LogLens 的日志级别判断也是这样写的，2.16 节有对应的位置。

## 2.9 null 与可空值类型

### null 是什么

`null` 表示“这里什么都没有”。字符串变量可以是 `null`，但对它做操作会出错。

```csharp
string? name = null;
Console.WriteLine(name.Length);
```

这段代码在编译时会给出警告，运行时会崩溃，抛出 `NullReferenceException`。它的中文名叫空引用异常，口语里常叫“空指针”。它是 C# 程序最常见的崩溃原因之一。

```text
NullReferenceException: Object reference not set to an instance of an object.
```

异常信息的文字取决于系统语言，这里是英文原文。

### 可空标注，提前发现问题

项目文件里的 `<Nullable>enable</Nullable>` 会打开可空引用检查。在这个设置下，编译器区分两种字符串。

```csharp
string a = "abc";                      // 不可为 null：编译器保证它不是 null
string? b = null;                      // 可为 null：提醒你这里可能是 null
```

对 `b` 直接取长度，编译器会给出警告。

```csharp
string? b = null;
Console.WriteLine(b.Length);           // 警告 CS8602：解引用可能出现空引用
```

这是警告，不会阻止编译。它的作用是提醒你先做判断。判断之后，编译器就知道这里一定不是 `null`。

```csharp
if (b != null)
{
    Console.WriteLine(b.Length);       // 这里编译器知道 b 不是 null
}
```

### 三个常用工具

```csharp
string? b = null;

// 1) ??：左边是 null 时，取右边的值作为兜底
var display = b ?? "（未填写）";
Console.WriteLine(display);            // （未填写）

// 2) ?.：左边是 null 时，整个访问直接得到 null，不会崩溃
var len = b?.Length ?? 0;
Console.WriteLine(len);                // 0

// 3) string.IsNullOrWhiteSpace：同时挡住 null、空字符串和纯空白
Console.WriteLine(string.IsNullOrWhiteSpace(null));   // True
Console.WriteLine(string.IsNullOrWhiteSpace(""));     // True
Console.WriteLine(string.IsNullOrWhiteSpace("   "));  // True
Console.WriteLine(string.IsNullOrEmpty("   "));       // False
```

`IsNullOrEmpty` 只挡住 `null` 和空字符串，不挡纯空白。判断用户有没有真正输入内容，用 `IsNullOrWhiteSpace` 更稳妥。

`null`、`""` 和 `"  "` 是三种不同的值，初学者常常混在一起。

### 可空值类型 `int?`

`int` 本身不能是 `null`。如果想表达“可能没有数字”，要用 `int?`，它叫可空值类型。

```csharp
int? maybe = null;
Console.WriteLine(maybe.HasValue);             // False，有没有值
Console.WriteLine(maybe.GetValueOrDefault());  // 0，没有值时给出默认值
Console.WriteLine(maybe is null);              // True
Console.WriteLine(maybe ?? -1);                // -1

int? some = 5;
Console.WriteLine(some.HasValue);              // True
Console.WriteLine(some.Value);                 // 5
Console.WriteLine(some + 1);                   // 6
```

对可空值做运算，只要其中有一个是 `null`，结果也是 `null`。

```csharp
int? nothing = null;
Console.WriteLine(nothing + 1);                // 输出空行，结果是 null
Console.WriteLine($"[{nothing}]");             // []

nothing = nothing ?? 10;                       // null 时取 10，否则保持原值
Console.WriteLine(nothing);                    // 10
```

`nothing = nothing ?? 10` 的意思是“如果 nothing 是 null，就取右边的 10，再把结果放回 nothing”。`x = x ?? 值` 的效果是，只有 `x` 为 null 时才换成右边的值。

## 2.10 转换，字符串与数字之间

`Console.ReadLine()` 永远返回 `string`。想把输入当成数字用，必须先转换。

```csharp
var text = Console.ReadLine();         // 假设用户输入了 1520
```

### Parse，转换失败就抛异常

```csharp
int ms = int.Parse("1520");            // 1520
int bad = int.Parse("abc");            // 运行时抛出 FormatException
```

`int.Parse` 遇到不能转换的文字会抛出异常。异常信息如下，同样是英文原文。

```text
FormatException: The input string 'abc' was not in a correct format.
```

程序里用户输入的内容随时可能不合法，用异常来处理“用户随便输了点东西”，代码会变得很难读。

### TryParse，不抛异常，用返回值判断

`TryParse` 是更好的选择。它返回 `true` 或 `false`，成功时把结果放进 `out` 后面的变量里。

```csharp
if (int.TryParse(text, out var ms))
{
    Console.WriteLine($"解析成功：{ms}");
}
else
{
    Console.WriteLine("这不是一个数字");
}
```

`out var ms` 的意思是，如果转换成功，就把结果放进一个新变量 `ms`。`out` 的完整用法在[第 5 章](/chapter/05)讲方法时细讲，现在照着写就行。

```csharp
Console.WriteLine(int.TryParse("12a", out var tp) + " " + tp);     // False 0
Console.WriteLine(double.TryParse("3.14", out var dp) + " " + dp); // True 3.14
```

这两行的输出前一项是 `True` 或 `False`，后一项是转换出来的数字。转换失败时，输出的数字是默认值 0。

LogLens 解析时间戳时用的也是 `TryParse` 系列方法，2.16 节有具体的位置。

### Convert，宽松的转换

`Convert` 也能转换，但对 `null` 和空白的处理比较宽松。

```csharp
Console.WriteLine(Convert.ToInt32("  42 "));   // 42，前后空白会被忽略
Console.WriteLine(Convert.ToInt32(null));      // 0，null 会变成 0
```

`Convert.ToInt32(null)` 返回 0，这往往会把“没有数据”悄悄当成“数据是 0”。所以对用户输入，本书统一使用 `TryParse`。

### 反方向，数字变字符串

```csharp
int ms2 = 1520;
var text2 = ms2.ToString();            // "1520"
var text3 = $"{ms2}";                  // 同上，插值更常用
```

## 2.11 日期与时间

C# 有三个常用的时间类型，它们各有用途。

| 类型 | 表示什么 | 典型用途 |
| --- | --- | --- |
| `DateTime` | 一个日期和时间，不带时区信息 | 只关心本地日历时间的场景 |
| `DateTimeOffset` | 一个日期和时间，并带有相对于 UTC 的偏移 | 日志时间戳、跨时区的记录 |
| `TimeSpan` | 一段时长，不是某个时刻 | 耗时、超时时间、两个时刻之差 |

日志的时间戳最好用 `DateTimeOffset`，因为它把时区也记下来了。

### DateTime

```csharp
var dt = new DateTime(2026, 11, 1, 9, 30, 0);
Console.WriteLine(dt.ToString("yyyy-MM-dd HH:mm:ss"));       // 2026-11-01 09:30:00
Console.WriteLine(dt.AddHours(5).ToString("yyyy-MM-dd HH:mm:ss"));  // 2026-11-01 14:30:00
Console.WriteLine(dt.DayOfWeek);                             // Sunday
Console.WriteLine(dt.Kind);                                  // Unspecified
```

`AddHours` 不会修改 `dt`，它返回一个新的时间，和字符串方法的规则相同。`Kind` 为 `Unspecified`，表示没有标明它是哪个时区的时间。

### DateTimeOffset

```csharp
var start = new DateTimeOffset(2026, 11, 1, 9, 30, 0, TimeSpan.FromHours(8));
var end = start.AddMilliseconds(1520);

Console.WriteLine(start.ToString("yyyy-MM-dd HH:mm:ss zzz"));       // 2026-11-01 09:30:00 +08:00
Console.WriteLine(end.ToString("yyyy-MM-dd HH:mm:ss.fff zzz"));     // 2026-11-01 09:30:01.520 +08:00
```

`TimeSpan.FromHours(8)` 表示东八区，也就是北京时间。`zzz` 会把偏移量显示出来。

同一个时刻，换一个时区显示，时钟读数不同。

```csharp
var utc = new DateTimeOffset(2026, 11, 1, 9, 30, 0, TimeSpan.Zero);
Console.WriteLine(utc.ToOffset(TimeSpan.FromHours(8)).ToString("HH:mm zzz"));   // 17:30 +08:00
```

`DateTimeOffset.Now` 表示当前时间，每次运行的结果都不同，所以这里不写输出。

### TimeSpan

两个时刻相减，得到的是一个 `TimeSpan`。

```csharp
var span = end - start;
Console.WriteLine(span);                       // 00:00:01.5200000
Console.WriteLine(span.TotalMilliseconds);     // 1520
Console.WriteLine(span.TotalSeconds);          // 1.52
Console.WriteLine(span.ToString(@"ss\.fff"));  // 01.520
```

`TotalMilliseconds` 和 `TotalSeconds` 返回总时长，是一个小数。`Seconds` 这类属性返回的是时长中“秒”的那一部分，和 `TotalSeconds` 不一样，初学者容易搞混。

```csharp
Console.WriteLine(TimeSpan.FromMinutes(90));                  // 01:30:00
Console.WriteLine(TimeSpan.FromMinutes(90).ToString(@"hh\:mm"));  // 01:30
```

`@"ss\.fff"` 是一个逐字字符串，`\.` 是普通的反斜杠加点，不需要转义。格式串里的 `ss`、`fff` 等字母会被替换成对应的数字。

## 2.12 Math 与 Random

`Math` 类提供了常用的数学函数。它的成员都是静态的，直接用类名调用。

```csharp
Console.WriteLine(Math.Abs(-3));           // 3
Console.WriteLine(Math.Max(3, 7));         // 7
Console.WriteLine(Math.Min(3, 7));         // 3
Console.WriteLine(Math.Sqrt(16));          // 4
Console.WriteLine(Math.Pow(2, 10));        // 1024
Console.WriteLine(Math.PI);                // 3.141592653589793
Console.WriteLine(Math.Clamp(150, 0, 100));   // 100，限制在 0 到 100 之间
Console.WriteLine(Math.Round(Math.PI, 2));    // 3.14，保留两位小数
```

`Math.Clamp` 很适合用来把一个值限定在合理的范围内。LogLens 计算健康分数时，就是用它把结果压在 0 到 100 之间，2.16 节有位置。

`Random` 生成随机数。它有两种常用写法。

```csharp
var rng = new Random();                // 每次运行的种子不同，结果不同
Console.WriteLine(rng.Next(1, 7));     // 1 到 6 之间的整数，不包括 7
```

`Next(1, 7)` 的上界 7 是开区间，所以模拟掷骰子用 `1, 7`。

如果给 `Random` 一个固定的种子，每次得到的序列都一样。这在测试和复现问题时很有用。

```csharp
var seeded = new Random(42);
for (var k = 0; k < 5; k++)
{
    Console.Write(seeded.Next(1, 7) + " ");
}
Console.WriteLine();
// 5 1 1 4 2
```

同一个种子在同一版本的运行时里，得到的序列是相同的。不要把具体的数字当成一个稳定的约定，换一个 .NET 版本，序列可能就不同了。

## 2.13 动手，完整程序

回到本章开头的程序。它把前面学到的类型、运算、字符串插值和转换放在一起。

进入配套项目 `code/ch02-types` 所在的文件夹，然后运行它。

<!--tab cd Linux,macOS-->

```bash
cd tutorial/code/ch02-types
dotnet run
```

<!--tab cd Windows-->

Windows 的 cmd 中，路径改用反斜杠，例如 `cd tutorial\code\ch02-types`，后面的 `dotnet run` 相同。

<!--tab-end cd-->

程序会先要求输入一个耗时，你可以输入 `1520`。完整代码如下，它和配套项目里的 `Program.cs` 完全一样。

```csharp
// ============================================
// 第 2 章 · 变量、类型与运算
// 运行方式：dotnet run
// ============================================

Console.Write("请输入一条日志的耗时（毫秒）： ");
var input = Console.ReadLine();

// 1) 转换：解析失败就提示并结束
if (!int.TryParse(input, out var milliseconds))
{
    Console.WriteLine($"「{input}」不是一个整数，没法换算。");
    return;
}

// 2) 类型与运算
var seconds = milliseconds / 1000.0;      // 除以 1000.0 才会保留小数
var isSlow = milliseconds > 1000;         // bool
var rounded = Math.Round(seconds);        // double

// 3) 输出对齐的"表格"：先把标题放到变量里，插值里就不用嵌套引号了
const string LabelRaw = "原始值";
const string LabelSeconds = "换算成秒";
const string LabelSlow = "是否慢请求";
const string LabelRounded = "四舍五入";
const string LabelFormatted = "格式化显示";

Console.WriteLine();
Console.WriteLine($"{LabelRaw,-12}{milliseconds}");
Console.WriteLine($"{LabelSeconds,-12}{seconds:F2} s");
Console.WriteLine($"{LabelSlow,-12}{(isSlow ? "是" : "否")}");
Console.WriteLine($"{LabelRounded,-12}{rounded} s");
Console.WriteLine($"{LabelFormatted,-12}{milliseconds:N0} ms");

// 4) 顺便演示字符串方法：注意 Trim() 返回新字符串，不会改原值
var messy = "  ERROR  ";
var trimmed = messy.Trim();
var containsError = trimmed.Contains("error", StringComparison.OrdinalIgnoreCase);

Console.WriteLine();
Console.WriteLine($"字符串演示：「{trimmed}」长度 {trimmed.Length}，包含 error？{containsError}");
```

输入 1520 之后，输出如下。

```text
请输入一条日志的耗时（毫秒）： 1520

原始值         1520
换算成秒        1.52 s
是否慢请求       是
四舍五入        2 s
格式化显示       1,520 ms

字符串演示：「ERROR」长度 5，包含 error？True
```

如果输入的不是整数，程序会打印一句提示后结束。

### 逐段解释

| 代码 | 说明 |
| --- | --- |
| `int.TryParse(input, out var milliseconds)` | 尝试把文本转成整数，成功返回 `true`，结果放进 `milliseconds` |
| `return;` | 在顶层语句里提前结束程序 |
| `milliseconds / 1000.0` | 除以 `1000.0`，结果是小数；写成 `/ 1000` 会得到整数 1 |
| `milliseconds > 1000` | 比较运算，结果是 `bool` |
| `isSlow ? "是" : "否"` | 三元表达式，条件成立取前一个，否则取后一个，2.6 节讲过 |
| `{LabelRaw,-12}` | 左对齐，至少占 12 个字符宽，中文也按一个字符计算 |
| `{seconds:F2}` | 保留两位小数 |

### 为什么标题要先放进常量

```csharp
const string LabelRaw = "原始值";
```

直接在插值里写 `$"{"原始值",-12}"` 也能编译，但外层和内层的引号混在一起，读起来很费劲。把标题抽成常量，读的时候一眼就能看清，改文案时也只需要改一处。

### 为什么这几行还是没对齐

`{LabelRaw,-12}` 按字符个数补空格。“原始值”有 3 个字符，后面补 9 个空格，总共 12 个字符。“是否慢请求”有 5 个字符，后面补 7 个空格，总共也是 12 个字符。

但终端显示时，中文字符占的宽度是英文字符的两倍。所以两行的显示宽度分别是这样。

```text
原始值␣␣␣␣␣␣␣␣␣   显示宽度 3 × 2 + 9 = 15
是否慢请求␣␣␣␣␣␣␣   显示宽度 5 × 2 + 7 = 17
```

两行差了 2 列，看起来就歪了。要真正对齐，必须按显示宽度计算，中文算 2 列，英文算 1 列。

LogLens 的表格就是这样做的。`src/LogLens.Core/Infrastructure/Ansi.cs` 里有一个 `DisplayWidth` 方法，它逐个字符判断是不是宽字符，然后累加宽度。`ConsoleTable.cs` 计算列宽时调用的就是它。[第 5 章](/chapter/05)学了方法、第 21 章讲命令行界面之后，就能读懂这段代码。

## 2.14 常见错误

下面的报错原文来自编译器的中文输出。错误信息里的引号和路径，在你的机器上可能略有不同。

| 报错（节选） | 原因 | 怎么改 |
| --- | --- | --- |
| `CS0029 无法将类型“string”隐式转换为“int”` | 把字符串直接赋给 `int` 类型的变量 | 用 `int.TryParse` 转换 |
| `CS0266 无法将类型“double”隐式转换为“int”。存在一个显式转换` | 把小数直接赋给整数 | 需要时用 `(int)` 显式转换，并想清楚小数部分怎么处理 |
| `CS0266 无法将类型“long”隐式转换为“int”` | 大类型直接赋给小类型 | 确认数值范围后再写 `(int)` |
| `CS0029` 出现在 `var x = 1; x = "a";` 中 | `var` 推断出 `int` 之后又放入字符串 | 保持类型一致，或换成需要的类型 |
| `CS0165 使用了未赋值的局部变量“x”` | 声明了变量，但没有给它初值就使用 | 声明时给初值，如 `int x = 0;` |
| `CS0136 无法在此范围中声明名为“count”的局部变量或参数` | 嵌套的代码块里又声明了同名变量 | 换一个名字 |
| `CS8602 解引用可能出现空引用。` | 对可能为 `null` 的变量直接取成员 | 先用 `!= null` 判断，或改用 `?.` |
| `CS8600 将 null 文本或可能的 null 值转换为不可为 null 类型。` | 把 `null` 赋给非可空的变量 | 声明成 `string?`，或确保不会是 `null` |
| `CS0031 常量值“300”无法转换为“byte”` | 字面量超出了目标类型的范围 | 换更大的类型，或检查这个数值是否写错 |
| `CS0220 在 checked 模式下，运算在编译时溢出` | 常量表达式的结果超出范围 | 检查常量运算，必要时换类型 |
| `CS1503 参数 1: 无法从“double”转换为“int”` | 给方法传入的参数类型不匹配 | 传入 `int`，或把参数类型改成 `double` |
| `CS0019 运算符“==”无法应用于“int”和“string”类型的操作数` | 把数字和字符串直接比较 | 先转换成同一类型，再比较 |
| `CS0133 指派给“Y”的表达式必须是常量` | `const` 的值在编译时无法确定 | 去掉 `const`，改用普通变量或 `static readonly` |

另外还有几个不报错、但结果不对的情况，初学者经常遇到。

| 现象 | 原因 | 怎么改 |
| --- | --- | --- |
| 百分比永远是 0 | 整数相除，`errors / total` 的小数被截掉 | 先转成 `double`，如 `errors / (double)total` |
| 千分位没有出现 | 用了 `F2`，`F` 不加千分位 | 千分位用 `N2`，`N` 表示 Number |
| 字符串调用之后没有变化 | 方法返回新字符串，没有赋值回去 | 写成 `s = s.Trim();` |

Console.Write("请输入文件大小（字节）： ");
if (!long.TryParse(Console.ReadLine(), out var bytes))

用 `long`，因为文件可能超过 21 亿字节。

**练习 2**

```csharp
Console.Write("请输入一条日志： ");
var line = Console.ReadLine() ?? string.Empty;

// 最多切成 3 段：第 3 段保留消息里原有的空格
var parts = line.Split(' ', 3);
if (parts.Length < 3)
{
    Console.WriteLine("格式不对，至少要三段：时间 级别 消息");

Console.WriteLine($"级别：{parts[1]}");
Console.WriteLine($"消息：{parts[2]}");
```

`Split(' ', 3)` 的第二个参数是“最多切成几段”。不加这个限制，消息里的空格也会被切开，`连接 超时 重试` 就会被拆成多段。`?? string.Empty` 用来处理 `ReadLine` 返回 `null` 的情况，让后面的 `Split` 不会出错。

## 2.16 这一章的知识，在 LogLens 里出现在哪

LogLens 的代码在 `src/` 文件夹里。下面几个位置和本章的知识直接相关。

| 你学的 | 位置 | 它在那儿做什么 |
| --- | --- | --- |
| `DateTimeOffset?` | `src/LogLens.Core/Query/QueryNode.cs` 第 62 行 | 时间锚点可以没有，`?` 表示可能为 `null`，和 2.9 节的 `int?` 是同一种写法 |
| `Math.Round` 与 `Math.Clamp` | `src/LogLens.Core/Models/HealthScore.cs` 第 92 行 | 先把分数限制在 0 到 100，再四舍五入成 `int` |
| `Ansi.DisplayWidth` | `src/LogLens.Core/Infrastructure/Ansi.cs` 第 103 行 | 按显示宽度（中文占 2 列）计算表格列宽 |
| `StringComparison.OrdinalIgnoreCase` | `src/LogLens.Core/Models/LogLevel.cs` 第 26 行 | 让 `WARN`、`warn`、`Warn` 都能匹配同一个级别 |
| `TryParse` 系列 | `src/LogLens.Core/Parsing/PlainTextLogParser.cs` 第 113 与 133 行 | 解析时间戳时，格式不对就返回 `false`，而不是抛异常 |
| `string?`、`??` | `src/LogLens.Core/Query/QueryEngine.cs` 第 31 行 | 日志记录器参数可以为 `null`，缺省时用 `??` 换成默认实现 |

查询语法里的 `within 5m` 表示一个时间窗口。它对应的节点里有一个时间参数，表示窗口以哪个时间点为中心。

```csharp
DateTimeOffset? Anchor
```

这个参数的类型是 `DateTimeOffset?`。用户可以不指定时间，所以它是可空的。`TimeSpan`、`DateTimeOffset` 这些日期类型在 2.11 节讲过，`?` 的用法在 2.9 节讲过，两者放在一起就是这里的写法。
