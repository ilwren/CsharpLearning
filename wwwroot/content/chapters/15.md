## 15.1 为什么会有新语法

C# 每个大版本都会加入一些新写法，目的大多是减少样板代码，也就是那些每次都要重复写、却不表达任何业务意思的代码。举个最常见的例子。

```csharp
// 旧写法：先判断，再赋值
if (nickname == null)
{
    nickname = "未设置";
}

// 新写法：空值合并赋值
nickname ??= "未设置";
```

两段代码的意思完全一样。这种"把一种写法换成另一种更短的写法，但意思不变"的东西，通常叫**语法糖**（syntactic sugar）。编译器看到新写法，会把它翻译成等价的旧代码。所以语法糖不会改变程序的行为，也不会让程序变快，它改变的是写代码和读代码的效率。

本章每个语法都会标注**最低需要的 C# 版本**。这些版本号不是凭印象写的。我们用同一套方法逐个验证，把语法放进一个小程序，用 `LangVersion` 指定不同的语言版本去编译，看它在哪个版本开始能通过。

下面是验证结果。`LangVersion` 是编译器的语言版本设置，它和 .NET 的版本是两回事，15.13 节会讲这个区别。

| 语法 | 最低 C# 版本 | 本章位置 |
| --- | --- | --- |
| `??=` 空值合并赋值 | C# 8.0 | 15.2 |
| `is not null` | C# 9.0 | 15.2 |
| `^` 与 `..`（索引与范围） | C# 8.0 | 15.3 |
| `switch` 表达式、属性模式 | C# 8.0 | 15.4 |
| 关系模式 `>= 90` | C# 9.0 | 15.4 |
| 扩展属性模式 `Text.Length: > 3` | C# 10.0 | 15.4 |
| 列表模式 `[1, .., var last]` | C# 11.0 | 15.4 |
| `record`、`init` | C# 9.0 | 15.5 |
| `record struct` | C# 10.0 | 15.5 |
| `required` 成员 | C# 11.0 | 15.5 |
| 原始字符串 `"""` | C# 11.0 | 15.6 |
| 集合表达式 `[...]` | C# 12.0 | 15.7 |
| 类的主构造函数 | C# 12.0 | 15.8 |
| `field` 关键字 | C# 14.0 | 15.9 |
| 空条件赋值 `a?.b = c` | C# 14.0 | 15.9 |
| 顶层语句 | C# 9.0 | 15.11 |
| 文件范围命名空间 `namespace X;` | C# 10.0 | 15.11 |
| `global using` | C# 10.0 | 15.10 |

这张表有一个规律，**新语法必须在它的版本号或更高版本下才能用**。如果你的项目把 `LangVersion` 设成 7.3，写 `??=` 就会直接编译失败。我们的项目在 `Directory.Build.props` 里统一设置了 `<LangVersion>14.0</LangVersion>`，所以本项目里这些语法都可以放心用。

## 15.2 空值相关，`??=` 与 `is not null`

### 空值合并赋值 `??=`（C# 8.0）

[第 2 章](/chapter/02) 2.9 节讲过 `??`，它会给你一个"要么是左边的值，要么是右边的默认值"的结果。`??=` 则是把结果写回左边的变量。

```csharp
string? nickname = null;
nickname ??= "未设置";      // 只有 nickname 为 null 时才赋值
Console.WriteLine(nickname); // 未设置
```

它等价于。

```csharp
if (nickname is null)
{
    nickname = "未设置";
}
```

有一个细节要记住，只有左边是 `null` 时，右边才会被计算。如果右边是一个开销很大的方法调用，`??=` 能帮你避免在不需要时白算一次。

项目里的真实用法在 `QueryEngine.cs`，那里的 `options` 参数为空时才换成默认配置。

```csharp
options ??= QueryRunOptions.Default;
```

### `is not null`（C# 9.0）

判断一个值是不是 `null`，以前大家常写 `x != null`。C# 9 之后，推荐写成 `x is not null`。

```csharp
if (nickname is not null)
{
    Console.WriteLine($"昵称长度：{nickname.Length}");
}
```

两者在大多数情况下效果一样，但 `is not null` 有一个好处，它是"模式匹配"的一种，判断的是引用本身是不是空，**不会调用类型自己重载的 `==` 运算符**。对于重载了 `==` 的类型，`x != null` 有时会得到你没想到的结果，`is not null` 则始终只做空值判断。

项目里这样的写法随处可见，比如 `LogEntry.cs` 里的。

```csharp
public bool HasProblem => Level.IsProblem() || ExceptionType is not null;
```

## 15.3 范围与索引，`^` 与 `..`（C# 8.0）

以前取数组的最后一个元素，要写 `arr[arr.Length - 1]`。取一段子数组，要用 `Skip`、`Take` 或者 `Array.Copy` 之类的方法。C# 8 引入了两个符号，让这些操作变得直观。

```csharp
string[] levels = ["debug", "info", "warn", "error"];

Console.WriteLine(levels[^1]);                    // error：^1 表示"从末尾数第 1 个"
Console.WriteLine(string.Join(",", levels[..2])); // debug,info：从开头到索引 2 之前
Console.WriteLine(string.Join(",", levels[1..3])); // info,warn：索引 1 到 3 之前
```

几点要注意。

- `^1` 是倒数第一个，`^2` 是倒数第二个。它对应的是 `Length - 1`、`Length - 2`。
- `a..b` 包含左边、不包含右边，和[第 3 章](/chapter/03)循环里的 `for (int i = 0; i < b; i++)` 习惯一致。
- `..2` 省略了左边，表示从头开始；`2..` 省略右边，表示到末尾。
- 对数组使用范围，得到的是一个**新数组**，会复制元素。对字符串使用范围，得到的是**新字符串**。两者都不会修改原来的变量。

项目里可以看到大量这样的用法。`TimeSpanParser.cs` 用 `candidates[^1]` 取最后一个候选项，`StringExtensions.cs` 用 `value[..width]` 截取前面一段文字。

## 15.4 模式匹配增强

[第 3 章](/chapter/03)讲过 `switch` 语句，它根据一个值执行不同的分支。C# 8 之后，模式匹配的能力越来越强，`switch` 还能当作表达式使用，直接算出一个值。

### `switch` 表达式（C# 8.0）

```csharp
int score = 95;
string grade = score switch
{
    >= 90 => "优秀",     // 关系模式（C# 9），下面会讲
    >= 60 => "及格",
    _ => "不及格",       // _ 是弃元，表示"其它所有情况"
};
```

和 `switch` 语句相比，`switch` 表达式有三点不同。

1. 它**有返回值**，可以直接赋值给变量；
2. 每个分支用 `=>` 连接，不需要 `break`；
3. 每个分支只能是一个表达式，不是一段语句。

如果你没有写 `_`，而且输入的值没有被任何分支覆盖，编译器会给出警告。运行时如果真的遇到没有覆盖的值，会抛出 `SwitchExpressionException`。所以养成习惯，**最后总是写一个 `_`，或者确认分支已经覆盖所有情况**。

项目里 `QueryParser.cs` 用它把运算符文字映射成内部符号。

```csharp
op = _tokens.Advance().Text.ToLowerInvariant() switch
{
    "matches" => "~",
    // ...
};
```

### 属性模式（C# 8.0）

属性模式允许你直接在 `switch` 里检查对象的属性，不需要先把属性取出来。

```csharp
var tag = line switch
{
    { Level: "error" } => "需要处理",
    _ => "其它",
};
```

`{ Level: "error" }` 的意思是"`Level` 属性等于 `"error"`"。如果分支需要的条件更多，可以写成 `{ Level: "info", Text.Length: > 3 }`。

### 关系模式（C# 9.0）

上面的 `>= 90` 就是关系模式。它支持 `<`、`<=`、`>`、`>=`，让你不用再写 `score >= 90 ? ... : ...` 这种嵌套三元表达式。

### 扩展属性模式（C# 10.0）

在属性模式里，C# 10 之后可以直接写 `Text.Length` 这样的嵌套属性路径。

```csharp
{ Level: "info", Text.Length: > 3 } => "正常",
```

在 C# 8 和 9 里，你只能写 `{ Text: { Length: > 3 } }`，多套了一层花括号。

### 列表模式（C# 11.0）

列表模式可以按**元素个数和内容**匹配数组或列表。

```csharp
int[] sample = [1, 2, 3];

string shape = sample switch
{
    []                      => "空",
    [var only]              => $"只有一个：{only}",
    [1, .., var last]       => $"以 1 开头，最后是 {last}",
    _                       => "其它形状",
};
```

`..` 在列表模式里表示"中间任意多个元素"。`[1, .., var last]` 的意思是，第一个元素是 1，最后一个元素绑定到变量 `last`，中间的随便。

## 15.5 `record`、`record struct`、`init` 与 `required`

[第 6 章](/chapter/06)已经用过 `record`。这里做一个回顾，再补上它的几个兄弟。

### `record` 与 `with`（C# 9.0）

`record` 是一种"主要用来存数据"的类型，它自动生成相等比较、`ToString` 和 `with` 复制语法。

```csharp
var original = new LogLine("warn", "磁盘快满了");
var upgraded = original with { Level = "error" };   // 复制一份，只改 Level

Console.WriteLine(original);   // warn: 磁盘快满了
Console.WriteLine(upgraded);   // error: 磁盘快满了
```

`with` 不会修改原对象，它返回一个新对象。这和[第 6 章](/chapter/06)讲的"数据不要随便改"是同一个思路。项目里 `WorkspaceService.cs` 就用它复制快照。

```csharp
var snapshot = current with { Report = report };
```

### `record struct`（C# 10.0）

`record` 默认是类（引用类型）。如果你希望它是值类型，放进数组和字典时不产生额外的堆分配，可以写 `record struct`。

```csharp
public readonly record struct LogLine(string Level, string Text);
```

`readonly` 表示创建后不能修改，它和 `record struct` 经常一起用。我们用 LangVersion 9.0 去编译 `record struct`，会得到 CS8773 错误，而 10.0 可以通过。

### `init` 访问器（C# 9.0）

`init` 比 `set` 更严格，属性只能在对象初始化器（`new X { ... }`）里设置，之后就不能再改。

```csharp
public sealed class Server
{
    public int Port { get; init; } = 8080;
}

var server = new Server { Port = 9000 };   // 可以
// server.Port = 9001;                     // 编译错误：init 之后不能再改
```

### `required` 成员（C# 11.0）

`required` 更进一步，这个属性**必须**在创建对象时设置，漏写会直接编译失败。

```csharp
public sealed class Server
{
    public required string Host { get; init; }   // 必须设置
    public int Port { get; init; } = 8080;       // 有默认值，可以不写
}

var ok = new Server { Host = "localhost" };
// var bad = new Server();   // 编译错误 CS9035：Host 必须在对象初始化器里设置
```

我们把 `new Server()` 放进编译器里，错误码确实是 CS9035，提示 "Required member 'Server.Host' must be set in the object initializer or attribute constructor."。这是一个很好的"让编译器替你检查"的例子，不用等到运行时才发现漏了配置。

项目里 `AnalysisReport.cs` 用的也是这种写法。

```csharp
public required LogSourceInfo Source { get; init; }
public required IReadOnlyList<LevelCount> Levels { get; init; }
```

## 15.6 原始字符串 `"""`（C# 11.0）

写 JSON、SQL、正则或者多行文字时，最麻烦的是引号和换行。以前要写成这样。

```csharp
string json = "{\n  \"level\": \"error\",\n  \"message\": \"数据库超时\"\n}";
```

满屏的 `\"` 和 `\n`，很难看出原来的样子。C# 11 的原始字符串字面量用三个双引号包住内容，里面的引号和换行都可以原样写。

```csharp
string json = """
    {
      "level": "error",
      "message": "数据库超时"
    }
    """;
```

使用时要记住三条规则。

1. 开头的 `"""` 后面必须直接换行，内容从下一行开始；
2. 结尾的 `"""` 必须独占一行；
3. 结尾 `"""` 前面的空白会被当成"缩进基准"，所有内容行都要以同样的空白开头，多出来的部分会保留，少了就编译失败。

所以上面的 `"""` 结尾和内容对齐在同一列，输出的 JSON 没有多余的缩进。

如果内容里本身要出现三个连续的双引号，可以用四个双引号包住，比如 `""""`。这种情况很少见，知道有这个规则就够了。

项目里 `QueryHelp.cs` 的帮助文字就是这样写的，这样改文档时不用担心转义。

## 15.7 集合表达式 `[...]`（C# 12.0）

创建数组和列表，以前要写 `new int[] { 1, 2 }` 或 `new List<int> { 1, 2 }`。C# 12 统一成了方括号。

```csharp
int[] first = [1, 2];
int[] merged = [..first, 3, 4];    // .. 展开另一个集合
List<int> numbers = [..merged];    // 同一种写法，也可以创建列表

Console.WriteLine($"合并：{string.Join(",", merged)}，列表数量：{numbers.Count}");
// 合并：1,2,3,4，列表数量：4
```

`[..first, 3, 4]` 里的 `..` 要和前面 15.3 节的范围符号区分开来。在集合表达式里，它的意思是"把这个集合的所有元素依次放进来"，和范围没有关系。

项目里 `QueryEngine.cs` 这样用。

```csharp
? [.. ordered.Take(options.Limit)]
: [.. ordered];
```

这一行的意思是，有上限就只取前面几个，否则全部保留，两个分支的结果类型一致。

## 15.8 主构造函数（C# 12.0）

[第 6 章](/chapter/06)讲过 `record` 可以把参数直接写在类型名后面。C# 12 开始，普通的 `class` 也能这么做。

```csharp
public sealed class Printer(string prefix)
{
    public void Print(string message) => Console.WriteLine($"[{prefix}] {message}");
}

var printer = new Printer("后台");
printer.Print("启动完成");   // [后台] 启动完成
```

`prefix` 是构造函数的参数，但只要在类的成员里用到它，编译器就会把它保存成一个私有字段。所以你不需要写 `private readonly string _prefix;` 和一个赋值的构造函数。

主构造函数的参数只在类的内部（成员和字段初始化器）里可见，类外面访问不到。它和普通构造函数的参数不同，普通参数只在构造函数体里有效，主构造函数的参数可以一直被类的成员使用。

项目里 `ListBoxBehaviors.cs` 有一个私有内部类就是这样写的。

```csharp
private sealed class NotifyingCollectionWatcher(ListBox owner)
{
    // ...
}
```

## 15.9 C# 14 的两个新东西，`field` 与空条件赋值

### `field` 关键字（C# 14.0）

属性的 `get` 和 `set` 里，经常要保存一个值。以前你得自己写一个私有字段。

```csharp
private string _name = "";
public string Name
{
    get => _name;
    set => _name = value.Trim();
}
```

C# 14 允许你直接用 `field` 指代编译器为属性生成的那个幕后字段，不用再取名字。

```csharp
public sealed class Tag
{
    public string Name
    {
        get => field;
        set => field = value.Trim();     // 写入时自动去掉前后空格
    } = "";
}
```

这里的 `} = "";` 是属性的初始值。如果去掉它，编译器会给出 CS9264 警告，提示非空属性没有被赋值。

项目里 `StudioSettings.cs` 就有一个真实的例子，它用 `field` 把 `MaxRows` 限制在 100 到一百万之间。

```csharp
public int MaxRows
{
    get => field;
    set => field = Math.Clamp(value, 100, 1_000_000);
} = 20000;
```

这样不管值是从界面输入、从 JSON 读入，还是被别的代码改掉的，非法值都进不来。把校验放在属性里，是一个很值得养成的习惯。

用 LangVersion 13.0 去编译 `field`，会得到 CS0103（名字不存在）的错误，说明这个关键字要到 C# 14 才能用。

### 空条件赋值 `a?.b = c`（C# 14.0）

[第 2 章](/chapter/02) 2.9 节讲过 `?.`，它在左边为 `null` 时直接返回 `null`，不会抛异常。C# 14 之前，`?.` 只能用来读取，不能放在赋值语句的左边。C# 14 允许了。

```csharp
Config? maybe = config;
maybe?.Level = "debug";     // maybe 不为 null 时才赋值
```

如果 `maybe` 是 `null`，这一行什么也不做，也不会抛出 `NullReferenceException`。

这个写法很方便，但要注意它的含义，它的前提是"如果对象不存在，那就算了"。如果你的程序在这里必须确保赋值成功，就应该显式判断 `null`，把"对象不存在"当成一个错误处理，而不是悄悄跳过。

## 15.10 `global using` 与隐式 using

### `global using`（C# 10.0）

每个 `.cs` 文件顶部都要写 `using System;`、`using System.Linq;`，很繁琐。C# 10 允许用 `global using`，让整个项目共用一份。

```csharp
global using System;
global using System.Linq;
```

写在任何一个文件里，所有文件都能用。

### 隐式 using（ImplicitUsings）

更省事的做法是打开项目的 `ImplicitUsings`。SDK 会自动生成一个文件，把 `System`、`System.Linq`、`System.Collections.Generic` 等常用命名空间设为全局可见。这正是本章的检查点能省掉大部分 `using` 的原因。

本项目在根目录的 `Directory.Build.props` 里统一打开了 `ImplicitUsings`，所以各个 `.cs` 文件都不必再逐一写这些 `using`。

```xml
<Nullable>enable</Nullable>
<ImplicitUsings>enable</ImplicitUsings>
<LangVersion>14.0</LangVersion>
```

所以项目里的文件可以省掉 `System`、`System.Linq` 这些常用命名空间的 `using`（仍然需要的命名空间还是要写）。项目里**没有任何手写的 `global using` 文件**，全部由 SDK 自动生成。

这里有一个陷阱。我们做语法版本探针时，如果把 `LangVersion` 降到 9.0 同时保持 `ImplicitUsings` 打开，编译器会先报 "Feature 'global using directive' is not available in C# 9.0" 的错误，把真正想测的语法错误挡在后面。原因是自动生成的隐式 using 文件本身就用到了 `global using`（C# 10 的语法）。所以探针里要先关掉隐式 using，再做版本测试。你在实际项目里把 `LangVersion` 调低时，也要记住这一点。

## 15.11 顶层语句与文件范围命名空间

### 顶层语句（C# 9.0）

[第 1 章](/chapter/01)的 `Program.cs` 就是一个顶层语句的例子，文件里没有 `class Program` 和 `static void Main`，直接写代码就行。它只能出现在一个文件里，而且必须放在文件的最前面，类型声明要放在它后面。

这是为了让初学者的第一个程序更短。等项目变大，你仍然会想要一个明确的 `Main` 方法，这时只需要把顶层语句换回普通的 `static void Main`。

### 文件范围命名空间（C# 10.0）

以前一个文件里的类型要包在 `namespace X { ... }` 里面，整体多缩进一层。C# 10 允许写成一行。

```csharp
namespace LogLens.Core.Models;

public sealed record AnalysisReport
{
    // 注意：这里不需要再多缩进一层
}
```

整个文件的类型都属于这个命名空间，直到文件结束。

本项目 `src/` 下 144 个 `.cs` 文件中，有 143 个采用这种写法，旧的 `namespace X { }` 块式写法一处都没有。唯一的例外是 `LogLens.Cli/Program.cs`，它是顶层语句，本身没有命名空间。

## 15.12 特性，贴在代码上的标签

前面几节的写法，大多是把旧写法变短。特性（Attribute）不太一样。它是 C# 1.0 就有的东西，放在这里讲，是因为新语法的代码里经常会遇到它，很多人第一次见到时不知道它是干什么的。

特性写在方括号里，贴在类型、方法、属性、参数或枚举值的前面。它不改变这段代码的执行过程，只是留下一条附加的说明，供编译器或某个库读取。格式是 `[Name]` 或 `[Name(参数)]`。名字后面的 `Attribute` 可以省略，所以 `ObsoleteAttribute` 通常写成 `[Obsolete]`。

### `[Flags]`，让枚举的值可以组合

```csharp
[Flags]
public enum LogFields
{
    None = 0,
    Time = 1,
    Level = 2,
    Message = 4,
}
```

`[Flags]` 告诉 `ToString` 方法，这个枚举的值可以用 `|` 组合起来。每个值最好是 2 的幂（1、2、4、8……），这样各个值占用的二进制位互不重叠。

```csharp
var fields = LogFields.Time | LogFields.Level;
Console.WriteLine($"组合：{fields}，是否包含 Level：{fields.HasFlag(LogFields.Level)}");
```

运行结果是 `组合：Time, Level，是否包含 Level：True`。`ToString` 会把组合值打印成各个名字，用逗号隔开。

### `[Obsolete]`，标记一个将被淘汰的成员

```csharp
[Obsolete("请改用 New()")]
public static string Old() => "old";
```

别人调用 `Old()` 时，编译器会给出警告。我们做过一个探针，实际的输出（已去掉文件路径）如下。

```text
warning CS0618: 'Api.Old()' is obsolete: '请改用 New()'
```

如果第二个参数写成 `true`，警告就变成错误，代码无法通过编译。

```csharp
[Obsolete("已删除", true)]
public static string Dead() => "dead";
```

```text
error CS0619: 'Api.Dead()' is obsolete: '已删除'
```

这个特性适合用在库或公共接口上。先给旧接口加上警告，留出一段时间让调用方迁移，再把它删掉。

### `[CallerMemberName]`，让编译器替你填参数

```csharp
public static class Service
{
    public static void Start() => Log("服务启动");

    private static void Log(string message, [CallerMemberName] string caller = "")
        => Console.WriteLine($"[{caller}] {message}");
}
```

调用 `Log` 时，`caller` 没有传参，编译器会自动填入调用者的方法名。`Start` 调用了它，所以输出是 `[Start] 服务启动`。写日志时经常用到这个特性，省得每个调用处都手写方法名。

### `[JsonPropertyName]`，指定 JSON 里的字段名

```csharp
public sealed class LogRecord
{
    [JsonPropertyName("lvl")]
    public string Level { get; init; } = "";

    [JsonPropertyName("msg")]
    public string Message { get; init; } = "";
}
```

序列化时，JSON 里的字段名是 `lvl` 和 `msg`，C# 代码里仍然叫 `Level` 和 `Message`。使用它需要 `using System.Text.Json.Serialization;`。输出是 `{"lvl":"error","msg":"disk full"}`。

[第 14 章](/chapter/14)用到的 `[CsvRecord]` 也是同一类东西，它给 CsvHelper 留下一条说明，告诉它为这个类型生成读写 CSV 的代码。

### 怎么读懂一个特性

遇到陌生的特性，先看它的名字，名字通常已经说明了意思。再看括号里的参数，多数特性的参数就是它的具体配置。例如 `[Obsolete("请改用 New()")]` 里的字符串，就是给调用者看的提示。

15.5 节讲过的 `required`，背后也是一个特性（`RequiredMemberAttribute`）。编译器看到它，才会检查对象创建时有没有设置这个成员。

自己写特性，并用反射把它读出来，超出了本书的范围。本章只要求你能读懂项目里已经写好的特性。

## 15.13 常见误解

学新语法很容易走进几个误区，下面逐个说清楚。

**误解一，语法糖能让程序更快。** 多数语法糖只是编译器的改写，编译后的结果和旧写法等价。它让代码更短、更好读，但不保证更快。性能要靠测量，不要靠猜。

**误解二，新语法越多越好。** 团队里每个人对语法的熟悉程度不同。把一行能看懂的代码，改成三层嵌套的模式匹配，只会让下一个读代码的人更难受。判断标准很简单，**换过来之后，别人是不是更容易看懂？** 不是，就不要换。

**误解三，`LangVersion` 和 .NET 版本是一回事。** 它们不一样。`LangVersion` 决定编译器认识哪些语法；.NET 版本决定运行时和类库里有哪些类型。有些新语法要依赖库里的某个类型。例如 `required` 依赖 `RequiredMemberAttribute`，`init` 依赖 `IsExternalInit`。在较旧的目标框架上，这些类型可能不存在，需要你自己补充定义。本章没有在旧框架上做验证，所以只给出语言版本的结论。

**误解四，`switch` 表达式不写 `_` 也没事。** 没有覆盖的输入会在运行时抛出 `SwitchExpressionException`。编译器的警告不能省，它是在帮你发现漏掉的分支。

**误解五，`??=` 和 `??` 一样。** `??` 只是算出一个值，原来的变量不变。`??=` 会把结果写回左边的变量，它修改了变量本身。

**误解六，`is not null` 和 `!= null` 在所有情况下都一样。** 对多数类型，两者效果一样。但 `!=` 可能调用类型自定义的运算符，`is not null` 则只做空值判断。如果你的类型重载了 `==` 或 `!=`，要明白这两者的差别。
